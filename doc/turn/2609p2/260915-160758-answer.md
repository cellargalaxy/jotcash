### 资料冲突（列出并给出采用依据）

1. **CSV 列数：文档 8 列 vs 代码 11 列。** 需求文档 E-1 写「契约仅 8 个业务列」且不含记账币种；`base_csv.go:16-28` 实际是 11 列，多出 `记账币种`、`摊分月数`（`支出类型` 两边都有）。**采用代码**：`checkColumns` 用 `slices.Equal` 做全等比较，少一列连解析器都不认领（`Support` 返回 false），按文档写模板会直接「文件格式无法识别」。前端模板与单行新增均按 11 列生成。
2. **记账币种来源：文档「新增行取请求携带值」vs 代码「CSV 列优先」。** `expense.go:62-64` 是 `if object.AccountingCurrency == ""` 才取 jwt 里的值，即 CSV 列非空时以 CSV 为准。**采用代码**：模板保留该列，前端单行新增时留空，让 jwt 携带值生效，与文档语义一致。

## 二、目标与边界

- **交付物**：`static/` 下一套零构建、纯静态的前端，覆盖需求文档 8 域的全部页面，数据全走前端 mock，可直接 `go run .` 后在 `/static/` 打开验收。
- **不做**：与服务端联调（本轮明确不要求）、任何后端代码改动、月度统计（G-2 本轮无消费方）。
- **硬约束**：
  1. 一切资源走**相对路径**——页面在 `<前缀>/static/`，接口按 `../api/` 拼，反代加前缀后自动跟随，全仓无以 `/` 开头的 URL。
  2. 三方库**落本地**，不走 CDN；已下载 Bootstrap 5.3.3（CSS + bundle JS）、decimal.js 10.4.3，并剥掉 `sourceMappingURL` 注释避免 404 噪声。
  3. 标识符英文、注释与文案中文；同一概念全仓一个名字（`编码规范` §4.2/§4.3）。

## 三、方案

### 3.1 页面切分（4 页 + 1 道闸）

### 3.3 关键逻辑

- **疑似重复分组**：以 `支出日期|支出金额|支出币种` 为键分组（§8.3），组内行数 >1 即整组加框高亮，同组同色、相邻组换色；新增、编辑、删除后重新分组。
- **核实视图（E-3）**：`#/expense?operation_id=X&verify=1` → 先取该批次的三要素集合，再用集合反查全库未删除明细，合并展示。
- **内联编辑（E-4）**：行内切换为输入态，仅 10 个可手编字段可改；记账金额随支出金额/汇率实时重算（decimal.js，按 `AmountScale=2` 取整）；支出币种 = 记账币种时汇率锁死为 1（§8.1）；保存带 `version` 乐观锁，冲突文案「数据已落后，请刷新页面重新加载」。
- **新增一行（E-2①）**：草稿行 → 按 11 列拼一份仅 1 行的 CSV → 走入库接口，与上传真实 CSV 同一条链路。
- **批量删除（E-5）**：勾选当前页 / 全选当前筛选结果全集；删除前提示「本次将删除 N 笔」；已删除行不可勾选。
- **记账币种提示（F-5）**：表头旁列出全库记账币种集合，多于一种或与当前选择不一致时挂黄条并给出切换入口。

### 6.2 页面、功能块与布局

**页面数：4 个路由页 + 1 道解锁闸。** 选单页 hash 路由的理由见 §3.1。

| # | 页面 | 自上而下的功能块 | 覆盖的功能项 |

**明细页的表格内布局是全系统唯一需要特别设计的地方**，三条决定：

1. **编辑器是「行下展开的整行区域」，不是「单元格变输入框」。** 单元格内联编辑有个绕不过去的洞：可手编字段有 10 个，而默认表头只有 10 列且用户可以隐藏任意列——汇率列一旦被隐藏，这一行就永远改不了汇率。行下展开固定渲染全部 10 个可编辑字段，与列显隐彻底解耦。
2. **新增与编辑共用同一个编辑器**（`expenseEditor`）。两者的字段集、校验、派生预览完全一致，差别只有出口：新增拼一份 1 行 CSV 走入库接口，编辑走单行更新接口。这正是「一次新增 = 一份 CSV」这条规则在界面上的直接体现。
3. **派生字段实时预览而不可编辑**：编辑器底部一行常驻显示「记账币种 · 记账金额 · 摊分起止月」，随支出金额/汇率/日期/月数即时重算，让 §8.1 的联动看得见。

### 6.3 功能之间的交互（跨页面的四条主链路）

1. **入库 → 核实**：新增一行 / 上传 CSV 成功 → 拿到返回的审计ID → 自动跳 `#/expense?operation_id=X&verify=1` → 核实视图取本批次三要素反查全库 → 分组高亮 → 人工裁定 → 勾选批量软删除。这条链路把 E-2 → E-3 → E-6 → E-5 串成一次连续操作，中途不需要用户自己去填筛选条件。
2. **审计 ↔ 明细 ↔ 文件 三角互跳**：明细行的「来源」→ 审计页按审计ID 定位；审计行的「本批明细」「本批文件」→ 分别跳明细页与文件页；文件行的「来源审计」「本文件明细」→ 跳回去。三处跳转都只是带参数的查询，不构成任何回滚入口（C-2）。
3. **记账币种提示 → 切换**：表头在「记账币种」列名后挂出全库币种集合；一旦多于一种或与当前选择不一致，表格上方出现黄条并直接挂切换按钮；设置页也有同一个入口。切换完成后提示条自动消失——这是 F-5 与 F-4 的闭环。
4. **已删除 → 复制新增**：删除是终态没有恢复入口，所以「只看已删除」筛选出来的行，操作列不给「编辑」而给「复制新增」，点下去把字段灌进新增编辑器（清掉明细ID 与删除时间），走新增路径产生新的审计ID / 文件ID。

### 6.4 实施中发现并修掉的三个缺陷

| # | 缺陷 | 后果 | 处置 |
| - | ---- | ---- | ---- |
| 1 | 单行新增拼 CSV 时，支出币种 = 记账币种会让编辑器把汇率锁成 1，而记账币种列被固定留空 | 命中 `base_csv.parseExpense` 的「填了折算汇率就必须填记账币种」，**单行新增 100% 失败** | 汇率非空时一并写出记账币种，汇率留空时两列都留空以继承请求口径（`page_expense.js` `draftToCsv`） |
| 2 | 行勾选框的 `onchange` 直接重绘整张表 | 正在编辑的输入框被重建，焦点与填到一半的内容都会丢 | 拆出 `renderToolbar`，勾选只刷工具条与勾选框本身；编辑草稿提升到 `state.editDraft`，任何重绘都不再冲掉 |
| 3 | 页面在 `<前缀>/static/` 下，浏览器仍会去请求根路径的 `favicon.ico` | 反代前缀下必然 404，污染服务端访问日志 | `index.html` 加 `<link rel="icon" href="data:,">` |

缺陷 1、2 都是实跑才暴露的——前者靠「新增一行走通了吗」，后者靠「勾选之后编辑器还在不在」，都不是读代码能看出来的。

# 对话3 · 安全公告与三个缺陷

## 一、下载为什么还是不动 —— 上一轮我修错了地方

上一轮我判定根因是「blob 地址撤销得太早」，只延后了 `URL.revokeObjectURL`。你反馈**依然没反应**，说明诊断不完整。重看 `download` 的时序：

```js
link.click();
link.remove();                                   // ← 和 click 同一轮事件循环
setTimeout(() => URL.revokeObjectURL(url), 60000);  // 上一轮只改了这一行
```

`click()` 只是把下载**排进队列**，浏览器真正去读这个 blob 是异步的。**锚点在同一 tick 就被摘出 DOM，Chrome 会把这次下载取消掉**——这和撤销地址是两件独立的事，我上一轮只补了其中一件。

「导出查询结果」那条反馈是决定性的证据：**右下角有提示框，说明 `toastOk` 执行到了**，而 `toastOk` 在 `download()` 之后——所以代码全跑完了、没抛异常，问题一定在 `download()` 内部的时序，不在调用方。

### 处置：两条路，不再赌时序

1. **`download()` 的清理全部延后**（摘锚点 + 撤地址一起放到 120 秒后），并返回 blob 地址供调用方复用。
2. **「下载导入模板」直接做成真正的 `<a download href="blob:…">`**，长得还是按钮的样子。模板内容是固定的，blob 可以在渲染工具条时就建好。**用户点的是链接本身，整个链路里没有程序发起的 `click()`**，也就没有任何时序可赌——这是浏览器支持最好的形态。
3. **「导出查询结果」必须先异步拉数据，没法预先建 blob**，所以仍然发起一次自动下载，但**提示框里额外挂一条「点这里保存」的 `<a download>`**，保留 20 秒。自动下载被浏览器策略或拦截插件吃掉时，用户点一下就能拿到文件。

> 依据：`编码规范.md` §3.1「一旦一个函数在失败时会改变外部状态，调用方就永远无法安全地重试」。程序化下载失败是**静默**的，JS 拿不到任何回执，所以正确做法不是继续猜时序，而是留一条用户能亲手走的路。

## 二、下拉撑出滚动条导致页面跳动

根因是 CSS 规范里一条容易被忘掉的规则：**`overflow-x` 与 `overflow-y` 其中一个不是 `visible` 时，另一个的 `visible` 会被计算成 `auto`**。

编辑器嵌在 `.table-responsive` 里，那层是 `overflow-x: auto`（全字段平铺时要横向滚动，去不掉），于是纵向也变成 `auto`。下拉菜单一展开就超出容器高度 → 容器冒出纵向滚动条 → 可用宽度少了十几像素 → 表格缩一下，页面跳动。

**处置**：组合框的下拉菜单改用 `position: fixed`（Popper 的 `strategy: 'fixed'`）。fixed 定位的元素不参与祖先的滚动区计算，撑不出滚动条，Popper 还会在下方空间不够时自动向上翻。

```js
new bootstrap.Dropdown(toggle, {
  popperConfig: (config) => ({ ...config, strategy: 'fixed' }),
});
```

实测：展开前后 `.table-responsive` 的 `scrollHeight === clientHeight`（始终没有纵向滚动条），`clientWidth` 前后都是 1476，**宽度零跳动**。

## 三、GoLand 内置浏览器：下载不动的真正原因

你这条线索把前两轮查不动的问题解开了。

### 3.1 你打开的很可能不是这个服务

`localhost:63342` 是 GoLand 内置 web 服务的默认端口，它托管的是**项目里的静态文件**，不是你 `go run` 起来的 jotcash（默认 `:7678`）。两件事随之发生：

1. **接口全打偏。** 前端接口基址是相对路径 `../api/`（为了适配反代前缀）。页面在 `localhost:63342/<项目>/static/` 下时，它解析成 `localhost:63342/<项目>/api/` ——那里根本没有接口。现在是 mock 模式，不发请求，所以表面一切正常；**一旦联调必然全挂**，而且错得很隐蔽。
2. **下载不工作。** GoLand 内置浏览器是 JCEF（嵌入式 Chromium），**默认没有下载管理器**，`<a download>` 点下去就是没有任何反应——没有弹窗、没有报错、控制台也干净。这和我前两轮在真实 Chromium 里怎么测都能下载、完全对得上。

所以**前两轮我对下载的两次诊断都是错的**：第一次赌撤销时序，第二次赌摘锚点时序。两次改动本身都是对的（那两个坑真实存在，FileSaver 这类库也是这么处理的），但都不是你遇到的那个原因。**真正的原因是浏览器本身不具备下载能力**，前端没有任何办法绕过去。

### 3.2 正确的打开方式

```
go run .            # 服务起在 :7678
```
然后在**真实浏览器**里打开 `http://127.0.0.1:7678/static/`。

### 3.3 加了一个自查入口

设置页「会话与运行信息」里补了两行，**接口相对前缀解析之后的绝对地址直接摆出来**：

```
页面地址   http://127.0.0.1:7678/static/?_ijt=abc123token#/setting
接口地址   ../api/ → http://127.0.0.1:7678/api/
```

只要这一行的主机端口不是你启动的那个服务，就说明页面被别的服务托管了。这个自查如果早点有，前两轮就不用瞎猜了——**相对路径的好处是跟着反代走，代价就是「到底打到哪去了」不直观，那就把它显式打出来。**

## 二、通用约定（已实现部分核出来的，待开发接口请沿用）

### 2.1 凭据

除 `GET /api/ping` 外**每个**接口都要请求头 `Authorization: Bearer <jwt>`，且**只走请求头、不走 query**（走 query 会把口令写进访问日志）。

jwt 由前端自签，不经过后端换发：

- 算法 HS256，密钥是 **`sha256(后端口令)` 的原始字节**，不是十六进制串（`go_common/util/codec.go:93-101`）
- 载荷：`exp`（必填，`ValidateGin` 校验过期）、`iat`、`client_token`（前端口令）、`accounting_currency`（记账币种）——后两个见 `model/claims.go:11-12`
- 前端当前签的有效期是 300 秒

### 2.2 响应包络

**HTTP 状态码恒为 200**，成败一律看响应体（`go_common/util/gin.go:31-41`）：

```json
{ "code": 200, "msg": "", "data": { "object": ..., "count": 0 } }
```

`code != 200` 即失败，`msg` 是错误文案，前端**原样展示、不二次加工**。列表类接口 `data` 是 `HttpData{object, count}`，`count` 是**满足条件的总数**（不是本页条数），前端靠它算分页。

### 2.3 数据形态

| 类型 | 形态 | 依据 |
| ---- | ---- | ---- |
| 时间 | RFC3339 字符串，如 `2026-09-15T00:00:00+08:00` | Go `time.Time` |
| **时间零值** | **键直接不出现**，不要传空串 | Go 的 `time.Time` 反序列化吃不下 `""`；前端 `cleanInquiry` 已做 |
| 金额 / 汇率 | **带引号的字符串**，如 `"128.50"` | `shopspring/decimal` 默认带引号 |
| ID | 数字，16 位十进制如 `2609151607580000` | `util.GenIdByTime`；**小于 2^53，在 JS 安全整数内**，前端按数字收发 |
| 删除时间 | `null` 表示未删除 | `gorm.DeletedAt` |

### 2.4 分页与排序

- `page` **从 1 起**；`page_size` 默认 20、上限 200（`service/repo/inquiry.go:12-25`）。你提过这个上限之后会去除——去除后前端的「导出查询结果」会少翻几页，不需要改前端。
- `sort` 走白名单，不在白名单直接报错（`rdb/inquiry.go:29-38`）。现有白名单：
  - 明细：`id`/`expense_date`/`expense_amount`/`created_at` × `asc`/`desc`
  - 审计：`id`/`created_at` × `asc`/`desc`
  - 文件：`id`/`file_name`/`created_at` × `asc`/`desc`

### 2.5 上传

multipart/form-data，文件字段名统一 `file`（`config/handler.go:20-21`）。

**响应**：`{object: Expense[], count}`。`Expense` 21 个字段见 `model/expense.go:32-56`。

### 3. `POST /api/expense/insert` — 明细入库

- **请求**：multipart，字段 `file`；大小上限 `expense_file_limit`（默认 10MB）
- **响应**：`{object: <本次审计ID>, count: <入库笔数>}`
- **语义**：解析器**按文件内容认领、不看扩展名**（`service/expense/expense.go:36-45`）。当前只有本系统标准 CSV 一种，**11 列、顺序固定、表头须完全相等**（`base_csv.go:16-28`）：


- **前端三个入口共用它**：上传真实文件、新增一行（拼一份只有 1 行的 CSV）、复制已删除行。

### 7. `POST /api/token/change` — 更换口令

- **请求体**：`{"new_token": "..."}`
- **响应**：`data` 为空，靠 `code` 判成败
- **强度判据**（`tool/token.go:60-83`）：长度 ≥ 12、不得含空格、不得纯数字或纯字母。**前端已按同一套判据做了前置校验**，后端仍需自行校验。
