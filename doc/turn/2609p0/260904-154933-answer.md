## 一、范围边界

| 项 | 内容 |
| -- | ---- |
| **本轮做** | `internal/base/pwdhash` 一个包：Argon2id 哈希与校验 + 密码学安全随机源，含单测 |
| **本轮不做** | 其余 40 包一律不碰；不建 `entity.User`、不写 `rule/passwd` 的 A-8 策略校验、不写 `store` 的列类型、不引入 `base/errs` 五档错误 |

**四条硬约束**（决定了下面每一个 API 形状）：

| # | 约束 | 来源 | 对本包的直接后果 |
| - | ---- | ---- | ---------------- |
| 1 | **L0 层内零依赖**，仅依赖标准库与第三方库 | 分层版 §六 L0 表头；约定 5；§三 问题 2（`idgen` 不借道 `pwdhash` 取随机性，反向同理） | **不能 import `base/errs`**（它是 L0 兄弟包）。因此本包**不返回五档错误**，只返回普通 `error`，映射到 `base/errs` 是调用方（`service/auth` / `service/account`）的事 |
| 2 | **盐独立列存**，不用自包含哈希串格式 | 分层版 §六 L0 表；终版 §四 1 `User.盐` 是单列属性 | 不能用 PHC 串（`$argon2id$v=19$m=..,t=..,p=..$salt$hash`）——那会把盐编码进哈希串，`User.盐` 这一列就没意义了。**盐必须作为独立返回值给出** |
| 3 | **Argon2 参数写死在包内常量并带版本前缀，不进配置** | 分层版 §六 L0 表、约定 8「业务阈值一律写死在对应包（…Argon2 参数…）」 | 参数不出现在 `base/config`，也不出现在任何函数入参——**没有任何入口能把安全参数调低** |
| 4 | **密码值红线** | 分层版 §九 红线行；终版 8.4 边界② | 本包属「内存流转白名单四包」之一，但**不是三类出口**中的任何一类：因此本包**不得打印明文、哈希、盐**，日志只允许出现长度、版本号这类非物料信息 |

## 二、对外 API（5 个导出符号）

> 标识符用英文、注释与日志用中文（约定 3）；`ctx` 置首参且**仅在会打日志的函数上出现**（`go_common` 的 `CreateRandString(n int) string` 即无 ctx 的先例）。

| 符号 | 签名 | 职责 | 唯一调用方 |
| ---- | ---- | ---- | ---------- |
| `Hash` | `(ctx, plaintext string) (hash string, salt string, err error)` | 生成盐 → Argon2id 派生 → 返回**带版本前缀的哈希**与**独立的盐** | `service/account`（A-2/A-3/A-7/A-8 写密码）、`service/auth` 无需 |
| `Verify` | `(ctx, plaintext, hash, salt string) (bool, error)` | 按哈希串里的版本前缀取参数 → 重算 → **恒定时间比较** | `service/auth`（A-4 登录）、`service/account`（A-8 自助改密校验旧密码） |
| `RandBytes` | `(ctx, n int) ([]byte, error)` | n 个密码学安全随机字节 | 包内（生成盐）+ 预留 |
| `RandInt` | `(ctx, max int) (int, error)` | `[0, max)` 内**无模偏差**的均匀随机整数 | `rule/passwd`（A-2 按 A-8 字符类别采样初始密码） |
| `RandText` | `() string` | 26 字符 base32 随机串（约 128 位熵） | `rule/passwd`（A-2 不需要字符集控制时的「安全随机串」） |

**为什么随机源要出 `RandInt` 而不是直接出一个「生成初始密码」函数**：A-8 的「长度 ≥ 10、字母/数字/符号至少两类」是**业务规则**，字符集属于业务语义，按约定 5「`base/` 是纯技术层：任何带业务语义的类型都不得放入」必须留在 `rule/passwd`（分层版 §六 L2 表已把「符合策略的随机初始密码生成」判给 `rule/passwd`，并注明「采样自 `base/pwdhash` 的安全随机源」）。本包只出**无偏采样能力**，字符集由 `rule/passwd` 自己持有。

**为什么 `Verify` 的「密码错误」不是 error 而是 `(false, nil)`**：`base/errs` 的五档里「用户输入错误」与「系统错误」分属不同 HTTP 状态（分层版 §六 `middleware` 行）。密码错误是前者、且 A-8 要据此累计失败次数；哈希串损坏是后者、不该计入失败次数。用返回值 / error 两个通道区分，调用方无需解析错误内容即可分流。

## 三、五处关键取舍

### 取舍 1 · Argon2id 参数取值：RFC 9106 §4 第二组推荐值

分层版只写「Argon2 参数（内存/迭代/并行度）写死在包内常量」，**没给具体数值**；`260903-173423-answer.md:91` 只写「OWASP 现行推荐 Argon2id」。数值须本轮定档。

| 参数 | 取值 | 依据 |
| ---- | ---- | ---- |
| 变体 | Argon2id | T36 定案（`260903-201810-answer.md:1876`）；`golang.org/x/crypto/argon2` 包注释「If you aren't sure which function you need, use Argon2id (IDKey)」 |
| `time`（迭代） | **3** | RFC 9106 §4 **第二组**推荐值 `time=3, memory=64 MiB, threads=4`，即 `x/crypto/argon2` 注释中的「If much less memory is available, the second recommended option」 |
| `memory`（内存） | **64×1024 KiB = 64 MiB** | 同上。第一组推荐值是 2 GiB，个人自建单二进制服务（SQLite 单文件、终版定位「个人记账系统」）不具备为一次登录申请 2 GiB 的条件，取第二组 |
| `threads`（并行度） | **4** | 同上。**必须是常量，绝不能取 `runtime.NumCPU()`**——见下方陷阱 |
| 盐长度 | **16 字节** | OWASP 密码存储建议的最小值；`x/crypto/argon2` 注释「Remember to get a good random salt」 |
| 哈希长度 | **32 字节** | 同上（256 位） |

**这里有一个会静默锁死全部用户的陷阱，已在代码注释中写死**：`threads` **参与哈希计算**——`x/crypto/argon2` 的 `deriveKey` 把 `threads` 传进 `initHash` 生成 `h0`，并用它调整 `memory`（`memory / (syncPoints * threads) * (syncPoints * threads)`）。所以同一密码 + 同一盐在 `threads=4` 与 `threads=8` 下得到的哈希**不同**。若按「并行度自适应 CPU」的常见写法取 `runtime.NumCPU()`，则**换一台核数不同的机器部署，全部用户的密码校验立刻全部失败**；叠加终版 A-3「`admin` 遗忘密码不设计恢复路径」，后果是整个系统永久无法登录。故 `threads` 必须是编译期常量。

### 取舍 2 · 版本前缀落在哈希串上（而非仅是常量命名）

分层版原文：「Argon2 参数（内存/迭代/并行度）**写死在包内常量并带版本前缀**」。字面有两种读法：

| 读法 | 落法 | 判定 |
| ---- | ---- | ---- |
| A | 仅 Go 常量名带 `v1` 前缀 | **不采用**。版本号只存在于源码里，运行时无从得知库里某条哈希是用哪组参数算的 |
| B | 哈希串带版本前缀 `$argon2id-v1$<base64>` | **采用** |

**采用 B 的依据**：读法 A 下，将来一旦调高参数（安全参数随硬件升级本就该调高），旧哈希无法被识别，重算必然对不上 → **全部存量用户登录失败**，且 A-3 已明确 `admin` 无恢复路径。读法 B 让 `Verify` 按前缀取对应版本的参数，新旧哈希共存，加一组参数 = `paramsByVersion` 加一项 + 换 `currentVersion` 一行。

**与约束 2（不用自包含哈希串格式）不冲突**：约束 2 反对的是「把**盐**编码进哈希串」，理由是那会让 `User.盐` 这一列失去意义（`260903-201810-answer.md:1876` 原文「否则该字段无意义」）。版本前缀不含盐、不含参数值，`User.盐` 仍是唯一的盐来源，独立列存不受影响。

**格式**：`$argon2id-v1$<base64(StdEncoding) 的 32 字节>`。选 `$` 作分隔符是因为 base64 标准字母表（`A-Za-z0-9+/=`）不含 `$`，切分无歧义；`go_common` 的 `EnBase64` / `DeBase64` 同样用 `base64.StdEncoding`，编码口径一致。

### 取舍 3 · 未知版本前缀 → 返回 error，不返回「校验不通过」

库里出现本版本代码不认识的前缀（回退部署、数据被改写）时，若返回 `(false, nil)`，`service/auth` 会当成密码错误并**计入 A-8 失败次数、5 次后锁定 10 分钟**，用户被锁死却查不出原因。故一律作为系统错误暴露。哈希串格式非法、base64 解不开、盐长度不符，同此处理。

### 取舍 4 · 明文参数用 `string`，且不做内存擦除

密码明文在 Go 里从 HTTP JSON 解出来就已经是 `string`（不可变、不可擦除）。改用 `[]byte` 入参只会**多一次拷贝**，原始 `string` 仍在堆上等 GC，擦除是自欺。故直接收 `string`，不假装擦除。红线靠「白名单四包 + 三类出口」的结构约束守（分层版 §九 红线行），不靠内存擦除。

### 取舍 5 · 日志与错误：用 logrus + pkg/errors，不用 `base/errs` / `base/log`

约束 1 禁止 import L0 兄弟包。而 `logrus` 与 `github.com/pkg/errors` 是第三方库（L0 允许），且是 `go_common` 全仓库的日志与错误底座（`util/log.go` 用 `logrus` + lumberjack、`util/gen.go` 用 `errors.Errorf`），沿用它们即与项目风格一致，日志格式也能被将来的 `base/log`（`util.InitLog` 全局配置 logrus）统一接管。

**日志内容红线**：本包所有日志**只打长度与版本号**，绝不打明文 / 哈希 / 盐。理由：`base/log` 经 lumberjack 落盘（`go_common/util/log.go` 的 `InitLog` 把 `logrus` 输出接到 `log/<服务名>/log.log`），而分层版 §九 红线行规定「三类出口中 A-3 admin 初始密码日志打印是唯一落盘处」——本包不是那个出口。

### 4.2 依赖引入（不造轮子）

| 依赖 | 版本 | 用途 | 为什么不自己写 |
| ---- | ---- | ---- | -------------- |
| `golang.org/x/crypto/argon2` | **v0.55.0** | Argon2id 派生（`argon2.IDKey`） | Go 官方扩展库，PHC 获胜算法的权威实现；密码哈希自己实现属高危造轮子 |
| `crypto/rand`（标准库） | Go 1.27 | 随机源（`Read` / `Int` / `Text`） | 标准库即密码学安全随机源。**注意不能用 `go_common` 的 `util.CreateRandString`**——它底层是 `math/rand`（`util/gen.go` 的 `rand.Intn`），不是密码学安全的，用来生成盐或初始密码会直接击穿 A-2 |
| `crypto/subtle`（标准库） | Go 1.27 | `ConstantTimeCompare` | 恒定时间比较必须用标准库实现 |
| `github.com/pkg/errors` / `github.com/sirupsen/logrus` | v0.9.1 / v1.10.2 | 错误与日志 | 与 `go_common` 同底座，风格一致 |

> **关于 `x/crypto` 的选版**：实际落到 **v0.55.0** 而非最新的 v0.56.0——`go_common@v0.0.0-20260905162556` 的 `go.mod:66` 已 require `golang.org/x/crypto v0.55.0`，MVS 取该版本。已比对确认 **v0.55.0 与 v0.56.0 的 `argon2/argon2.go` 逐字节完全一致**（`diff -q` 无差异，`IDKey` 签名与 `Version = 0x13` 均相同），故对本包无任何影响，不强行抬版本以免与 `go_common` 的依赖树打架。

`go_common` 全库无任何密码哈希 / 加盐能力（`util/codec.go` 只有 MD5、SHA256、AES、RSA、JWT，均不适用于口令存储），故本包不引入 `go_common`。

### 4.3 异常与边界处理

| 场景 | 行为 | 理由 |
| ---- | ---- | ---- |
| `Hash` 明文为空 | 返回 error | A-8 要求长度 ≥ 10，策略校验在 `rule/passwd`；此处兜一道，防止调用方漏校验时把空口令哈希进库 |
| `Verify` 明文为空 | 返回 `(false, nil)` | 与「密码错误」同一表现（不给攻击者额外信息），且不必为此付出一次 64 MiB Argon2 开销 |
| `Verify` 哈希串格式非法 / base64 非法 / 版本未知 / 盐长度不符 / 哈希长度不符 | 返回 error | 取舍 3 |
| `RandBytes` n ≤ 0 / `RandInt` max ≤ 0 | 返回 error | `crypto/rand.Int` 对 `max <= 0` 是 **panic**（`crypto/rand/util.go` 的 `Int`），必须在入口挡住，不能让 panic 冒到 HTTP 层 |
| `crypto/rand.Read` 返回错误 | 仍显式判错并返回 | Go 1.27 的 `Read` 文档写明「never returns an error」，失败时直接 `fatal` 崩溃进程；此分支是防御带，不删 |

### 5.2 用例覆盖与对应约束

31 个用例分三组：`pwdhash_test.go`（包内白盒 17）、`rand_test.go`（包内白盒 11）、`zz_consumer_check_test.go`（**外部黑盒消费者验证 3**，包名 `pwdhash_test`，与兄弟包 `idgen` / `errs` 的 `zz_consumer_check_test.go` 约定同构）。

| # | 用例 | 校验的约束 |
| - | ---- | ---------- |
| 1 | 哈希 → 校验往返成功 | 基本正确性 |
| 2 | 错误密码（含大小写差异、尾部空格）→ `(false, nil)` | 取舍 3 的分流；无意外规范化 |
| 3 | 同一明文哈希两次，盐与哈希**均不同**，且各自配对仍成立 | 盐随机、每次新生成；库中不出现「相同密码相同哈希」 |
| 4 | 哈希串前缀 = `$argon2id-v1$`、载荷解出 32 字节；盐**不含**分隔符、解出 16 字节 | 取舍 2 的格式；盐不带版本号 |
