## 一、承载口径（逐条摘录，作为验收基准）

分层 §六 L0 `base/pwdhash` 行原文给出三条口径，全部落地如下：

| # | 文档口径 | 落地方式 |
| - | -------- | -------- |
| 1 | **Argon2id** 哈希与校验（T36）+ 密码学安全随机源 | `Hash` / `Verify` 走 `golang.org/x/crypto/argon2.IDKey`；随机源为 `RandBytes` / `RandIndex` / `RandString`，底座是标准库 `crypto/rand` |
| 2 | **盐独立列存**（终版 §四 `User.盐` 是单列属性，**不用自包含哈希串格式**） | `Hash` 返回 `(hash, salt)` 两个值，分别落 `User.密码哈希` 与 `User.盐`；`Verify` 由调用方把两列一并传回。**哈希串里不含盐** |
| 3 | Argon2 参数（内存/迭代/并行度）**写死在包内常量并带版本前缀**，不进配置 | 参数表 `paramTable` 是包内私有 `map[版本]参数`，哈希列形态为 `argon2id_v1$<base64 派生密钥>`；`configs/jotcash.example.yaml` 已明写「Argon2 密码哈希参数……一律写死在代码里」，本包不读任何配置 |
| 4 | 对外另出的「安全随机串」**只供 `rule/passwd` 采样初始密码**（A-2） | `RandString(ctx, n, charset)` 由调用方传字符集——A-8 的「字母/数字/符号至少两类」是业务策略，按约定 5「`base/` 是纯技术层，任何带业务语义的类型都不得放入」留在 `rule/passwd`，本包只提供无偏采样 |

补充约束：
- **L0 层内零依赖**（§六 L0 表头「仅依赖标准库与第三方库」+ 约定 5 + §三 问题 2 的修法「`base/idgen` 不借道 `pwdhash` 取随机性」）。
- **§九 红线**：明文内存流转白名单含本包（Argon2id 哈希与校验）；`密码哈希` 与 `盐` **连三类出口都不得出现**；A-3 的日志打印是唯一落盘明文处，且落在 `base/log`，**不在本包**。

## 二、关键取舍

### 取舍 1：用 `golang.org/x/crypto/argon2` 官方库，不引 `alexedwards/argon2id` 封装

prompt 要求「优先采用 github 上成熟/稳定/star 多的代码库（如果有），避免自己造轮子」。候选与结论：

| 候选 | 结论 | 依据 |
| ---- | ---- | ---- |
| **`golang.org/x/crypto/argon2`** | **采用** | Go 官方扩展库，是 Argon2 在 Go 生态的规范实现，下列所有封装库都以它为底座；`IDKey` 即 Argon2id。本地模块缓存已有 `v0.55.0` / `v0.56.0`，含 `argon2/` 与 `blake2b/`，实测可编译可运行 |
| `alexedwards/argon2id` | **不采用** | ① 它只产出**自包含 PHC 串** `$argon2id$v=19$m=..,t=..,p=..$<salt>$<key>`，**盐内嵌在哈希串里**，与承载口径 2「盐独立列存、不用自包含哈希串格式」+ 终版 §四「`盐` 是单列属性」直接冲突；照用就得「先让它拼出 PHC 串、再拆开取盐单独落列」，比直接调 `IDKey` 更绕且更易错。② 其 `DefaultParams.Parallelism = uint8(runtime.NumCPU())` 是明确的踩坑点，见取舍 3。③ 它本身只是 ~205 行的便捷封装，核心仍是 `argon2.IDKey` |
| `pilinux/argon2`、`matthewhartstonge/argon2` 等 | 不采用 | 同样是 `x/crypto/argon2` 的封装，且各自引入 PHC 串或 secret/pepper 等本设计未要求的形态，额外依赖换不来收益 |

**这不算「造轮子」**：Argon2id 算法本体、BLAKE2b、拒绝采样随机数全部来自官方实现；本包只写「按承载口径 2/3 要求的编解码与恒定时间比较」——把派生密钥 base64、拼版本前缀、按版本查参数、`subtle.ConstantTimeCompare`，正是任何封装库都无法替我们做的那部分（因为要求盐分列存放、参数不入串）。

### 取舍 2：不复用 `go_common` 的随机串实现

`go_common/util/gen.go:14-27` 的 `CreateRandString` 基于 **`math/rand`**（`rand.Intn`），是可预测的伪随机数，**不是密码学安全随机源**，用于初始密码（A-2）或盐会直接击穿 A-8。因此本包的随机源自出，底座为标准库 `crypto/rand`。这也是分层把「密码学安全随机源」写进 `base/pwdhash` 承载、而非指向既有工具库的原因。

同理，本包**不 import `go_common`**：只需要日志，而 `logrus` 是全局单例，`base/log`（按 `260904-153910-prompt.md` 走 `go_common/util.Init`）的配置对本包自动生效，无需 import 边。

### 取舍 3：并行度 `p` 必须写死为常量，不能取 `runtime.NumCPU()`

Argon2 的 `p`（lane 数）**参与哈希计算**，改变 `p` 会改变输出。本机实测（14 核 darwin/arm64）：同一 `(明文, 盐)` 下 `p=4` 与 `p=2` 产出的派生密钥**不相同**。因此若按 `runtime.NumCPU()` 取值，开发机（14 核）写入的哈希在 4 核服务器上**永远校验不通过**，且表现为「密码突然全错」这种极难定位的故障。承载口径 3「参数写死在包内常量」正是为此，本包 `threads` 取固定 `4`。

### 取舍 4：参数取值 = RFC 9106 §4 第二推荐档

T36 只定了算法（Argon2id），**具体代价参数文档未给**，本轮定值如下并写死：

| 参数 | 取值 | 依据 |
| ---- | ---- | ---- |
| 迭代次数 `time` | **3** | RFC 9106 §4 第二推荐档（`x/crypto/argon2` 包注释亦原文引用：`time=3, memory=64*1024 KiB, threads=4`） |
| 内存 `memory` | **64 MiB**（65536 KiB） | 同上；亦与 OWASP 密码存储建议的等强度组合之一一致 |
| 并行度 `threads` | **4** | 同上；固定值，见取舍 3 |
| 盐长度 | **16 字节**（128 bit） | RFC 9106 推荐 128-bit 盐 |
| 派生密钥长度 | **32 字节**（256 bit） | RFC 9106 推荐 256-bit tag |

**实测耗时**（本机 14 核 darwin/arm64，`x/crypto v0.56.0`，5 次均值）：

| 组合 | 单次耗时 |
| ---- | -------- |
| **t=3 / m=64MiB / p=4（本包采用）** | **约 27 ms** |
| t=2 / m=19MiB / p=1（OWASP 基线档） | 约 16 ms |
| t=1 / m=64MiB / p=4 | 约 9 ms |
| t=3 / m=32MiB / p=4 | 约 12 ms |

27 ms 落在交互式登录的延迟预算内，取更强的第二推荐档而非 OWASP 基线档。

### 取舍 5：本包返回标准 Go error，不返回 `base/errs` 五档

`base/errs` 与 `base/pwdhash` **同属 L0**，而 L0 层内零依赖（§六 L0 表头、约定 5、§三 问题 2）——本包**不能** import `base/errs`，也不能 import `base/log`。因此：

- 本包只返回标准 error（沿用项目风格的 `github.com/pkg/errors.Errorf`）；
- 「五档」映射由调用方 `service/auth`（A-4/A-8）与 `service/account`（A-2/A-3/A-7）完成——它们在 L5，import `base/errs` 无障碍；
- 日志直接用 `logrus.WithContext(ctx)`，与 `go_common/util` 各文件一致。

> 该推论文档未明写，登记为「**已确认（由 L0 层内零依赖约束推导）**」，非脑补：三处原文（L0 表头「仅依赖标准库与第三方库」、约定 5「L0 层内零依赖」、§三 问题 2 修法「7 个包的依赖列一律 `—` 名副其实」）互相印证。

### 取舍 6：`Verify` 的「空明文」与「哈希/盐异常」区别对待

| 入参异常 | 处置 | 理由 |
| -------- | ---- | ---- |
| 明文为空 | 返回 `(false, nil)`，不报错 | 明文来自**用户输入**，空口令是正常业务分支（A-8 与 `dto` 会先拦）。`Hash` 拒绝空明文，故空明文不可能匹配任何存量哈希，判不匹配是安全的；若报错会被上层映射成「系统错误」，把用户输入问题误报成故障。提前返回只泄露「本次提交的明文为空」——这是提交者本就知道的事，不构成侧信道 |
| 哈希或盐为空、无版本前缀、版本不认识、base64 非法、解码后长度与该版本参数不符 | 返回 `(false, err)` | 这两个值来自**库内存量数据**，异常即数据损坏或跨版本不兼容。必须与「密码错误」区分开，否则数据损坏会被静默显示成「密码错误」，运维无从发现 |

`Hash` 侧则**拒绝空明文并报错**：这不是业务策略（本包不做 A-8 的长度与字符类别校验），而是「禁止把空口令写成合法凭据」的失败关闭兜底——A-8 已要求长度 ≥ 10，该分支永远不会挡住合法流程。

### 取舍 7：无偏采样直接用标准库 `crypto/rand.Int`

`RandIndex` 若写成 `随机字节 % n` 会引入**取模偏置**（n 不是 2 的幂时低位下标概率偏高），使初始密码的熵低于名义值。标准库 `crypto/rand.Int` 内部已做拒绝采样、天然无偏，直接复用而不手写拒绝采样循环。`RandString` 按 **rune** 而非 byte 采样，保证传入多字节字符集时不产出半个 UTF-8 字符。

## 三、模块设计

包路径 `internal/base/pwdhash`（分层 §十 目录树原样）。按承载的两件事拆两个文件：

| 文件 | 职责 | 对外 |
| ---- | ---- | ---- |
| `pwdhash.go` | Argon2id 哈希与校验、版本与参数表 | `Version`、`Hash`、`Verify` |
| `rand.go` | 密码学安全随机源 | `RandBytes`、`RandIndex`、`RandString` |

### 对外 API

| 签名 | 输入 → 输出 | 关键逻辑 | 异常分支 |
| ---- | ----------- | -------- | -------- |
| `Version` 常量 = `"argon2id_v1"` | — | 当前哈希版本，写入哈希列前缀 | — |
| `Hash(ctx, password string) (hash, salt string, err error)` | 明文 → 哈希列值 + 盐列值 | 取当前版本参数 → `RandBytes(16)` 生成盐 → `argon2.IDKey` → 哈希列 = `argon2id_v1$<b64 密钥>`、盐列 = `<b64 盐>` | 明文为空 → 报错；随机源失败 → 透传 |
| `Verify(ctx, password, hash, salt string) (bool, error)` | 明文 + 库内两列 → 是否匹配 | 切分版本前缀 → 查参数表 → 解码盐与密钥 → 校验长度 → 同参数重算 → `subtle.ConstantTimeCompare` | 见取舍 6 |
| `RandBytes(ctx, n int) ([]byte, error)` | 字节数 → 随机字节 | `crypto/rand.Read` | `n <= 0` → 报错（**不返回空切片**：调用方可能直接当盐或密钥使用） |
| `RandIndex(ctx, n int) (int, error)` | 上界 → `[0, n)` 内无偏随机下标 | `crypto/rand.Int` | `n <= 0` → 报错 |
| `RandString(ctx, n int, charset string) (string, error)` | 长度 + 字符集 → 随机串 | 字符集转 `[]rune`，逐位 `RandIndex` 采样 | `n <= 0`、字符集为空 → 报错 |

### 红线落地（§九）

- **日志字段只出现长度、版本、错误原因，绝不出现明文 / 哈希 / 盐**——本包所有 `logrus` 调用逐一核对；并写了回归测试用 `logrus` 官方 test hook 抓取日志，断言明文不出现在任何一条日志里。
- 本包**不落盘、不进审计、不读写配置**，只做纯计算与随机数生成。
- 明文仅以入参形式出现在 `Hash` / `Verify` 的调用栈内，不写入任何包级变量。

### 依赖

| 依赖 | 用途 | 层级合规 |
| ---- | ---- | -------- |
| `golang.org/x/crypto/argon2` | Argon2id 实现 | 第三方库，L0 允许 |
| 标准库 `crypto/rand` / `crypto/subtle` / `encoding/base64` / `math/big` / `strings` / `context` | 随机源、恒定时间比较、编解码 | 标准库，L0 允许 |
| `github.com/sirupsen/logrus`、`github.com/pkg/errors` | 中文日志与错误（对齐 `go_common/util` 风格） | 第三方库，L0 允许 |

**层内零依赖成立**：不 import `base/` 下任何兄弟包（含 `errs` / `log` / `idgen`）。

| 12 | `TestRandBytes` | 长度正确；两次取值不同；**不返回全零切片**；`n <= 0` 报错且返回 `nil`（不把空切片当合法盐） |
| 13 | `TestRandIndex` | 6 组上界 × 200 次采样恒落 `[0, n)`；`n = 1` 恒为 0；`n <= 0` 报错且返回 0 |
| 14 | `TestRandIndexCoverage` | 2000 次采样覆盖全部 10 个取值（粗查分布，拦「退化成常量或只取低位」） |

### 5.3 变异测试（确认用例真的会失败）

覆盖率只说明代码被执行过，不说明断言有效。故逐一注入真实缺陷，确认对应用例**会失败**；每次注入后立即从备份复原，并以 `diff` 确认源码零残留。

| # | 注入的缺陷 | 结果 |
| - | ---------- | ---- |
| 1 | 盐退化为固定全零（随机盐失效） | ✅ 被 `TestHashSaltIsRandom` 捕获 |
| 2 | `Verify` 忽略盐（传全零盐） | ⚠️ **初版 `TestVerifyWrongSalt` 未捕获** → 已修正，见下 |
| 3 | 并行度由 4 偷偷改为 2（参数漂移） | ✅ 被 `TestParamsPinned` 捕获 |
| 4 | 日志字段加上 `"pwd": password`（红线破防） | ✅ 被 `TestNoPasswordInLog` 捕获 |
| 5 | `RandString` 改为按 byte 采样 | ✅ 被 `TestRandStringMultiByteCharset` 捕获 |

**变异 2 暴露的真实缺陷（已修）**：初版 `TestVerifyWrongSalt` 只有「换盐 → 应不匹配」这一条反向断言。而当 `Verify` 把盐替换成全零时，算出的密钥与存量哈希本就不同，反向断言**依然通过**——用例是「碰巧过」的，无法区分「盐被忽略」与「盐不对」。已补上**正向断言**（配对的盐必须匹配），重跑变异 2 后确认被单独捕获（报错定位到「配对的盐校验不通过」）。全量用例此时也有 4 个失败，但单个用例自身能捕获才算断言到位。

补充确认：把 `subtle.ConstantTimeCompare` 换成 `==` 普通比较属**功能等价**改动，行为用例本就无法区分（该改动只影响时序侧信道，非功能差异）——实际因 `crypto/subtle` 变成未使用 import 而**编译失败**，故此项不作为有效变异计入。恒定时间比较的必要性靠代码注释与评审保证，这是行为测试的固有边界，如实登记。

## 六、副作用评估

- **对现有链路**：仓库此前无 Go 实现，本包是首批产物，**无存量影响**。
- **对下游**：确立了三处将被下游依赖的契约——① `Hash` 返回**两个值**（哈希列 + 盐列），`store` 的 `User` 仓储更新方法需同时写 `密码哈希` 与 `盐`（分层 §六 `store` ② 已列这两项）；② `Verify` 返回 `(bool, error)` 双值，`service/auth` 需把 error 与「密码错误」分开处理（前者映射 `base/errs` 系统错误档，后者走 A-8 失败计数）；③ `RandString` 的字符集由 `rule/passwd` 提供，A-8 的字符类别策略不下沉到本包。
- **性能**：每次 `Hash` / `Verify` 约 27 ms CPU + 瞬时 64 MiB 内存。个人系统规模下可接受。
- **兼容性**：哈希列自带版本前缀，将来调参数 = 加一个版本条目 + 在改密时按新版本重算，存量哈希仍可校验，**无需数据迁移**。
