## 二、背景调研：承载边界与「为什么需要这个包」

### 2.1 存在理由（不是可选优化，是修静默错）

终版 §一 前提 7：「支出日期以账单字面值为准，**不做时区换算**」。分层版 §九 反向校验表前提 7 行把唯一实现处定为 **`base/calendar` 的日历日期类型**，并约束「**任何包不得引入带时区的时间类型参与支出日期的解析、存储与归月**（业务时间戳如创建/更新/操作时间不受此限）」。

若用 `time.Time` 承载 `Expense.支出日期`，同一账单字面值 `2026-01-01` 在不同 `TZ` 下 `.Month()` 会落到不同月份，于是**三处同时错且静默**：

1. `摊分起始月`（终版 §八 8.2「起始月 = 支出日期所属月」）；
2. J-1 未摊分口径「按支出日期归月」（终版 §二 J-1）；
3. I-4 日汇率取数「按支出日期的日汇率折算」（终版 §二 I-4）。

所以本包的三个类型是**前提 7 的结构性落点**，而非工具类。

### 2.2 承载四项 → 类型分工

| 分层版 §六 承载原文 | 落到 | 说明 |
| ------------------ | ---- | ---- |
| 不带时区的日历日期类型 | `Date` | `entity.Expense.支出日期`、`parser` 原始交易行的支出日期、F-4 日期区间筛选 |
| 年月类型 | `Month` | `entity.Expense.摊分起始月` / `摊分结束月`（终版 §四 只读派生 4 项之二） |
| 区间运算（`起始月 + N − 1`、`起始月 ≤ M ≤ 结束月`） | `MonthRange` + `Month.AddMonths` | 前者是 `rule/amortize` 的结束月派生（不变式 1b），后者是 §八 8.2 的**区间穿刺**判据 |
| 日期 → 所属月 | `Date.ToMonth()` | §八 8.2「起始月 = 支出日期所属月」这条边 |

### 2.3 明确**不**放进本包的（约定 5「`base/` 是纯技术层」）

- **不放**「当前月 / 今天」这类隐含部署决策的便捷函数（`Today()`）——见 §五 5.5；
- **不放**业务阈值：摊分月数默认 1、无上限（终版 H-1、前提 5）属业务规则，归 `rule/amortize`，本包只提供「给定月数算区间」的纯运算；
- **不放**币种小数位、金额（归 `currency` / `base/decimal`）；
- **不放**创建时间 / 更新时间 / 操作时间 / 上传时间等业务时间戳——前提 7 明确「不受此限」，它们仍用 `time.Time`，不进本包。

## 四、选型：先找库，再决定自研边界

> prompt 要求「优先采用 github 上成熟/稳定/star 多的代码库（如果有），避免自己造轮子」。以下为实际检索与**实测**结论，而非印象。

### 4.1 日期类型：采用 `cloud.google.com/go/civil`

| 候选 | 实测 / 核查结论 | 取舍 |
| ---- | -------------- | ---- |
| **`cloud.google.com/go/civil`** | 包文档原文：「implements types for civil time, a **time-zone-independent** representation of time」——语义与前提 7 完全同构。`Imported by 573`、Apache-2.0、v0.123.0（2025-09 仍在维护）。`Date` 提供 `AddDays`/`AddMonths`/`DaysSince`/`Compare`/`IsValid`/`IsZero`/`Scan`/`Value`。**关键实测**：`civil.go` 仅 import `database/sql/driver`、`fmt`、`time`；`go list -deps` 结果**全是标准库**；`go mod tidy` 后 `go.mod` 只多一行 `cloud.google.com/go v0.123.0`，`go.sum` 只含 2 个 module（module graph pruning 生效），**不会带入 grpc/otel/GCP SDK** | **采用**（作内核） |
| `github.com/golang-sql/civil` | 从上者 fork、专供 database/sql。但**缺 `AddMonths`、`Compare`、`Scan`、`Value`**（pkg.go.dev 索引核对），且停留在 `v0.0.0-20220223132316`（无 tag、2022 年后无更新）。我们恰恰需要 `AddMonths` 做年月运算 | 不用 |
| `github.com/rickb777/date` | 142 star，功能更全（Date/period/timespan）。但**无年月类型**，且体量与承载不匹配——本包只需要「日期 + 年月 + 月区间」，引入 period/timespan/clock 是超配 | 不用 |
| `github.com/domonda/go-types/date` | 是唯一检索到**带 `YearMonth`** 的库，但 `YearMonth` 定义为 `string`（弱类型，无法保证「非零必合法」），且该库是大杂烩类型库，star 少、会带入大量无关依赖 | 不用 |
| `github.com/cellargalaxy/go_common/util`（本项目在 `base/log`、`base/idgen` 两轮已确定引入的库） | 已核 `util/time.go` 全文：只有 `DateLayout_2006_01_02` / `DateLayout_2006_01` 等 layout 常量与时间戳互转，**没有任何不带时区的日期类型**，无法承载本包核心。**实测**：`util` 包连带 gin / gorm / excelize / mongo-driver 等，`go.sum` 达 80 个 module | **不为两个字符串常量 import 它**：会让 L0 的 `calendar` 及其单测链接进 Web / ORM 框架，与约定 5「`base/` 是纯技术层」相悖。两个 layout 是 Go 标准参考时间写法，本包内定常量即可。**登记为显式取舍** |

### 4.2 年月与月区间：自研（无库可用）

结论：**没有口径匹配的成熟库**（`civil` 无年月类型；`domonda` 的 `YearMonth` 是 string）。因此 `Month` / `MonthRange` 自研，但**日历算术仍下沉给 `civil`**（`Month.FirstDate/LastDate`、`Date.AddDays` 等），不自己写闰年与月末进位——「自研」限于**类型与不变式**，不重造日历算法。

### 4.3 为什么是「包装」而不是 `type Date = civil.Date`

别名会把 `civil.Date` 的三个性质一起暴露到全仓库，其中两个有害：

1. **导出字段可写** ⇒ 任何包都能构造 `{2026, 2, 30}` 这种不存在的日期，`IsValid()` 需被显式记得调用，漏一处即静默流到 `store`；
2. **`In(loc *time.Location) time.Time` 直接可用** ⇒ 这正是分层版 §九 前提 7 行明令禁止的「引入带时区的时间类型参与解析 / 存储 / 归月」的现成入口；
3. `civil.Date{}.Value()` 对零值返回字符串 `"0000-00-00"` ⇒ 一个 `ParseDate` 反过来解不回来的非法字面值会被写进库。

因此：**私有字段包装 + 只导出业务需要的方法**（不导出 `In`）。这是准则 6「能用结构表达的不写成口头约定」在本包的落地。

## 五、关键口径（每条都是「照此实现不会静默出错」的约定）

### 5.1 「非零值必合法」不变式

三个类型字段全私有，构造入口只有 `NewX` / `ParseX` / `DateOf`（及其 `MustX` 变体），全部在入口校验。于是全仓库成立：**一个 `Date`/`Month`/`MonthRange` 值要么 `IsZero()`，要么合法**。上层不需要（也无法）传播非法日期。

### 5.2 年份边界 `[1, 9999]`

不是随手设的上下界，理由有二：① `String()` 用 `%04d` 定长格式化，越界会破坏定长；② 定长是 5.3 那条正确性前提的基础。越界一律返回 `ErrYearRange`，`AddMonths` / `AddDays` 溢出同样拦截（**返回 error 而不是静默 wrap**）。

### 5.3 文本形态是唯一权威形态：定长 ⇒ 字典序 = 时间序

`Date` 定长 10 字符 `2006-01-02`、`Month` 定长 7 字符 `2006-01`。这条性质被 `store/sqlite` 直接依赖：SQLite 无原生 DATE 类型，日期以 TEXT 落库后，`ORDER BY`（F-3 按日期排序）、`BETWEEN`（F-4 日期区间）、以及 §八 8.2 **区间穿刺**的 `起始月 ≤ M AND 结束月 ≥ M` 全部可用**朴素字符串比较**完成，无需 SQL 侧函数。

对应地**不选** unix 时间戳存储：整数时间戳必须先选定一个时区才能还原「哪一天」，与前提 7 直接冲突。

### 5.4 零值 ⇔ SQL NULL ⇔ JSON null

`Value()` 对零值返回 `nil`（NULL），非零返回文本；`Scan(nil)` 与 `UnmarshalJSON(null/"")` 回到零值。

- 用途：F-4 日期区间的端点是**可选**的，「未指定」必须可表达；
- **取舍（有意为之）**：若 `Expense.支出日期`（终版 §四 必填 ✓）因上层 bug 为零值，落库时会因 `NOT NULL` 约束**报错**而不是写进一个 `"0000-00-00"`。选 fail-fast，不选静默污染。

### 5.5 与 `time.Time` 的边界：**只留入口，不留出口**

- **入口**：`DateOf(t time.Time)` —— 取 `t` **自身时区**下的年月日，不做换算。这是本包与带时区时间的唯一接触点。
- **不提供出口**：不导出 `In(loc)`、不提供 `Time()`。§三 逐条核对后确认无人需要——外部汇率源要 `2026-09-06` 字符串（`String()`）、`store/sqlite` 要 TEXT（`Value()`）、`dto` 要 JSON（`MarshalJSON`）、`parser` 要解析（`ParseDate`）。将来确有需要再加（可逆，且届时必须显式说明用途）。
- **不提供 `Today()`**：`Today()` 隐含「用哪个时区判定今天」这一部署决策，放进 L0 会让决策失去落点。不提供，等于强制调用方显式写出 `calendar.DateOf(time.Now().In(loc))`，让时区选择在调用点可见、可评审。

### 5.6 错误：哨兵错误，不 import `base/errs`

分层版 §六 L0 表头「层内零依赖」+ 该行依赖列 `—` ⇒ 不能依赖同层 `base/errs`。本包导出哨兵错误（`ErrDateFormat` / `ErrDateValue` / `ErrMonthFormat` / `ErrMonthValue` / `ErrYearRange` / `ErrMonthCount` / `ErrMonthOrder` / `ErrScanType`），上层用 `errors.Is` 映射到 `base/errs` 的「用户输入错误」档与文案键。这与 `parser` 承载「错误分类……一律返回带文案键的 `base/errs`」是配套的：分类信息由本包给出，文案与档位由上层附加。

### 10.2 与方案的差异

实现期新增的两处**实现细节**（不改变对外语义，登记备查）：

1. `ParseDate` / `ParseMonth` **不直接用 `time.Parse`**，改为逐字符校验分隔符与数字后再交 `NewDate` / `NewMonth`。原因：`time.Parse("2006-01-02", "2026-1-02")` 会**接受**非定长写法，而 §五 5.3 的「定长 ⇒ 字典序 = 时间序」是 `store/sqlite` 侧排序与 `BETWEEN` 的正确性前提，必须在入口就拦住。另配 `parseDigits` 拒绝 `strconv.Atoi` 会放过的 `"+12"`、`" 12"`。
2. `Month.LastDate()` 用「下月 1 日回退 1 天」实现。对 `9999-12` 会临时构造 `10000-01-01`，但 `civil.Date` 本身不限年份上界，回退后落回 `9999-12-31` 不越界——已由 `TestMonthFirstLastDate` 的上界用例实测确认。

### 10.4 变异测试（验证「测试真能拦住回归」而非仅仅通过）

覆盖率高不等于断言有效。故对 4 处关键不变式各注入一个真实 bug，确认测试**会红**、复原后**回绿**：
