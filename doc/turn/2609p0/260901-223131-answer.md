## 一、系统定位与范围边界

- 定位：个人/小团队的支出记账与分析系统，以「银行 PDF 对账单导入」为主要数据来源，以「支出分类打标 + 跨月摊分 + 月度分析」为核心价值。
- 在范围内：账户与登录、数据隔离、PDF 账单导入解析、支出去重、支出明细维护、支出类型打标、支出摊分、多币种折算、明细查询统计、月度统计分析。
- 暂不在范围内（本轮未提及，标记为不可推断）：收入与收支结余、预算与超支提醒、账本/多账本共享、资产负债与净值、报销与对账工作流、发票与凭证管理、还款与分期负债跟踪。
- 术语口径：原始诉求中的 "denglt" 按上下文理解为登录态（见待确认 Q1）。

## 三、功能清单（按业务域，一项一句）

### A. 账户与认证域

- A-01 系统初始化：系统首次启动时内置唯一管理员账户。
- A-02 登录：账号 + 密码登录，签发登录态。
- A-03 登出：主动注销登录态。
- A-04 全局登录态校验：除登录页与登录接口外，所有页面与接口强制校验登录态。
- A-05 登录态失效处理：过期/失效后统一跳回登录页（推导）。
- A-06 新增账户：仅管理员可创建新账户并设置初始密码。
- A-07 账户列表：仅管理员可见，仅展示账户元信息，不含任何业务数据（推导）。
- A-08 账户启用/禁用：管理员冻结或恢复账户（推导）。
- A-09 重置密码：管理员重置他人密码（推导）。
- A-10 修改本人密码：用户自助改密（推导）。
- A-11 密码安全策略：密码加盐哈希存储、强度校验、登录失败次数限制（推导）。

### B. 权限与数据隔离域

- B-01 数据归属：所有业务数据（账单文件、导入批次、支出明细、类型、规则、汇率偏好）均绑定归属用户。
- B-02 查询强制过滤：所有列表、详情、统计、导出一律按归属用户过滤。
- B-03 按 ID 访问的归属校验：明细编辑/删除、批次回滚、原始账单文件下载等均校验归属，防止越权（推导）。
- B-04 操作审计：记录登录、账户管理、导入、批量修改、删除等敏感操作（推导）。

### C. 数据来源域（账单导入）

- C-01 账单上传页：上传银行 PDF 对账单。
- C-02 加密 PDF 解密：上传时可输入密码解密受保护的 PDF。
- C-03 密码校验反馈：密码错误/文件损坏/非账单文件的明确提示（推导）。
- C-04 账单解析：从 PDF 中解析出逐笔交易，作为支出数据来源。
- C-05 解析模板适配：按「银行 + 账单格式」选择或匹配解析规则（推导，多银行必需）。
- C-06 账期识别：识别该份账单覆盖的账期起止日期（去重与重叠判断的基础）。
- C-07 解析结果核对：解析出的笔数/金额合计与账单汇总值比对，防止漏解析（推导）。
- C-08 入库前预览：解析结果先进入预览态，可逐条勾选、修改后再确认入库（推导）。
- C-09 导入批次管理：每次导入生成一条批次记录（文件名、银行卡、账期、笔数、金额、状态、时间）。
- C-10 批次回滚：整批撤销某次导入产生的数据（推导，纠错必需）。
- C-11 原始文件与原始摘要留存：保留原文件与每笔交易的原始文本，供追溯与复核（推导）。
- C-12 手工补录：支持手工新增单笔支出，覆盖 PDF 之外的现金/其他来源（推导）。
- C-13 银行卡片档案：维护「银行 + 卡片别名 + 卡号后四位 + 卡片币种」，用于标识数据来源并界定去重范围（推导）。

### D. 去重域

- D-01 交易指纹：以「归属用户 + 卡片 + 支出日期 + 金额 + 币种 + 对手方（+ 原始摘要）」生成唯一指纹。
- D-02 入库前查重：确认入库前对逐笔交易做指纹比对，标记「疑似重复」。
- D-03 账期重叠检测：新账单账期与已导入账期存在重叠时提示，并对重叠区间重点查重。
- D-04 重复处理策略：对疑似重复项支持「跳过 / 人工确认后仍导入 / 覆盖更新」。
- D-05 非重复白名单：允许把「同日同金额同商户的两笔真实消费」人工标记为非重复，避免误杀（推导，真实场景必现）。
- D-06 去重日志：记录本次被跳过的条目及判定依据，可回看（推导）。

### E. 支出明细域

- E-01 明细字段：支出日期、支出金额、支出币种、交易对手方、交易备注、支出类型、摊分月数。
- E-02 系统字段：来源批次、来源卡片、原始摘要、本位币折算金额与汇率、创建/更新时间（推导）。
- E-03 明细列表页：逐笔查看支出明细，分页展示。
- E-04 多维筛选：日期区间、金额区间、币种、对手方（模糊）、备注（模糊）、支出类型（多选）、来源批次/卡片、是否摊分、是否未打标。
- E-05 排序：按日期/金额等排序（推导）。
- E-06 逐笔编辑：E-01 的七个字段全部可修改。
- E-07 批量编辑：批量设置支出类型、批量设置摊分月数（推导，打标效率必需）。
- E-08 新增/删除明细：手工增删单笔支出（推导）。
- E-09 筛选态累计统计：当前筛选条件下的笔数、按币种分组金额合计、本位币折算总额。
- E-10 明细导出：导出当前筛选结果（推导）。
- E-11 编辑留痕：关键字段的修改历史（推导，可选）。

### F. 支出类型（打标）域

- F-01 类型字典：维护交通/餐饮/住宿等支出类型，支持自定义增删改。
- F-02 类型层级：支持一级/二级分类（推导，可选）。
- F-03 默认类型：未识别的支出统一落入「未分类」（推导）。
- F-04 自动打标规则：按对手方/备注关键词匹配规则，导入时自动赋类型（推导）。
- F-05 规则维护与优先级：规则的增删改与命中优先级（推导）。
- F-06 打标记忆：某对手方被人工改过类型后，后续同对手方自动沿用（推导）。
- F-07 未分类待办：集中展示未打标支出，提供快速批量打标入口（推导）。
- F-08 类型删除保护：被引用的类型不可直接删除，需迁移或停用（推导）。

### G. 摊分域

- G-01 摊分月数：每笔支出可设置摊分月数，默认 1（即不摊分）。
- G-02 摊分起始月：默认以支出日期所属月为第 1 个摊分月（是否允许自定义起始月见待确认 Q4）。
- G-03 摊分份额生成：一笔支出按摊分月数展开为 N 条「月度份额」。
- G-04 均分与尾差规则：金额均分，除不尽的尾差固定归入首月或末月（需统一规则，见待确认 Q5）。
- G-05 摊分重算：修改摊分月数（或金额、日期）后，该笔支出的全部份额整体重算，旧份额作废。
- G-06 摊分预览：编辑摊分月数时，即时展示覆盖月份区间与每月分摊金额。
- G-07 跨月影响提示：保存前提示「本次修改将影响 YYYY-MM ~ YYYY-MM 的月度统计」（推导）。

### H. 多币种域

- H-01 币种字典：维护系统支持的币种（推导）。
- H-02 本位币设置：设定统一折算的本位币（系统级或用户级，见待确认 Q6）。
- H-03 汇率表维护：维护「币种 + 日期（或月份）+ 汇率」，支持手工录入与修改（推导）。
- H-04 入账折算：记账时按规则折算出本位币金额（详见「四、关键议题 1」）。
- H-05 汇率快照：把折算时使用的汇率随明细一并留存，保证历史报表可复现。
- H-06 单笔汇率覆盖：允许对个别支出手工指定实际成交汇率（推导，真实刷卡场景常见）。
- H-07 缺失汇率处理：缺汇率时明确提示并列出待补清单，不静默按 1:1 处理（推导）。
- H-08 展示口径切换：统计与列表支持「原币展示 / 本位币折算展示」切换。

### I. 查询与统计域（月度分析）

- I-01 月度支出总额（未摊分口径）：按支出日期归月的每月支出金额。
- I-02 月度支出总额（摊分口径）：按摊分份额所属月份归月的每月支出金额。
- I-03 口径切换：同一页面上一键切换 I-01 / I-02 两种口径。
- I-04 月度类型分布：按支出类型看每月金额与占比，两种口径均支持。
- I-05 趋势与对比：多月趋势、环比/同比对比（推导）。
- I-06 下钻明细：从某月某类型下钻到构成它的支出明细（摊分口径下展示「份额 + 来源支出」）。
- I-07 币种维度统计：按币种拆分的月度金额（推导）。
- I-08 未来月份视图：展示已发生支出摊到未来月份的份额（摊分口径的自然结果，见待确认 Q7）。
- I-09 统计口径说明：页面上明示当前统计的口径与筛选语义，避免用户误读（推导，见「四、关键议题 2」）。

### J. 基础配置与运维域

- J-01 基础数据配置页：币种、本位币、支出类型、银行卡片、汇率的集中维护（推导）。
- J-02 操作日志查看：查看本人的关键操作记录（推导）。
- J-03 数据导出/备份：整体导出本人数据（推导）。

## 四、关键议题与方案取舍

### 议题 1：多币种如何统一处理？（对应原始诉求「对于多币种如何进行统一处理？」）

候选方案

| 方案                          | 做法                                                     | 优点                           | 缺点                                                           |
|-------------------------------|----------------------------------------------------------|--------------------------------|----------------------------------------------------------------|
| A 不统一                      | 只存原币，统计按币种分组                                 | 最简单、绝对准确               | 看不到「总支出」，多币种用户的核心诉求落空                     |
| B 入账折算 + 汇率快照（推荐） | 记账时按交易日汇率折算出本位币金额，把金额与汇率一起固化 | 报表可复现、统计快、历史不漂移 | 需要维护汇率表；补录汇率后要重算受影响的记录                   |
| C 查询时实时折算              | 只存原币，统计时按当前汇率换算                           | 无需固化                       | 同一张报表不同时间看到的数字不同，无法对账；每次统计都要查汇率 |

采用方案 B，具体规则：

1. 一笔支出同时保存：原币金额 + 原币种 + 折算汇率 + 本位币金额；
2. 汇率取「支出日期当天汇率」，当天缺失则回溯取最近一个有效汇率日，并标记为「近似汇率」；
3. 允许对单笔支出手工覆盖汇率（刷卡实际入账汇率优先于牌价）；
4. 汇率完全缺失时，该笔标记「待折算」，仍进入明细，但在本位币合计中单独列出「未折算金额」，不静默计 0 也不按 1:1 处理；
5. 所有统计默认按本位币展示，可切回原币分组展示；
6. 摊分份额在本位币金额上做均分，避免份额随汇率变动而变化。

> 取舍依据：原始诉求要求「按月查看支出金额」并在明细页做「累计统计」，两者都必须给出单一可比的总额；同时记账系统的报表必须可复现，故排除
> C；A 无法满足统计诉求。

### 议题 2：修改摊分月数后如何处理查询的筛选与统计范围？（对应原始诉求最后一条）

问题本质：一笔支出有两个时间属性——发生时间（支出日期）与归属时间（摊分份额所属月），改摊分月数只改后者，会同时影响多个月的统计结果。若筛选条件与统计口径混用这两个时间，用户必然看到「总额对不上」。

处理原则（四条）

1. 口径显式化，不隐式混用：系统只提供两种明确口径——
    - 发生口径（未摊分）：以支出日期归月，一笔支出只落在一个月，合计 = 该月实际刷卡额；
    - 摊分口径：以份额所属月归月，一笔支出可落在多个月，合计 = 该月应承担的成本。 页面上必须标注当前口径（I-03、I-09）。
2. 筛选语义跟随口径：在摊分口径下，「月份」筛选的含义是份额所属月（即「M 月承担了哪些成本」，来源支出日期可能远早于
   M）；如果用户想问「某段时间发生的支出摊到了哪些月」，那是发生口径下的下钻视图，两者分开入口，不在同一个查询里混用。
3. 份额物化 + 整笔重算：把摊分结果落成独立的「月度份额」数据；修改摊分月数时，以该笔支出为单位先删旧份额、再全量重建，保证重算幂等、不会残留脏份额。任何统计都只读份额，不在查询时临时展开。
4. 不变式校验：任一支出的所有份额金额之和恒等于该支出的本位币金额；系统提供一致性校验，防止尾差累积。

衍生规则

- 修改前用 G-06/G-07 展示「影响月份区间 + 每月新旧金额差异」，让跨月影响可预期；
- 摊分口径下的「合计」天然包含未来月份份额，需在 UI 上区分「已发生（≤ 当前月）」与「未来待摊」两段（见待确认 Q7）；
- 若未来引入「关账/锁月」，则重算落在已关账月份的份额需要拦截或走调整分录（本轮不做，见待确认 Q8）。

## 五、核心业务流程（概要）

1. 开户流程：管理员登录 → 新增账户 → 交付初始密码 → 用户首次登录（建议强制改密）。
2. 登录与鉴权流程：登录页提交账号密码 → 校验通过签发登录态 → 后续任意页面/接口先校验登录态、再按归属用户过滤数据。
3. 账单导入流程（主流程）：上传 PDF（必要时输入密码解密）→ 匹配银行解析模板 → 解析逐笔交易并识别账期 → 与已有账期做重叠检测 →
   逐笔指纹查重并标记疑似重复 → 进入预览页（可改字段、可勾选、可处置重复项）→ 确认入库 → 自动打标类型 →
   按摊分月数生成月度份额 → 生成导入批次记录。
4. 明细维护流程：明细页筛选定位 → 逐笔或批量修改字段 → 若改动金额/日期/摊分月数则触发份额重算与折算重算 → 统计随之更新。
5. 月度分析流程：进入月度页 → 选择口径（未摊分/摊分）与时间范围 → 查看总额与类型分布 → 下钻到明细 →
   发现打标或摊分错误时跳转明细页修正 → 回到月度页复核。

## 二、修订后功能清单

### A. 账户与认证域

- A-01 系统初始化：首次启动内置唯一管理员账户，用户名固定为 `admin`，初始密码随机生成。
- A-02 初始密码交付（管理员）：管理员完成首次改密前，初始密码打印到日志；改密后不再打印。
- A-03 登录：账号 + 密码登录并签发登录态。
- A-04 登录态时效：登录态最长 12 小时，到期自动过期。
- A-05 登出：主动注销登录态。
- A-06 全局登录态校验：除登录页与登录接口外，所有页面与接口强制校验登录态。
- A-07 失效处理：登录态过期或失效后统一跳回登录页。
- A-08 新增账户：仅管理员可创建账户，初始密码随机生成并在创建成功后仅展示一次，由管理员线下交付用户。
- A-09 账户列表：仅管理员可见，只含账户元信息，不含任何业务数据。
- A-10 启用/禁用账户：管理员可启停除自身以外的任意账户。
- A-11 账户不可删除：管理员账户与普通账户一律不支持删除，只能禁用。
- A-12 重置密码：管理员重置他人密码，系统随机生成初始密码并仅展示一次。
- A-13 强制首次改密：管理员首登、新账户首登、被重置密码后首登，均必须改密后方可使用系统。
- A-14 修改本人密码：用户自助改密。
- A-15 密码强度策略：长度 ≥ 10 位，且字母/数字/符号三类中至少包含两类。
- A-16 登录失败锁定：连续登录失败 5 次，禁止登录 10 分钟。
- A-17 密码安全存储：加盐哈希存储，全链路不可逆推明文。

### B. 权限与数据隔离域

- B-01 数据归属：所有业务数据（文件、审计、支出明细、类型、规则、偏好）均绑定归属用户。
- B-02 查询强制过滤：所有列表、详情、统计、导出一律按归属用户过滤。
- B-03 按 ID 访问的归属校验：明细编辑/删除、导入回滚、文件下载等均校验归属，防止越权。
- B-04 操作审计：记录登录、账户管理、文件上传、导入、明细增删改等敏感操作。
- B-05 敏感数据分级加密：文件内容与文件解密密码加密存储，参与筛选统计的业务字段保持明文（详见议题 3）。

### K. 文件管理域（新增）

- K-01 独立文件模块：所有用户上传的文件统一由文件模块存储与管理，业务模块只引用不自存。
- K-02 文件元信息：文件名、格式、大小、归属用户、上传时间、存储位置、内容校验值。
- K-03 解密凭据保管：上传时输入的文件密码（如 PDF 密码）随文件一并保存，供后续重新打开文件使用。
- K-04 文件与审计双向关联：由文件可查到它是在哪次操作中上传的，由某次操作可查到本次涉及了哪些文件。
- K-05 文件查看与下载：经归属校验后可下载或预览原始文件。
- K-06 文件只留存不删除：与账户策略一致，上传文件长期留存以保证可追溯。

### C. 数据导入域

- C-01 文件上传页：上传对账单文件并触发解析。
- C-02 解析器插件化：按「文件格式 + 来源机构」适配不同解析器，新增格式或银行不影响上层导入流程。
- C-03 本轮实现范围：仅实现 CSV 解析，Excel 与各银行 PDF 留待后续接入。
- C-04 非法文件反馈：格式不符、内容损坏、字段缺失、解密失败等情况给出明确错误提示。
- C-05 账单解析：从文件中解析出逐笔交易明细。
- C-06 解析预览页：解析结果先进入预览态，展示全部明细，默认全部勾选。
- C-07 预览页全字段可编辑：日期、金额、币种、对手方、备注、类型、摊分月数、汇率等全部字段提交前均可修改。
- C-08 预览页可增删行：支持在预览页手工新增或删除明细行（手工补录复用此页）。
- C-09 离开保护：预览页刷新或关闭前二次确认，明示未提交数据将全部丢失。
- C-10 疑似重复高亮：预览页高亮疑似重复明细，并同时展示与之冲突的已入库明细供人工比对。
- C-11 人工取舍后提交：用户取消勾选确认为重复的行，其余勾选项一并入库。
- C-12 汇率补录拦截：查不到汇率的明细，其汇率字段变为必填，未填写则不可提交。
- C-13 导入即审计：不设独立「导入批次」实体，一次导入即一条操作审计，入库明细关联该审计。
- C-14 按审计回滚：以一条操作审计为单位，整体撤销该次导入产生的全部明细。
- C-15 来源留痕：原始文件与解析原文经文件模块与审计模块留存，供追溯复核。
- C-16 卡片信息自动提取：能从文件解析出银行/卡号后四位/卡片币种时自动写入明细来源信息，不提供手工维护入口。

### D. 去重域

- D-01 交易指纹：由「归属用户 + 支出日期 + 支出金额 + 支出币种」四要素生成，不纳入卡片、对手方、原始摘要等非必有字段。
- D-02 双向查重：既检测本次上传文件内部明细之间的重复，也检测与已入库明细的重复。
- D-03 人工裁定：系统只负责标记「疑似重复」，是否真重复一律由人工在预览页判断，不做任何自动处置。

### E. 支出明细域

- E-01 明细字段：支出日期、支出金额、支出币种、交易对手方、交易备注、支出类型、摊分月数。
- E-02 系统字段：来源操作审计、来源文件、卡片信息、原始摘要、折算汇率、本位币金额、创建/更新时间。
- E-03 明细列表页：分页逐笔查看支出明细。
- E-04 多维筛选：日期区间、金额区间、币种、对手方（模糊）、备注（模糊）、支出类型（多选）、摊分月数（多选）、未分类、来源审计/文件。
- E-05 排序：按日期、金额等维度排序。
- E-06 逐笔编辑：E-01 的七个业务字段全部可修改。
- E-07 新增/删除明细：手工增删复用导入预览页，同样经过查重与编辑流程。
- E-08 筛选态累计统计：当前筛选条件下的笔数、按币种分组金额合计、本位币折算总额。
- E-09 明细导出：导出当前筛选结果。
- E-10 变更留痕：明细的修改与删除记入操作审计，不另建修改历史表。

### F. 支出类型（打标）域

- F-01 类型字典：单层分类，支持自定义增删改。
- F-02 默认类型：未识别的支出统一落入「未分类」。
- F-03 自动打标：按对手方/备注关键词自动赋予支出类型。
- F-04 未分类入口：在明细列表页以「未分类」筛选项作为待办入口，不另建页面。
- F-05 类型删除保护：被明细引用的类型不可直接删除，需迁移或停用。
- F-待定-1 规则优先级维护、F-待定-2 打标记忆学习：取决于自动打标的具体实现方式，本轮挂起不设计。

### G. 摊分域

- G-01 摊分月数：明细自带字段，全部明细都有值，默认 1（即不摊分）。
- G-02 起始月固定：以支出日期所属月为第 1 个摊分月，本轮不支持自定义起始月。
- G-03 派生式摊分：摊分份额在查询时由「金额 ÷ 摊分月数」实时派生，不落库、不额外产生数据行。
- G-04 尾差归末月：金额均分，除不尽的尾差固定计入最后一个摊分月。
- G-05 免重算：修改摊分月数只改明细自身字段，统计结果随之自动变化，无任何存量数据需要重算或作废。
- G-06 摊分预览：编辑摊分月数时即时展示覆盖月份区间与每月分摊金额。
- G-07 跨月影响提示：保存前提示「本次修改将影响 YYYY-MM ~ YYYY-MM 的月度统计」。
- G-08 摊分月数上限：设置系统级最大摊分月数并在录入时校验，既约束业务合理性，也使月度统计的回溯范围有界（见议题 2）。

### H. 多币种域

- H-01 币种字典：维护系统支持的币种。
- H-02 本位币设置：用户级配置，默认 USD，用户可自行修改。
- H-03 汇率自动获取：系统自动获取汇率，不提供手工汇率表维护页（获取方式属实现层，本轮不展开）。
- H-04 入账折算：按支出日期对应的汇率折算出本位币金额。
- H-05 汇率快照：折算所用汇率随明细一并留存，保证历史统计可复现。
- H-06 单笔汇率覆盖：允许对个别明细手工指定实际成交汇率。
- H-07 缺失汇率拦截：取不到汇率时在预览页将汇率置为必填，未填不可提交，不静默按 1:1 处理。
- H-08 展示口径切换：列表与统计支持「原币展示 / 本位币折算展示」切换。

### I. 月度统计域（第一轮全部保留）

- I-01 月度支出总额（未摊分口径）：按支出日期归月的每月支出金额。
- I-02 月度支出总额（摊分口径）：按摊分份额所属月归月的每月支出金额。
- I-03 口径切换：同一页面一键切换两种口径。
- I-04 月度类型分布：按支出类型看每月金额与占比，两种口径均支持。
- I-05 趋势与对比：多月趋势、环比/同比对比。
- I-06 下钻明细：从某月某类型下钻到构成它的支出明细，摊分口径下展示「份额 + 来源支出」。
- I-07 币种维度统计：按币种拆分的月度金额。
- I-08 未来月份视图：展示已发生支出摊到未来月份的份额。
- I-09 统计口径说明：页面明示当前口径与筛选语义，避免误读。

### J. 配置与运维域

- J-01 基础数据配置页：仅保留币种、本位币、支出类型三项维护；卡片自动解析、汇率自动获取，均不提供手工维护。
- J-02 操作日志查看：查看本人的关键操作记录，并可跳转到关联的文件与明细。
- J-03 数据导出/备份：整体导出本人数据。
- J-04 多语言：全部界面文案与提示走语言配置文件，新增语种只需增加配置、无需改动代码；本轮仅提供中文。

## 四、修订后核心业务流程

1. 开户与首登：`admin` 首次启动 → 从日志读取初始密码 → 登录 → 强制改密（此后日志不再打印）→ 新增账户 →
   一次性展示初始密码并线下交付 → 用户首登 → 强制改密。
2. 登录鉴权：登录签发 12 小时登录态 → 后续任意页面/接口先校验登录态、再按归属用户过滤 → 失效跳回登录页；连续 5 次失败锁定
   10 分钟。
3. 导入主流程（核心）：上传文件 → 文件入文件模块并绑定本次操作审计 → 按格式匹配解析器（本轮 CSV）→ 解析明细 →
   自动打标与自动取汇率折算 → 文件内与库内双向查重、标记疑似重复 →
   进入预览页（默认全选；高亮重复并并列展示冲突的已入库明细；可改全部字段、可增删行、缺汇率必填；刷新前二次确认）→ 提交入库 →
   明细关联本次审计。
4. 手工补录：直接进入与导入预览一致的页面，走同一套查重与编辑流程后提交。
5. 明细维护：明细页筛选定位 → 逐笔编辑 → 变更记入审计；改摊分月数即时生效，无需任何重算。
6. 导入回滚：从操作日志定位某次导入 → 整体撤销该审计产生的全部明细。
7. 月度分析：选择口径与月份 → 摊分口径按回溯窗口实时展开份额 → 查看总额与类型分布 → 下钻明细 → 发现错误跳明细页修正 →
   回来复核。

## 五、议题重答

### 议题 1：多币种统一（已确认）

采用第一轮方案 B（入账折算 + 汇率快照），并按对话2 修订两点：① 汇率不再手工维护汇率表，改为系统自动获取（H-03）；②

### 议题 2：查某月的摊分金额，来源可能追溯到很久以前，范围如何确定？

结论：回溯范围是可确定的，其上界由「最大摊分月数」唯一决定。

1. 贡献判定式：一笔支出对月份 M 有贡献 ⟺ `支出所属月 ≤ M ≤ 支出所属月 + 摊分月数 − 1`。
2. 等价变形：`支出所属月 ≥ M − (摊分月数 − 1)` 且 `支出所属月 ≤ M`。
3. 回溯窗口：因摊分月数逐笔不同，取全局上界 `N_max`（即 G-08 的系统最大摊分月数），候选集 = 支出月份落在
   `[M − (N_max − 1), M]` 的明细，再逐笔用判定式精确过滤。
4. 根因：「范围难以确定」的本质是缺少上界——只要不给摊分月数设上限，理论上就要回溯到系统第一天。设定 `N_max`
   后，范围立即收敛为一个有限、可预期的月份窗口，且与份额是否落库无关。
5. 份额金额：非末月 = `金额 ÷ 摊分月数` 按最小币值单位取整；末月 = `金额 − 前 N−1 月之和`（G-04 尾差归末月），保证 N
   个月份额之和恒等于原金额。
6. 口径不混用：摊分口径下「月份」筛选的是份额归属月，明细页与未摊分口径筛选的是支出日期；同一视图只用一种口径并在页面明示（I-03/I-09）。
7. 与 G-03 的一致性：全程不落库份额，改摊分月数天然一致、无重算；代价是月度统计需实时展开回溯窗口内的明细，性能问题属实现层，本轮不展开。

### 议题 3（新）：数据存储本身是否需要加密？

先厘清威胁模型：加密防的是「绕过应用直连数据库、或拿到库文件与备份」的人；防不住「应用层逻辑漏洞导致的越权」。你担心的越权若来自应用层，靠
B-02/B-03 的强制归属过滤解决；加密只对前一种场景有效。

全字段加密不可行：支出日期、金额、币种、类型、摊分月数一旦密文存储，范围筛选、分组求和、排序、月度统计（E-04/E-08/I-01~
I-09）全部失效；若为可查询而采用保序或可比较加密，安全性又基本等同明文。

推荐分级方案：

| 层级             | 对象                             | 做法                                                             |
|------------------|----------------------------------|------------------------------------------------------------------|
| 必须加密         | 文件解密密码（如 PDF 密码）      | 可逆加密（需还原以重开文件），不能哈希                           |
| 必须加密         | 上传的原始文件内容               | 静态加密存储                                                     |
| 建议加密（取舍） | 交易对手方、交易备注             | 纯展示、不参与聚合；但加密后 E-04 的模糊检索能力丧失             |
| 保持明文         | 日期、金额、币种、类型、摊分月数 | 筛选与统计的基础，加密即等于砍掉核心功能                         |
| 非加密兜底       | 全部数据                         | 库账号最小权限、库文件与备份磁盘级加密、密钥与数据分离、审计留痕 |

需你拍板的取舍：对手方/备注加密后无法做模糊筛选（E-04 明确要求对手方与备注模糊筛选），二者只能取其一。

## 二、全局设计前提（终版）

- 前提 1： **假定无人能直接读写数据库**，数据一律明文存储（含上传文件与文件密码），安全完全由应用层的登录态校验与归属校验保证。
- 前提 2： **只记支出**，不涉及收入、结余、资产负债。
- 前提 3： **纯个人数据隔离**，不做账本共享；管理员的特权仅限账户管理域，同样看不到他人业务数据。
- 前提 4： **操作审计是唯一的留痕机制**，不另建导入批次表、修改历史表。
- 前提 5： **摊分月数无上限**，摊分份额不落库、不产生额外明细行。

## 三、终版功能清单（11 域 57 项）

### A. 账户与认证（8 项）

- A-1 系统初始化：首次启动创建唯一管理员账户，用户名固定 `admin`，密码随机生成。
- A-2 初始密码生命周期：所有初始密码（admin 初始、新建账户、重置密码）均随机生成、仅交付一次、首登强制修改。
- A-3 初始密码交付方式：admin 的初始密码在其完成首次改密前打印到日志，改密后不再打印；其余场景在界面上一次性展示，由管理员线下交付。
- A-4 登录与登出：账号 + 密码登录并签发登录态，支持主动登出。
- A-5 登录态时效：最长 12 小时，到期自动过期。
- A-6 全局登录态校验：除登录页与登录接口外，所有页面与接口强制校验，失效统一跳回登录页。
- A-7 账户管理（仅管理员）：新增账户、启停除自身外的任意账户、重置他人密码、查看仅含元信息的账户列表；账户一律不可删除。
- A-8 密码策略：长度 ≥ 10 且字母/数字/符号至少含两类；加盐哈希存储；连续失败 5 次锁定 10 分钟；用户可自助改密。

### B. 权限与审计（4 项）

- B-1 数据归属：所有业务数据（文件、审计、明细、类型、偏好）均绑定归属用户。
- B-2 查询强制过滤：所有列表、详情、统计、导出一律按归属用户过滤。
- B-3 按 ID 访问的归属校验：明细编辑/删除、导入回滚、文件下载等逐一校验归属，防止越权。
- B-4 统一操作审计：登录、账户管理、文件上传、数据入库、明细增删改等均记为审计记录，是全系统唯一的留痕与回滚依据。

### C. 文件管理（4 项）

- C-1 独立文件模块：所有上传文件统一存储与管理，业务模块只引用不自存。
- C-2 文件元信息：文件名、格式、大小、归属用户、上传时间、存储位置、内容校验值、文件密码（明文保存，供后续重新打开）。
- C-3 文件与审计双向关联：由文件可查到它在哪次操作中上传，由某次操作可查到本次涉及哪些文件。
- C-4 文件访问与留存：经归属校验后可下载或预览原件；文件只留存不物理删除。

### D. 数据录入（8 项）

- D-1 解析器插件化：按「文件格式 + 来源机构」适配不同解析器，新增格式或银行不影响上层流程；本轮仅实现 CSV。
- D-2 文件上传与解析：上传文件（必要时输入密码解密）并解析出逐笔交易明细。
- D-3 非法输入反馈：格式不符、内容损坏、字段缺失、解密失败等给出明确错误提示。
- D-4 统一录入预览页：文件导入、手工新增、明细补录三个入口共用同一预览页，默认全部勾选，全字段可编辑，可增删行。
- D-5 未提交保护：预览页刷新、关闭或登录态失效前二次确认，明示未提交数据将全部丢失。
- D-6 疑似重复高亮：预览页高亮疑似重复行，并并列展示与之冲突的已入库明细供人工比对。
- D-7 提交入库：用户取消勾选确认重复的行后提交，一次提交生成一条操作审计，入库明细关联该审计。
- D-8 按审计整体回滚：以一条审计为单位，整体撤销该次入库产生的全部明细。

### E. 去重（2 项）

- E-1 交易指纹：由「归属用户 + 支出日期 + 支出金额 + 支出币种」四要素生成，不纳入卡片、对手方、摘要等非必有字段。
- E-2 双向查重与人工裁定：既查本次文件内部重复，也查与已入库明细的重复；系统只标记「疑似重复」，是否真重复一律人工判断，不做任何自动处置。

### F. 支出明细（7 项）

- F-1 业务字段：支出日期、支出金额、支出币种、交易对手方、交易备注、支出类型、摊分月数。
- F-2 系统字段：来源审计、来源文件、卡片信息、原始摘要、折算汇率、本位币金额、摊分起始月、摊分结束月、创建/更新时间。
- F-3 明细列表：分页逐笔查看，支持按日期、金额等排序。
- F-4 多维筛选：日期区间、金额区间、币种、对手方（模糊）、备注（模糊）、支出类型（多选，「未分类」即其中一项）、摊分月数（多选）、来源审计/文件。
- F-5 逐笔编辑：七个业务字段全部可改；改动金额/币种/日期/摊分月数时同步刷新折算金额与摊分起止月。
- F-6 筛选态累计统计：当前筛选条件下的笔数、按币种分组金额合计、本位币折算总额。
- F-7 明细导出：导出当前筛选结果。

### G. 支出类型（4 项）

- G-1 类型字典：用户级、单层分类、可自定义增删改；开户时初始化一套默认类型（交通/餐饮/住宿等）。
- G-2 默认类型：未识别的支出统一落入「未分类」。
- G-3 自动打标：按对手方/备注关键词自动赋予支出类型（判定方式待定，见待确认 T4）。
- G-4 删除保护：被明细引用的类型不可直接删除，需迁移或停用。

### H. 摊分（4 项）

- H-1 摊分月数：明细自带字段，全部明细都有值，默认 1（不摊分）， **不设上限**。
- H-2 摊分规则：以支出日期所属月为第 1 个摊分月；金额按币种的最小币值单位均分；除不尽的尾差固定计入末月；原币金额与本位币金额各自独立均分。
- H-3 派生不落库：摊分份额在查询时实时派生，不产生额外数据行；明细上冗余「摊分起始月 / 摊分结束月」两个派生字段，供统计定位（见议题
  2）。
- H-4 编辑预览与影响提示：编辑摊分月数时即时展示覆盖月份区间与每月分摊金额，并提示本次修改将影响的月份范围。

### I. 多币种（6 项）

- I-1 币种字典：系统级维护，用户只读引用。
- I-2 本位币：用户级配置，默认 USD，用户可自行修改。
- I-3 汇率自动获取：系统自动获取汇率，不提供手工汇率表维护（获取方式属实现层，本轮不展开）。
- I-4 入账折算与汇率快照：按支出日期对应汇率折算出本位币金额，所用汇率随明细留存，保证历史统计可复现。
- I-5 汇率兜底：允许对单笔明细手工指定实际成交汇率；自动获取失败时该行汇率变为必填，未填不可提交，不静默按 1:1 处理。
- I-6 展示口径切换：列表与统计支持「原币展示 / 本位币折算展示」切换。

### J. 月度统计（6 项）

- J-1 月度支出总额：支持「未摊分口径（按支出日期归月）」与「摊分口径（按份额所属月归月）」双口径，一键切换并在页面明示当前口径与筛选语义。
- J-2 月度类型分布：按支出类型看每月金额与占比，两种口径均支持。
- J-3 趋势与对比：多月趋势、环比与同比对比。
- J-4 币种维度统计：按币种拆分的月度金额。

## 四、议题终稿

### 议题 1：多币种统一（已确认，无变化）

入账折算 + 汇率快照：一笔支出同时保存原币金额、币种、折算汇率、本位币金额；汇率由系统自动获取，取不到则在预览页强制人工填写后方可入库；所有统计默认本位币口径，可切回原币。

补充澄清（第二轮的口径矛盾，见纠错 3）：摊分不是只在本位币上做——原币金额与本位币金额 **各自独立均分、各自尾差归末月**
。因汇率已快照固定，两套结果比例一致，不会互相矛盾，也保证原币口径下的月度摊分金额可直接展示。

### 议题 2：摊分月数无上限时，如何避免从记账第一天开始回溯？（终稿）

**先定位问题**：查询 M 月摊分总额，需要找出所有满足 `摊分起始月 ≤ M ≤ 摊分结束月`
的支出。第二轮靠「摊分月数上限」把回溯窗口夹成有限区间，你指出上限实际不存在——该方案作废。真正的解法不是限制业务，而是
**换一种数据组织方式，让查询成本与历史数据量脱钩**。

**优化一：把「回溯」变成「区间穿刺」（基础，必做）**

- 在明细上冗余两个派生字段：`摊分起始月`（= 支出日期所属月）与 `摊分结束月`（= 起始月 + 摊分月数 − 1）。
- 查询条件从「遍历历史逐笔判断」变为「`起始月 ≤ M` 且 `结束月 ≥ M`」的区间包含判断，可直接建索引。
- 效果：占绝大多数的 `摊分月数 = 1` 的历史支出，其结束月早已远离 M，被索引直接排除，根本不进入候选集——「从第一天回溯」的问题在
  **近期月份查询**上即刻消失。
- 代价：两个字段必须在支出日期或摊分月数变更时同步刷新，属常数级开销。
- 局限：查询 **久远的历史月份**时，「结束月 ≥ M」会把 M 之后发生的所有支出也纳入候选，候选集仍随数据量增长。这是优化二要解决的。

**优化二：月度差分聚合（彻底与数据量脱钩）**

- 核心变换：一笔支出对月份区间的「区间加」，等价于在区间端点上的 **常数条增量事件**：
    - 起始月：`+ 每月均分额`
    - 结束月：`+ 尾差`
    - 结束月的下一月：`− (每月均分额 + 尾差)`
- 把这些端点事件累加到一张「用户 × 月份 × 支出类型 × 币种 → 净增量」的聚合表； **任意月份的摊分总额 =
  该维度上从最早月份到该月的前缀和**。
- 验证（金额 100、摊分 3 个月、均分 33、尾差 1）：起始月 +33、第 3 月 +1、第 4 月 −34；前缀和依次为
  33、33、34、0，与「33/33/34」完全一致，且三个月之和恒等于 100。
- 三个关键性质：
    1. **写入代价与摊分月数 N 无关**：无论摊 1 个月还是 1000 个月，都只触碰 2~3 个聚合行，不会产生 N 条数据——与
       H-3「不落库、不产生额外数据行」不冲突（聚合表是统计加速层，不是明细的复制品）。
    2. **查询代价与明细总量无关**：只与月份数相关，记账 20 年也不过 240 个月，前缀和是极小规模的扫描；查多月趋势时一次滚动即可全部得出，比逐月查询更省。
    3. **改摊分月数仍是常数级**：冲销旧的端点事件、写入新的端点事件即可，不需要重算任何历史份额。
- 一致性要求：明细的新增、修改、删除、按审计回滚，都必须同步冲销与重写端点事件，否则聚合与明细会漂移；需要提供一致性校验（任一支出的各月份额之和恒等于其金额）。
- **适用边界（重要）**：聚合表只能覆盖固定维度（用户/月份/类型/币种）的统计；一旦筛选条件涉及对手方模糊、备注模糊等任意维度，聚合表无法回答，必须回落到优化一的明细路径实时展开。因此两者是互补关系，不是二选一。

**结论**：月度总额与类型分布类统计走优化二（成本与历史数据量无关）；明细下钻（J-5）与带任意筛选条件的统计走优化一的区间索引（单月、结果集小，可接受）。摊分月数无需任何上限，第二轮的
G-08 作废。

### 议题 3：数据存储加密（终稿）

**已按你的决定定案：数据库中的数据全部不加密，包括上传文件与文件密码。**
理由采纳你的论断——只加密文件而不加密明细，等于没加密；因此不做半吊子加密，改为假定「无人能直接读写数据库」，把安全边界收敛到应用层单点。

对应的功能取舍：

- 删除第二轮 B-05「敏感数据分级加密」，第二轮为此列出的「对手方/备注加密即丧失模糊检索」取舍问题随之关闭，F-4 的模糊筛选能力完整保留。
- 文件密码（K-2/C-2）明文保存，可直接用于重新打开文件。
- 应用层成为唯一防线，因此 B-2 查询强制过滤与 B-3 按 ID 归属校验的 **覆盖必须无死角**——任何一个漏做归属校验的接口都等于全量数据泄露，无任何第二层兜底。
- 附带风险（仅记录，不改变决定）：数据库凭据泄露、备份文件外流、运维直连查询这三条路径下数据完全裸露。若后续要补救，磁盘级/备份级加密是不侵入功能的最小代价选项。

## 六、终版核心业务流程（6 条）

1. **开户与首登**：`admin` 首启从日志读取初始密码 → 登录 → 强制改密（此后日志不再打印）→ 新增账户并一次性展示初始密码 →
   线下交付 → 用户首登 → 强制改密。
2. **登录鉴权**：登录签发 12 小时登录态 → 任意页面与接口先校验登录态、再按归属用户过滤 → 失效跳回登录页；连续 5 次失败锁定
   10 分钟。
3. **数据录入（核心）**：上传文件 → 文件入库并绑定本次审计 → 匹配解析器（本轮 CSV）→ 解析明细 → 自动打标 + 自动取汇率折算 →
   文件内与库内双向查重并高亮 → 统一预览页人工编辑/增删行/取消勾选/补录汇率 → 提交入库 → 计算摊分起止月与摊分端点增量 →
   关联本次审计。手工新增走同一条流程，仅入口不同。
4. **明细维护**：筛选定位 → 逐笔编辑 → 同步刷新折算金额、摊分起止月与摊分增量 → 变更记入审计。
5. **回滚**：从操作日志定位某次入库 → 整体撤销该审计产生的全部明细及其摊分增量。
6. **月度分析**：选择口径与月份 → 未摊分口径按支出日期归月直接统计，摊分口径读月度聚合的前缀和 → 查看总额、类型分布与趋势 →
   下钻到明细（走区间索引）→ 发现错误跳明细页修正 → 回来复核。
