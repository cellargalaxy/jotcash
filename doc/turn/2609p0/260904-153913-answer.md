## 一、承载边界：这个包只装什么

`base/config` 的承载在设计文档里出现三次，三处口径一致，取其交集即为本包的全部内容：

| 出处 | 原文要点 |
| ---- | -------- |
| §六 L0 表 `base/config` 行 | **仅部署相关参数**：监听地址、SQLite 文件路径、令牌密钥、汇率源端点与密钥、日志级别；**业务阈值不进配置**；**仅被 `app` / `cmd` import** |
| §十 约定 8 | **配置只在 L7 读**；`base/config` 只装部署参数；**L0~L6 所需部署参数由 `app` 注入**；业务阈值一律写死在对应包（12h / 5 次 / 10 分钟 / Argon2 参数 / 汇率 8 位 / 本位币 2 位） |
| §十 约定 4 + 目录树 | **三 embed 一运行时**：仅 `configs/` 运行时加载，是「唯一非 embed 的外部资源」 |

由此**定死 6 个字段**（5 类参数，汇率源端点与密钥各占一个字段），一个不多一个不少：

| 字段 | yaml 键 | 类型 | 依据 |
| ---- | ------- | ---- | ---- |
| 监听地址 | `listen_address` | string | L0 表第 1 项 |
| SQLite 文件路径 | `sqlite_path` | string | L0 表第 2 项；`store/sqlite` 的文件路径「由 `app` 注入」（§六 L4 表） |
| 令牌密钥 | `token_secret` | string | L0 表第 3 项；`token` 边界包「**仅密钥由 `app` 注入**」（§六 L3 表） |
| 汇率源端点 | `fx_rate_endpoint` | string | L0 表第 4 项；`fxrate/<源>`「端点与密钥由 `app` 注入」（§六 L4 表） |
| 汇率源密钥 | `fx_rate_secret` | string | 同上 |
| 日志级别 | `log_level` | string | L0 表第 5 项 |

**明确排除**（有据可查，不是漏项）：

- 令牌 12h（§二 A-5 / `token` 承载）、连续失败 5 次与锁定 10 分钟（§二 A-8 / `service/auth` 承载）、Argon2 内存/迭代/并行度（T36 / `base/pwdhash` 承载）、汇率 8 位（T39）、本位币存储 2 位（T35）——约定 8 明写「业务阈值一律写死在对应包」，**安全参数不应可被部署方调低**（T36②）。
- 服务名：`base/log` 的承载范围（该包按 `260904-153910-prompt.md` 走 `go_common/util` 的 `util.Init(DefaultServerName)`），不属本包 5 类参数。
- 日志切割参数（大小 / 个数 / 天数）：L0 表只列「日志级别」一项，不扩。
- 本位币、界面语言：§二 I-2 / K-1 是**用户级配置**，落 `User` 实体，不是部署参数。
- 语言目录、迁移脚本、前端产物路径：T37 / T33 / T34 已定为 embed（约定 4），没有路径可配。

## 二、方案取舍（6 项，逐项给依据与被否方案）

### 取舍 1 · 配置库选型：复用 `go_common/util`，不引入 viper

prompt 要求「优先采用 github 上成熟稳定 star 多的代码库，避免自己造轮子」。候选与判定：

| 候选 | star | 判定 |
| ---- | ---- | ---- |
| `spf13/viper` | 30.4k | **不采用**。它解决的是「多来源（文件/环境/远端 KV/命令行）合并 + 热更新 + 大小写不敏感键」，本包是 **6 个扁平字符串字段、一次性读取**；引入它会为 6 个字段新增一整棵传递依赖树，且与「配置只在 L7 读、由 `app` 注入」的单向数据流相斥 |
| `knadh/koanf` | 4.2k | 同上，轻一些但仍是多来源合并框架，本包无此需求 |
| `caarlos0/env` / `kelseyhightower/envconfig` | 6.3k / 5.5k | **不采用**：纯环境变量方案，与目录树「`configs/` 运行时加载」的既定形态冲突 |
| **`cellargalaxy/go_common` 的 `util`** | — | **采用**。它已经提供本包需要的全部能力：`YamlString2Struct`（底层 `gopkg.in/yaml.v2`）、`ReadFile2String`、`GetFileInfo`、`GetEnvString`、`JsonStruct2String`（脱敏日志） |

采用 `go_common/util` 的三条硬依据，不是偏好：

1. **它已经是本项目的既定基座**。`.gitignore` 里有一条本轮之前就存在的注释：「运行期与测试期产生的日志（**go_common/util** 按相对工作目录落 `log/<服务名>/log.log`）」——项目已显式接受该库的日志落盘行为，包括测试期。
2. **兄弟包已被 prompt 指定用它**：`base/log` 用 `util/log.go` + `util.Init`（`260904-153910-prompt.md`）、`base/idgen` 用 `util/gen.go` 的 `GenId()`（`260904-153915-prompt.md`）。它是**零边际成本**依赖；换成 viper 反而是**净新增**一棵依赖树。
3. **不违反分层**：L0 表头是「仅依赖标准库与**第三方库**」，`go_common` 即第三方库；本包依赖列 `—`（层内零依赖）指的是**仓库内 L0 包之间**不互相依赖，本包确实不 import 任何 `internal/` 包。

### 取舍 2 · 一次性读取，**不做热更新**

`go_common/util` 里现成有 `NewConfigService`（守护协程每分钟重载 + 缺失时写出默认配置 + `ParseConfig` 回调），`survive_monitor` / `msg_gateway` 都用了同类形态。本包**不用**它：

- 约定 8 定的数据流是「`app` 读一次 → 注入 L0~L6」。热更新会让**已注入的值与文件不一致**：`token` 拿到的是旧密钥、`store/sqlite` 已按旧路径开了写连接单例（T33②），配置文件改了也没有回路能把新值送进去，只会制造「改了没生效」的假象。
- 6 个参数本身都不可热改：监听地址、SQLite 文件路径要重启才能生效；令牌密钥热改等于当场作废全部登录态，而 §五 3「登录令牌」明确规定令牌失效只有 `User.登录态基线时间` 一条路径。

因此 `Load` 只做「读 → 反序列化 → 填默认 → 校验」，无守护协程、无副作用。

### 取舍 3 · 返回值，**不做包级全局单例**

同作者其余仓库一律 `var Config = model.Config{}` + `init()` 里加载（`survive_monitor/config/config.go`、`msg_gateway/config/config.go`）。本包**不照搬**，改为 `Load(ctx, path) (Config, error)`：

- **依据**：约定 8「配置只在 L7 读」+ 约定 6「L5 及以下一律通过显式入参接收」。全局单例天然可被任何包 `import` 后直接读，与 R3 登记的「`base/config` 是普通包，任何包 import 得到」这条残留同向，只会把残留放大；返回值形态让「谁拿到了配置」在函数签名上可见。
- **依据**：`init()` 里 `panic` 的加载方式让 `cmd` 无法决定失败时的退出语义，也让单测无法构造多组配置。
- **登记为与既有仓库风格的显式偏离**（不是默默取一方）：本仓库有分层约定，其余仓库没有；冲突时以本仓库设计文档为准。

### 取舍 4 · 配置缺失 → **报错，不落盘模板**

`util.ConfigService.loadConfig` 的做法是「文件不存在就写出默认配置」。本包不这么做：

- 令牌密钥必填（见取舍 5），写出模板后**紧接着仍会校验失败**，用户得到「文件被创建了 + 启动仍失败」两条互相干扰的信号。
- `Load` 保持**纯读语义**：无写盘、无建目录，可在只读环境与单测中直接跑。
- 一次性复制动作由 `configs/jotcash.example.yaml` 承担（目录树 `configs/ # 配置样例` 的字面落地），错误信息里直接指向它。

### 取舍 5 · 校验强度：必填只有令牌密钥，汇率源两项**不校验**

| 字段 | 处理 | 依据 |
| ---- | ---- | ---- |
| `token_secret` | **必填**，空（含纯空白）即返回错误 | 同作者 `msg_gateway/config/config.go` 的 `checkAndResetConfig` 现成先例：`if config.Secret == "" { return error }`。且 §二 A-5「签发起 12 小时绝对过期」要求令牌可被验签，空密钥等于无签名 |
| `listen_address` | 空则取默认；非空做一次 `net.SplitHostPort` 形状校验 | 把 `"127.0.0.1"`（漏端口）这类笔误挡在启动阶段，而不是等 `app` 真正监听时报在 `net` 包里 |
| `sqlite_path` | 空则取默认；**不建目录、不校验可写** | 建库与建目录属 `store/sqlite`（阶段 5），本包只搬参数 |
| `log_level` | 空则取默认；非空走 `logrus.ParseLevel` 校验 | 手写白名单会与 logrus 的取值域漂移；logrus 已是 `go_common/util` 的传递依赖，直接用其权威解析器 |
| `fx_rate_endpoint` / `fx_rate_secret` | **只 TrimSpace，不校验** | §六 L4 表 `fxrate/<源>` 的**包名与选型都未定**（§四「`fxrate/<源>` 的具体包名随汇率源选定后确定」）。是否需要密钥、端点形状由该实现自行校验；此处若写死口径就是脑补 |

### 取舍 6 · 错误用 `pkg/errors`，**不用 `base/errs`**

`base/errs` 是同层包，L0 层内零依赖直接禁止 `base/config → base/errs`（§三 问题 2 刚把 L0 的层内边清成 `—`）。且 `base/errs` 的五档（用户输入错误 / 唯一冲突 / 归属越权 / 未登录 / 系统错误）**携带面向用户的文案键**，供 `middleware` 经 `i18n` 渲染——而配置加载发生在启动阶段、没有请求也没有用户，套用五档是错配。故用 `github.com/pkg/errors`（`go_common/util` 全库统一用它）。

同理，日志**不经 `base/log`**（层内零依赖），直接用 `logrus`：`go_common/util` 的 `init()` 已在包加载时完成 logrus 的全局配置（`InitDefaultLog`），全仓库的写法本就是 `logrus.WithContext(ctx).WithFields(...)`，直接用即与项目风格一致。

## 三、模块职责 / 输入输出 / 关键逻辑

**包路径**：`internal/base/config`（目录树原位，未新增目录层级）

| 导出项 | 签名 | 职责 |
| ------ | ---- | ---- |
| `Config` | struct（6 字段） | 部署参数全集；`yaml` 标签供反序列化，`json` 标签供日志输出，两套标签**取同名**，保证配置文件键名与日志键名一致 |
| `Config.String()` | `() string` | 走 `util.JsonStruct2String`，**两个密钥被掩码为 `******`**，可直接进日志字段 |
| `Load` | `(ctx, path string) (Config, error)` | 唯一入口：路径回落 → 存在性检查 → 读文本 → 空文件拦截 → YAML 反序列化 → 填默认 → 校验 |
| `GetConfigPath` | `(path string) string` | 路径优先级：**显式入参 → 环境变量 `jotcash_config` → `DefaultConfigPath`** |
| `DefaultConfigPath` 等常量 | — | 默认路径、样例路径、环境变量名、默认监听地址 / 库路径 / 日志级别 |

> **实施中的一处修正**：方案初稿写的是「密钥用 `json:"-"` 排除」，落地时改为**掩码**（值接收者复制后就地改写为 `******`）。理由是 `json:"-"` 会让密钥字段在日志里**整个消失**，从而无法区分「密钥填了」与「密钥没填」——而这恰恰是启动失败时最需要的排障信号（最常见的失败原因就是密钥漏填）。掩码取定长常量、不随原值长度变化（长度本身也是信息）；未配置时保持空串，两种状态在日志里可区分。已由单测 `TestConfigString` 锁死：明文不得出现、非敏感字段必须保留、未配置的密钥不得被掩码。

**关键逻辑与异常分支**（每条都对应一个单测）：

1. 路径回落：入参 TrimSpace 后非空即用；否则读环境变量 `jotcash_config`（键名沿用 `go_common/util` 的 `server_name` 风格：小写下划线 + 服务名前缀）；再回落 `configs/jotcash.yaml`。
2. 存在性：`util.GetFileInfo` 返回 nil（不存在 / 是目录）→ 报错并指向样例文件。**必须先判存在**：`util.OpenReadFile` 在文件不存在时会**创建空文件**，绕过判存直接读会污染磁盘。
3. 空文件：`util.ReadFile2String` 对空文件只返回空串不报错，若不显式拦下，最终会以「令牌密钥为空」的形式报错，误导排查方向 → 单独拦成「配置文件为空」。
4. YAML 非法：`util.YamlString2Struct` 已把 yaml.v2 的 panic 兜成 error（该库对非指针目标会 panic），直接透传。
5. 填默认 + 校验：见取舍 5 的表格；**任一项不合法立即返回错误**，不静默降级——部署参数错了应当启动失败，而不是带着半套配置跑起来。
6. 成功日志：`logrus...WithFields{"path", "config"}.Info("加载配置")`，`config` 经 `String()` 脱敏。

## 四、副作用评估

| 维度 | 评估 |
| ---- | ---- |
| 现有链路 | **无**。本包不改任何既有代码；实施期间落地的兄弟包 `base/errs`、`base/idgen`、`base/pwdhash` 与本包互不 import，无交叉影响（唯一共享物是 `go.mod`，见下行） |
| 分层 | 依赖列仍为 `—`（不 import 任何 `internal/` 包），L0 层内零依赖不破；本包只被 `app` / `cmd` import 的约定 8 由后续阶段遵守，本轮无违反者 |
| 依赖树 | `go_common` 及其传递依赖（logrus / yaml.v2 / pkg-errors / gin / gorm 等）此前已由兄弟包 `base/idgen`、`base/pwdhash` 引入 `go.mod`，**非本包净增**；本包唯一的增量是把 `gopkg.in/yaml.v2` 从间接提升为直接依赖（供消费者验证测试独立解析样例文件），未引入任何新库 |
| 运行期副作用 | `go_common/util` 的包级 `init()` 会做两件事：① `InitDefaultLog()` 按相对工作目录建 `log/<服务名>/log.log`；② `initHttp()` 起一个每小时拉取公网 IP 的守护协程。二者由该库的形态决定、任何 import 它的包都会触发，**`.gitignore` 里既有的 `/log/`、`*.log` 两条规则已说明项目预先接受**（注释明确写了「运行期与测试期」） |
| 性能 | 启动时一次文件读 + 一次 YAML 反序列化，无热更新协程 |
| 兼容性 | 首次引入配置文件契约；`configs/jotcash.yaml` 已加入 `.gitignore`，避免把真实令牌密钥提交进公开仓库 |

### 风格对齐（与实施期间落地的兄弟包逐项比对）

实施开始后 `base/errs`、`base/idgen`、`base/pwdhash` 已由并行的兄弟 prompt 落地，本包按它们的既有风格对齐，未自立一套：

| 维度 | 兄弟包既有做法 | 本包 |
| ---- | -------------- | ---- |
| 包注释 | 首行 `// Package xxx ...` + 引用设计文档原文 + 列硬约束 + 列调用方 | 同（4 条硬约束 + 2 个调用方） |
