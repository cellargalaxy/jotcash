## 一、阻塞性问题

**无。** 6 个配置项的键名、默认值、必填性、取值域、路径确定顺序全部在已入库的 `configs/jotcash.example.yaml` 中写定，`base/config` 依赖列为 `—`（不依赖任何仓内包），无待确认输入，本轮直接编码。

下列 3 项**曾疑似待确认，实为已定**，登记以免后续返工：

| 疑点 | 结论 | 依据 |
| ---- | ---- | ---- |
| 汇率源未选定，`fx_rate_endpoint` / `fx_rate_secret` 形态未知，是否阻塞？ | **不阻塞，且必须不做形态校验**。二者按不透明字符串处理、允许为空 | 样例注释：「汇率源尚未选定，两项均可留空」「是否需要密钥、端点的具体形态由汇率源决定」 |
| 日志级别是否需要落成 `logrus.Level` 类型？ | 落成 `string`（YAML 契约不变），另出 `GetLogrusLevel()` 便捷方法 | 样例枚举的 7 个值与 logrus 7 档完全一致；`base/log` 已定为 logrus 实现（兄弟 prompt） |
| `sqlite_path` 的目录是否由本包创建？ | **不由本包创建、也不 stat 校验** | 样例注释：「目录不存在时由程序在**初始化数据库阶段**创建」——职责在 `store/sqlite`，本包只校验取值形态 |

## 二、范围边界（做什么 / 不做什么）

**做**：`internal/base/config` 一个包——配置文件路径解析（三级优先级）、YAML 读取与解析、默认值回填、启动期校验、日志脱敏输出。

**不做**（均有明确依据，不是遗漏）：

| 不做 | 依据 |
| ---- | ---- |
| 不装业务阈值（令牌 12h、失败 5 次、锁定 10 分钟、Argon2 参数、汇率 8 位、本位币 2 位、密码长度与字符类别） | 分层表 `base/config` 行「业务阈值不进配置」+ 约定 8「业务阈值一律写死在对应包」+ 样例注释「它们是规则而非部署差异，尤其是安全参数不应存在可被调低的入口」 |
| 不装本位币、界面语言 | 样例注释「是**用户级**设置，在系统内按账户配置」；终版 I-2 / K-4 |
| 不定义 `flag`、不在 `init()` 里读配置 | 约定 8「仅被 `app` / `cmd` import」——CLI 参数的定义权在 `cmd`，本包只接收已解析出的字符串；`init()` 里注册全局 flag 会污染 `go test` 的 flag 集 |
| 不做热加载 / 不起守护协程 | 承载只有「仅部署相关参数」；5 类参数（监听地址、DB 路径、令牌密钥、汇率源、日志级别）改动都必须重启进程才生效，热加载是无效复杂度。go_common 的 `util.ConfigService`（分钟级轮询 + 落盘默认配置）因此**不采用** |
| 配置文件缺失时不自动落盘默认文件 | 样例的用法是「复制本文件为 `jotcash.yaml`」；且自动生成的文件 `token_secret` 必为空，随即被必填校验拒绝，等于用一次静默写盘换一个更晚更绕的报错。故缺失即报错，并在错误里给出 `cp` 命令与环境变量名 |
| 不依赖 `base/errs` / `base/log` | L0 表头「**层内零依赖**」。校验失败一律返回 `error`，由 `cmd` 打印后退出；此时 `base/log` 尚未按级别初始化，本包也无处可记 |

## 三、选型：为什么不用 viper / koanf，而用 `gopkg.in/yaml.v2` + 标准库

prompt 要求「优先采用 github 上成熟/稳定/star 多的代码库（如果有），避免自己造轮子」。按此逐个评估：

| 候选 | 结论 | 理由 |
| ---- | ---- | ---- |
| `spf13/viper`（约 30k star）["https://github.com/amanbolat/awesome-go-with-stars?search=1"] | **不采用** | ① 其核心卖点（多格式、远程配置中心、热监听、env/flag 自动绑定）本包全部不需要，见 §二「不做」；② `viper.Unmarshal` 走 mapstructure，**默认静默忽略未知键**——`sqlitepath` 这类拼错会静默退回默认值，与本包「启动期必须响亮失败」的取向相反；③ 为一个 6 字段结构体引入十余个间接依赖，与 L0「纯技术层、依赖尽量少」相悖 |
| `knadh/koanf`（viper 的轻量替代）["https://github.com/knadh/koanf/"] | **不采用** | 依赖比 viper 少，但同样是「多来源多格式」框架，本包只有单文件单格式，收益为零；且会引入项目里第二套 YAML 实现 |
| `gopkg.in/yaml.v2` | **采用** | ① YAML 解析这件真正该复用的事交给它，不自己写解析器；② **它已在依赖树中**——`base/log` 必用的 `go_common` 在 go.mod 里直接 require `gopkg.in/yaml.v2 v2.4.0`，用它零新增模块，也避免 v2/v3 两套 YAML 同时进二进制；③ 提供 `UnmarshalStrict`，未知键直接报错，正是本包需要的严格语义 |
| `sirupsen/logrus` | **采用（仅用于级别校验与转换）** | 日志级别的合法值必须与真正消费它的 `base/log` 完全一致。用 `logrus.ParseLevel` 校验，`base/config` 认可的与 `base/log` 能接受的**天然是同一个集合**；自己维护白名单则存在两套口径漂移的风险。logrus 同样已由 `go_common` 引入 |
| 路径解析（CLI > env > 默认） | **标准库 `os.Getenv` + 字符串判断** | 三级优先级共约 10 行，引框架不划算；这不是「造轮子」，是不为 10 行逻辑引入一个配置框架 |

> 净新增直接依赖 2 个（`gopkg.in/yaml.v2`、`github.com/sirupsen/logrus`），且二者都是后续 `base/log` 必然要引入的，本包未额外扩大依赖面。

## 四、模块设计

### 4.1 交付物

- `internal/base/config/config.go`——类型、常量、路径解析、加载、校验、脱敏
- `internal/base/config/config_test.go`——单测（含对已入库样例文件的契约核验）

### 4.2 输入输出

| 导出项 | 签名 | 职责 |
| ------ | ---- | ---- |
| `Config` | struct，6 个导出字段 + yaml tag | 部署参数的唯一载体 |
| `ResolvePath` | `func(cliPath string) string` | 三级优先级定路径：命令行参数 > 环境变量 `jotcash_config` > `configs/jotcash.yaml`。纯函数，只读环境变量，不碰文件系统 |
| `Load` | `func(path string) (*Config, error)` | 读文件 → 严格解析 → 回填默认值 → 校验 → 返回。任一步失败返回带路径与键名的中文错误 |
| `(Config) String` | `func() string` | **脱敏**输出，令牌密钥与汇率源密钥只显示「已设置(N字符)/未设置」 |
| `(Config) GetLogrusLevel` | `func() logrus.Level` | 已校验的级别串转 `logrus.Level`，供 `app` 传给 `base/log` |

调用方（`cmd/jotcash`，阶段 11 落地）预期两行：

```go
path := config.ResolvePath(cliConfigPath) // cliConfigPath 由 cmd 自己的 flag 提供
conf, err := config.Load(path)
```

`ResolvePath` 与 `Load` 分开而不合并成一个 `LoadByCli`，是为了让调用方拿到**实际生效的路径**用于日志与报错，不必从错误文本里反解。

### 4.3 关键逻辑与取舍

1. **严格解析（`yaml.UnmarshalStrict`）**：未知键报错。代价是将来删键时旧配置文件会启动失败；收益是键名拼错不再静默退回默认值。个人自建系统下「响亮失败」优于「静默跑偏」，故取严格。
2. **默认值只回填「空值」**：`listen_address` → `:4747`、`sqlite_path` → `data/jotcash.db`、`log_level` → `info`（与样例注释逐字一致）。
3. **空白字符处理分两类**（这是唯一需要区别对待的地方）：
   - 结构性取值（`listen_address` / `sqlite_path` / `log_level` / `fx_rate_endpoint`）：**去首尾空白后存储**——这些位置的空白从无语义，`" :4747 "` 只会让 `net.Listen` 报一个难懂的错。
   - 两个密钥（`token_secret` / `fx_rate_secret`）：**判空时去空白、存储时原样保留**。密钥是不透明字节串，静默裁剪会让签名结果取决于用户看不见的字符；但 `token_secret: "   "` 这种显然是没填，必须按未填拒绝。
4. **`listen_address` 必须带端口**：用 `net.SplitHostPort` 校验并要求端口段非空，正好覆盖样例注释的三种写法（`:4747`、`127.0.0.1:4747`、`[::1]:4747`），而 `4747`（漏冒号）被拒。不额外限制端口必须为数字——`net.Listen` 也接受服务名。
5. **`token_secret` 必填**：为空即返回错误，错误文本直接给出样例里的生成命令 `openssl rand -base64 48`，对应样例注释「留空会导致启动失败」。
6. **汇率源两项零校验**：形态由未来选定的汇率源决定，此处任何校验都是凭空猜测。
7. **`String()` 脱敏**：`fmt` 对 `%v` / `%s` 会走 `Stringer`，因此 `logrus.Fields{"conf": conf}` 与 `%+v` 都自动脱敏；值接收器使 `Config` 与 `*Config` 同时受保护。**已知边界**：`yaml.Marshal(conf)` 不走 `Stringer`，仍会输出明文——该路径是「写出配置文件」的正当用途，本包不提供、也不建议用于日志。
8. **错误处理**：全部返回 `error`，中文、含路径与键名、可直接呈现给部署者；文件不存在单独成一档，提示 `cp configs/jotcash.example.yaml configs/jotcash.yaml` 与环境变量 `jotcash_config`。不 panic——启动失败的呈现方式属 `cmd` 的决定。

### 4.4 对现有链路 / 性能 / 兼容性的副作用

- **链路**：本包立项时仓库无任何 Go 实现（仅 `go.mod` / `README.md` / `configs/` / `doc/`），且本包依赖列为 `—`、不 import 仓内任何包，无回归面。对下游的唯一约束是约定 8（只被 `app` / `cmd` import），Go 可见性无法强制，靠评审——与设计文档 §四 R3 登记的残留一致，本轮未新增新的口头约定。
- **性能**：进程启动时读一次几百字节的文件，无常驻协程、无锁、无定时器。
- **兼容性**：字段名、默认值、路径顺序与已入库的 `configs/jotcash.example.yaml` 逐字对齐，样例文件**零改动**；单测直接加载该文件反向验证契约，样例与代码日后不会各走各路。

### 5.2 验证结果

| 手段 | 结果 |
| ---- | ---- |
| `go build ./...` | 通过 |

| `gofmt -l internal/base/config/` | 无输出（本包格式合规） |

单测覆盖的核心口径：

1. **样例文件契约核验**（最关键一条，走的是与编码不同的路径）：直接 `UnmarshalStrict` 已入库的 `configs/jotcash.example.yaml`，逐字段断言其取值等于文档默认值；再对该文件调 `Load`，断言**恰好**只因 `token_secret` 为空而失败。任何一个 yaml tag 拼错、任何一个默认值与注释不符，这条都会红。
2. **路径三级优先级**：CLI 优先于 env、env 优先于默认、三者皆空取默认、CLI 与 env 的首尾空白被忽略。
3. **默认值回填**：只给 `token_secret` 的最小配置 → 另外三项取默认，汇率源两项保持空。
4. **校验拒绝面**：`token_secret` 缺失 / 全空白、`log_level` 非法、`listen_address` 漏端口、`sqlite_path` 显式空串、未知键、YAML 语法错、文件不存在——逐条断言报错且错误文本含可定位的键名或路径。
5. **正常化**：`LOG_LEVEL` 大写与含空白的输入被规范化为小写；`warning` 被接受（logrus 别名）并映射到 `logrus.WarnLevel`。
6. **脱敏**：断言输出中**不包含**密钥原文、且包含「已设置(48字符)」；空密钥与全空白密钥显示「未设置」；`String()`、`%v`（值）、`%+v`（指针）、`%s`（值）四条打印路径逐一验证。
7. **密钥不被裁剪**：`token_secret` 含首尾空白时，`Load` 后的值与文件原值逐字节相等；同时断言结构性字段（监听地址/DB 路径/端点/级别）**已**去空白——两类相反口径同一个用例内对照。
8. **`sqlite_path` 空白的确定行为**：单独成例断言「空白 = 未配置 → 回填默认」，而非报错，避免这条边界日后被当成 bug 改掉。

### 5.3 变异校验（确认单测不是走过场）

逐个向源码植入缺陷、跑测、再逐字节还原（`diff` 已确认源文件与变异前一致）：

| 植入的缺陷 | 是否被测出 | 报出的用例 |
| ---------- | ---------- | ---------- |
| yaml tag 由 `sqlite_path` 改成 `sqlitepath`（模拟契约漂移） | **是** | `TestExampleYamlContract` 直接指出「样例与结构体已脱节：line 23: field sqlite_path not found」 |
| 去掉 `token_secret` 必填校验（`if …== ""` 改 `if false`） | **是** | 8 处断言同时失败 |
| `String()` 不脱敏（`maskSecret` 直接返回原文） | **是** | `TestStringMaskSecret` 报「泄露了 token_secret / fx_rate_secret」，四条打印路径全部报出 |

### 5.4 端到端冒烟（临时 main，验证完毕后已删除）

不走单测，而是按 `cmd/jotcash` 未来的真实两行调用（`ResolvePath` → `Load` → 交给 logrus）跑通四个场景：

| 场景 | 实际输出 |
| ---- | -------- |
| A 默认路径无配置文件 | 报「配置文件不存在: configs/jotcash.yaml。请复制样例后填写: cp configs/jotcash.example.yaml configs/jotcash.yaml；或用环境变量 jotcash_config 指定其他路径」——报错自带下一步动作 |
| B 环境变量指向样例文件 | 生效路径正确切换到样例；报「token_secret 为空 …… 请生成一个随机值填入: openssl rand -base64 48」 |
| C 填入 `openssl rand -base64 48` 真值 | 加载成功；**logrus 字段输出为** `token_secret:已设置(64字符) fx_rate_secret:已设置(14字符)`，密钥原文未出现在日志中；级别 `debug` 正确传导到 `logrus.SetLevel` |
| D 键名拼错 `sqlitepath` | 响亮失败：「解析配置文件异常 …… line 2: field sqlitepath not found」——验证了选用 `UnmarshalStrict` 而非 viper 静默忽略的收益 |

> 另有一处意外收获：把冒烟程序放在仓库外的独立 module 时，Go 直接以 `use of internal package … not allowed` 拒绝编译——约定 1「全部业务包在 `internal/` 下，不对外提供库」是**编译期强制**的，不属于 §四 R1/R3 那类只能靠评审的口头约定。

## 六、结论

`base/config` 已按分层表承载落地：**只装 5 类部署参数、层内零依赖、严格校验、启动期响亮失败、密钥日志脱敏**，字段契约与已入库样例文件双向对齐并有单测锁定。阶段 1 的 7 个 L0 包中，本包无任何遗留待确认项，可作为 `app` / `cmd`（阶段 11）的输入直接使用。
