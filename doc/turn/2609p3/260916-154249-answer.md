## 二、需求分析与方案设计

### 2.1 样例 PDF 逆向与结构特征

通过对样例 PDF 二进制结构与内容流进行逆向解析，确认以下核心事实：
1. **生成来源与编码体系**：
   - Producer 为 `openhtmltopdf.com`；
   - 字体采用嵌入式子集 `APBYBG+SimSun` 与 `AZFDZC+SimSun`，字符通过 `Identity-H` CMap 映射为 Unicode；
   - 页面尺寸为标准 A4（`595.275 x 841.875 pt`），共 2 页。
2. **凭据与账户基本信息**（位于第 1 页顶部）：
   - 主标题：`招商银行交易流水` / `Transaction Statement of China Merchants Bank`；
   - 账号信息：格式为 `账号：****<末四位>`，动态提取末四位卡号；
   - 开户行信息在第 1 页顶部呈现，户名已脱敏。
3. **表格布局与坐标特征**：
   - 表格具有 6 列：
     - `记账日期` (Date)：水平坐标 X 位于 `[30, 80)`；
     - `货币` (Currency)：水平坐标 X 位于 `[80, 140)`；
     - `交易金额` (Transaction Amount)：水平坐标 X 位于 `[140, 210)`；
     - `联机余额` (Balance)：水平坐标 X 位于 `[210, 280)`；
     - `交易摘要` (Transaction Type)：水平坐标 X 位于 `[280, 400)`；
     - `对手信息` (Counter Party)：水平坐标 X 位于 `[400, 580)`；
   - **单元格换行现象**：表格中长文本（如业务付款说明、长商户名、利息计提全称）在 PDF 流中以多段 `BT ... ET` 指令分行输出。必须基于底层 TextChunk 的水平 X 坐标进行区间投递，多行文本在所属单元格内按顺序拼接。

### 2.2 方案取舍与技术选型

1. **三方库选型**：
   - 采用 `github.com/ledongthuc/pdf`，其轻量纯 Go 实现、无 CGO 依赖、已在 `go.mod` 预载；
   - 利用 `pdf.Interpret` 遍历页面操作流，拦截 `Tm`、`Td`、`Tj`、`TJ` 等指令，精准提取带 `(X, Y)` 绝对坐标的文本块（TextChunk）。
2. **文件识别策略（`Support`）**：
   - 坚守《编码规范》§3.5「识别用内容不用外壳，外壳相同而内容不同的情况一定会出现」；
   - 严格要求必须满足：
     - 文件头符合 PDF 规范（含 `%PDF`）；
     - 读取第 1 页纯文本，必须同时包含招行借记卡专有标识：`招商银行交易流水`、`账号`；
     - 必须完整包含该表格 6 个核心列名：`记账日期`、`货币`、`交易金额`、`联机余额`、`交易摘要`、`对手信息`；
   - 避免与工行信用卡流水（`icbc_credit`）或其他银行/账单格式发生认领冲突。
3. **收支过滤与金额符号转换（`Parse`）**：
   - **收支判定**：在银行借记卡对账逻辑中，扣款支出表现为负数，入账收入表现为正数；
   - **金额转换**：按照系统「金额以正数为常态表示支出」模型，扣款金额统一执行取反 `amount.Neg()`，生成正数支出金额；
   - **入账丢弃**：非负数（收入、转账转入、提现、存款结息）直接过滤丢弃，不作为支出落库；
   - 样例文件中非消费流水被过滤后，精准产出有效支出。
4. **解析层职责边界（无派生计算）**：
   - 解析器仅抽取与转换原始报表包含的字面字段：`BankName`、`CardLast4`、`ExpenseDate`、`ExpenseCurrency`、`ExpenseAmount`、`Counterparty`、`Remark`；
   - 派生字段（`Id`、`Version`、`AccountingAmount`、`ExchangeRate`、`AmortizationStartMonth` 等）统一留空/留零，交由上层门面 `expense.Parse`、`fillExpense`、`Derive` 计算，确保全系统派生规则唯一收敛。

## 二、需求分析与方案设计

### 2.1 解析器严格认领机制（`Support`）

#### 2.1.1 现实痛点
同一家银行在不同卡种（储蓄卡、信用卡、财富卡）、不同渠道（手机银行、网银专业版）导出流水时，表格字段往往存在可选配置（如用户导出时未勾选“对手信息”或“联机余额”），或者表头排布不同。若解析器仅通过简单的个别关键字匹配，会导致解析器误认领布局不兼容的 PDF，引发错列或 panic。

#### 2.1.2 严格校验方案
在 `Support` 方法中建立四重严格约束：
1. **文件载体约束**：前 1024 字节必须包含 `%PDF` 标识，`pdf.NewReader` 打开无异常且页数 > 0；
2. **凭据类型约束**：首页纯文本必须包含完整的固定标题 `招商银行交易流水`，以及账户标识 `账号`；
3. **列名完整性与排布顺序约束（核心）**：
   必须同时包含完整的 6 个列名，且必须按照招行该模板的物理出现顺序单调递增：
   $$\text{idx}(\text{记账日期}) < \text{idx}(\text{货币}) < \text{idx}(\text{交易金额}) < \text{idx}(\text{联机余额}) < \text{idx}(\text{交易摘要}) < \text{idx}(\text{对手信息})$$
   若用户在导出时取消了某可选列（如未勾选对手信息），或列位置发生置换，顺序校验立即阻断并返回 `false`；
4. **辅助语言对齐**：必须包含该模板特有的 6 个英文副表头（`Date`、`Currency`、`Amount`、`Balance`、`Transaction Type`、`Counter Party`）。

### 2.2 保守丢弃规则（`isNonExpenseRow`）

#### 2.2.1 规则原则
系统定位为「只记支出」，但个人借记卡常承载内部转账、信用卡还款、利息结算等多种非消费场景。规则必须遵循**“宁可保留为负数支出待人工甄别，不可粗暴误删真实消费”**的保守原则。

#### 2.2.2 规则矩阵与判定流
实现专用判据函数 `isNonExpenseRow(amount, remark, counterparty)`：
1. **信用卡还款（扣款/入账均丢弃）**：
   - 判定特征：摘要或对手方包含 `信用卡还款`，或摘要为 `还款`、`自动还款`；
   - 依据：还款属于借记卡向信用卡账户的内部资金调拨，真实消费已在信用卡对账单中记录，若在借记卡中重复计入支出会导致双重记账。予以丢弃。
2. **借记卡利息（入账丢弃）**：
   - 判定特征：金额非负，且摘要或对手方包含 `结息` 或 `利息`；
   - 依据：活期存款利息、定期结息属于纯资产孳息，不属于消费支出，予以丢弃。
3. **资金纯转入 / 收入（入账丢弃）**：
   - 判定特征：金额非负，且摘要包含 `转入`、`收款`、`代付`（提现入账）、`工资`；
   - 依据：纯收入与资金充值/转入，不属于消费支出，予以丢弃。
4. **冲抵性质的正数入账（保留）**：
   - 判定特征：金额非负，且内容包含 `退款`、`冲正`、`退货`、`退税`；
   - 依据：消费后的退款或商户冲正属于支出的负向抵扣，必须保留为负数支出（`amount.Neg()`）。
5. **未明确标识的正数流水（保守保留）**：
   - 若金额非负且未命中上述任何纯收入特征，不作假定，保守保留并转为负数支出。
6. **正常扣款流水（`amount < 0`，保留）**：
   - 除明确的信用卡还款外，其余所有扣款均视为正常支出保留，取反后生成正数支出金额。

### 2.3 隐私保护与零信息泄露机制

为落实“代码、单测与 answer.md 中绝不写死任何真实个人信息”的要求：
1. **源码层**：
   - `cmb_debit.go` 中所有数据提取均通过流坐标定位与正则表达式动态解析（如卡号末四位通过 `账号[：:]\s*([0-9*]+)` 提取），没有任何写死的数据特征值。
2. **测试层**：
   - `cmb_debit_test.go` 与 `expense_test.go` 中：
     - 移除全部硬编码的真实姓名、真实卡号末四位、真实商户全称与真实具体金额；
     - 断言全部改为结构性契约检查：`len(CardLast4) == 4`、`ExpenseCurrency == "CNY"`、`ExpenseAmount.IsPositive()`、`len(objects) == 17`、`!ExpenseDate.IsZero()`；
     - 增加测试样本文件探测：若样例文件已被删除或未随仓分发，单测通过 `t.Skip` 优雅跳过真实文件读取，绝不 panic 或断言失败；
     - 新增 `cmb_debit_internal_test.go`：构建 14 组基于内存的合成测试用例（覆盖还款、结息、代发、冲正、退款、代付、未知入账等所有分支），彻底摆脱对真实敏感文件的依赖。
3. **交付文档层（`answer.md`）**：
   - 对话1 与 对话2 的全量文本中，一律对姓名、账号、特定商户进行泛化脱敏，不保留任何具体敏感数据痕迹。

## 四、核心代码实现

### 4.1 保守过滤与严格认领实现 (`service/expense/cmb_debit/cmb_debit.go`)

```go
func (this *Parser) Support(ctx context.Context, data []byte) bool {
	if len(data) < 4 || !bytes.Contains(data[:min(1024, len(data))], []byte("%PDF")) {
		return false
	}
	reader, err := pdf.NewReader(bytes.NewReader(data), int64(len(data)))
	if err != nil || reader.NumPage() == 0 {
		return false
	}
	page := reader.Page(1)
	text, err := page.GetPlainText(nil)
	if err != nil {
		return false
	}

	// 1. 标题与账户元数据必须包含"招商银行交易流水"与"账号"
	if !strings.Contains(text, titleKeyword) || !strings.Contains(text, accountKeyword) {
		return false
	}

	// 2. 表格六个核心列必须完整存在，且出现顺序严格一致，防止可选导出列缺失或表格样式不一致时误认领
	idxDate := strings.Index(text, colDate)
	idxCurrency := strings.Index(text, colCurrency)
	idxAmount := strings.Index(text, colAmount)
	idxBalance := strings.Index(text, colBalance)
	idxRemark := strings.Index(text, colRemark)
	idxCounterparty := strings.Index(text, colCounterparty)

	if idxDate < 0 || idxCurrency < 0 || idxAmount < 0 || idxBalance < 0 || idxRemark < 0 || idxCounterparty < 0 {
		return false
	}
	if !(idxDate < idxCurrency && idxCurrency < idxAmount && idxAmount < idxBalance && idxBalance < idxRemark && idxRemark < idxCounterparty) {
		return false
	}

	// 3. 英文辅助表头严格对齐
	return strings.Contains(text, "Date") &&
		strings.Contains(text, "Currency") &&
		strings.Contains(text, "Amount") &&
		strings.Contains(text, "Balance") &&
		strings.Contains(text, "Transaction Type") &&
		strings.Contains(text, "Counter Party")
}

func isNonExpenseRow(amount decimal.Decimal, remark, counterparty string) bool {
	content := remark + counterparty

	// 1. 信用卡还款：内部账务结算，不论扣款或入账均不属于消费支出，丢弃以防与信用卡对账单双重记账
	if strings.Contains(content, "信用卡还款") || strings.Contains(remark, "还款") || strings.Contains(remark, "自动还款") {
		return true
	}

	// 2. 扣款明细（金额为负数）：除信用卡还款外，一律视为支出保留
	if amount.IsNegative() {
		return false
	}

	// 3. 入账明细（金额非负）：
	// 若包含退款、冲正、退货等具有冲抵支出属性的词汇，保留为负数支出
	if strings.Contains(content, "退款") || strings.Contains(content, "冲正") || strings.Contains(content, "退货") || strings.Contains(content, "退税") {
		return false
	}

	// 借记卡利息、结息属于纯存款利息收入，丢弃
	if strings.Contains(content, "结息") || strings.Contains(content, "利息") {
		return true
	}

	// 纯转入、收款、代付、工资等资金流入，丢弃
	if strings.Contains(remark, "转入") || strings.Contains(remark, "收款") || strings.Contains(remark, "代付") || strings.Contains(remark, "工资") {
		return true
	}

	// 无法断言为纯收入的非负流水，保守保留
	return false
}
```
