## 二、需求与范围

- **核心目标**：① 把「摊分」这个不严谨的叫法在页面上订正为「摊销」；② 给两处模糊搜索补小字提示；③ 明细链路改成「一次拉全量 → 前端分页 / 前端统计 / 前端导出」；④ 新增金额统计图表。
- **交付物**：纯前端（`static/`），继续 mock，不联调、不动后端。
- **范围边界**：审计页与文件页的分页**不动**（本轮只要求明细表格改前端分页）；后端零改动。
- **关键约束**：统计全部在前端算，后端只提供原始数据；图表筛选模块与明细页一致。

## 三、方案取舍

### 3.1 图表放哪：新增独立页面「统计」

放明细页会有三个问题：明细页已经背着筛选卡片 + 工具条 + 行内编辑器 + 表格 + 分页条 + 两条提示，再叠四张图，一屏什么都看不全；图表要的「口径切换」会和表格工具条抢位置；统计与逐笔核对是两种心智，混在一起两边都不顺手。

所以新增路由 `#/statistic`、导航名「统计」，排在「明细」之后。筛选模块与全量拉取抽成共用件，两页共用同一套定义，满足「筛选模块与明细页面一样」。

**两页各自持有自己的筛选条件**：共享一份 state 会让「在统计页缩小范围」把明细页的筛选也改掉，这种跨页副作用不值当。

### 3.2 「摊分 → 摊销」只改页面，CSV 列契约保持后端原文

冲突点：`csvHeader()` 现在是拿展示名当 CSV 列名（`page_expense.js:277-279`），而 CSV 列名是后端契约常量 `model.CsvAmortizationMonths = "摊分月数"`。展示名一改，导出的文件就带上「摊销月数」表头，联调时后端没有解析器认领它——而且 mock 自校验是自洽的，这个断裂要等到联调才暴露，属于静默故障。

采用：**把「展示名」与「CSV 列名」拆成两条独立声明**。`CSV_FIELDS` 由字符串数组改为 `{key, column}`，`column` 是后端契约原文；页面展示名照改为「摊销月数 / 摊销起始月 / 摊销结束月」。上传弹窗里补一句说明，讲清「摊分月数」是契约列名、页面称「摊销月数」，同一列。

**待确认**：后端 `model.CsvAmortizationMonths` 以及 5 处测试里的「摊分」要不要一并改成「摊销」。本轮任务限定前端，未动；改动本身只有一个常量 + 测试常量串，随时可做。

### 3.3 明细：一次拉全量，分页/统计/导出共用同一份数据

`newInquiry()` 里**删掉 `page` / `page_size`** —— 筛选条件从此只描述「筛什么」，不描述「取第几页」，后端据此返回全集。前端分页另起 `state.paging`，只切片不重查。

顺带删掉的：`fetchAllFiltered()` 与 `EXPORT_PAGE_LIMIT`（导出逐页拉 500 页的那套兜底，全量拉取之后没有存在理由）、`config.PAGE_SIZE_DEFAULT` / `PAGE_SIZE_MAX`（门面不再兜底也不封顶，mock 的 `checkPageSize` 一并删掉，改成与后端 `pageLimit` 同语义：非正即不限）。

**顺带修好的一个缺陷**：疑似重复的分组 `groupDuplicate` 原先只在当前页的行里找，跨页的重复组标不出来；改成在全量行上分组、只渲染当前页切片，跨页重复现在也会高亮。

### 3.4 统计口径

| 口径 | 落月规则 | 取数 |
| ---- | -------- | ---- |
| 记账金额 | 整笔落在支出日期所属月 | `accounting_amount` |
| 摊销金额 | 按摊销月数均摊到 `摊销起始月 … 摊销结束月` | `accounting_amount ÷ 摊销月数` |

均摊的尾差落在最后一个月（`总额 − 每月份额 × (月数−1)`），保证各月之和恒等于原始记账金额——除不尽时逐月四舍五入会让合计对不上。

支出类型为空的行归入「未分类」，不丢数据。已删除的行是否计入，跟着筛选里的「已删除」走，页面上写明。

### 3.5 图表选型：Chart.js + datalabels，落本地 lib

按编码规范的轮子顺序，图表属于「有积极维护且使用面广的成熟三方库」那一档，不自造。`chart.js@4.4.1` UMD + `chartjs-plugin-datalabels@2.2.0`（后者正是「标记出每段的金额与占比」这个诉求的现成件），都下载到 `static/lib/chart/`，走相对路径，与 bootstrap / decimal 一致。插件不自动注册，逐图 `plugins: [ChartDataLabels]` 显式挂，不污染别的图。

### 3.6 四张图

| 图 | 形态 | 回答什么 | 受口径影响 |
| -- | ---- | -------- | ---------- |
| 每月支出 × 支出类型 | 堆叠柱 + 每段标金额与占该月比例 + 柱顶标该月合计 | 任务指定的第一张 | 是 |
| 支出类型占比 | 环形 | 钱主要花在哪类 | 否 |
| 记账口径 vs 摊销口径 | 双折线 | 摊销把大额支出摊平了多少 | 否（两条线同时画） |
| 交易对手方 Top 10 | 横向条 | 钱主要给了谁 | 否 |

后三张与口径无关：一笔明细的各月份额之和恒等于它的记账金额，所以按类型/对手方汇总两种口径结果相同。因此**口径开关只放在第一张图的卡片头上**，不做成全局开关，免得让人以为切了会影响所有图。

堆叠柱的段太薄时标签必然挤成一团，datalabels 的 `display:'auto'` 会自动藏掉放不下的；为了「每段的金额与占比」在任何情况下都读得到，图下面挂一张可折叠的逐月逐类型明细表兜底。

# 对话1 · 追加二：除法精度与余数归属

## 一、先确认：余数本来就落在最后一个月

`page_statistic.js` 的 `monthShares` 一开始就是这个算法，本轮**没有改动**，只是补齐了证据：

```
前 N-1 个月 = 记账金额 ÷ 摊销月数，按金额精度四舍五入
第 N 个月   = 记账金额 − 前 N-1 个月 × (N-1)
```

逐月单独四舍五入会让各月之和对不上原始记账金额（100 ÷ 3 会得到 33.33×3 = 99.99），所以尾差一次性落在最后一个月。全程走 `Decimal`，不碰浮点。

穷举验证：8 个金额（含 `0.01`、`-7.77`、`999999.99`）× 1~120 个月共 960 组，**每一组的各月之和都与原始记账金额分毫不差，且每个份额都是两位小数**。

## 二、真正有浮点尾巴的地方：图表的柱顶合计与坐标轴

排查下来，除法/求和一共 4 处，出问题的只有展示链路：

| 位置 | 判定 |
| ---- | ---- |
| `page_statistic.js` 全部聚合与摊销 | **安全**，全程 Decimal |
| `component.js:182` 分页总页数 | **安全**，整数除法 |
| `chart.js:21` 占比 | **安全**，除完立刻 `toFixed(1)` 截住 |
| **`chart.js:57` 堆叠柱的柱顶合计** | **有问题**，把各段 `number` 用浮点加了一遍 |
| **`chart.js:96` 环形图总额** | 同上（只喂给占比，实际没显形，但同一个毛病） |
| **`util.js` `formatAmount`** | **放大器**，见下 |

复现（都是真实形态的分段金额）：

```
0.01 + 0.14 + 0.15 → 0.30000000000000004
0.02 + 0.15 + 0.17 → 0.33999999999999997
4.35 × 100        → 434.99999999999994
```

`formatAmount` 的「只补不截」规则是为后端的精确十进制串写的：有几位小数就印几位。喂给它一个 `0.30000000000000004`，它数出 17 位小数，**照着补齐，把整条尾巴原样印到屏幕上**。这就是你说的那两种形态。

## 三、两层修法

### 3.1 不产生：图表不再自己求和（`chart.js` + `page_statistic.js`）

柱顶合计与环形总额改为**由调用方把算好的精确值传进来**。统计页在聚合时就有 `summary.monthTotal`（Decimal），图表再拿 `number` 加一遍既重复又出错。

```
stackedBar({ labels, datasets, totals, format })   //totals 由调用方给
doughnut({ labels, values, total, format })        //total 同理
```

顺带也把层次理顺了：`chart.js` 从此**不对金额做任何算术**，只负责画；算术全留在持有 Decimal 的那一层。

### 3.2 不显形：`formatAmount` 先收噪声再量小数位（`util.js`）

坐标轴刻度是 Chart.js 自己算的，我们管不到，所以展示口也得兜一层：

```js
const amount = typeof value === 'number' ? new Decimal(value).toSignificantDigits(15) : new Decimal(value);
```

**只对 `number` 收，字符串一个字不动。** 判据不是拍脑袋：JS 的 `number` 本来就只有约 15~17 位有效数字，噪声全长在这条线之外；而后端给的是精确十进制串，它有几位小数就是几位，不能替它做主。

## 四、验证（新增 76 条断言，全绿）

### 4.1 噪声抹掉，真实小数位一位不丢

| 输入 | 输出 |
| ---- | ---- |
| `0.01+0.14+0.15` | `0.30` |
| `0.02+0.15+0.17` | `0.34` |
| `0.1+0.2` | `0.30` |
| `0.7+0.1`（`0.7999999999999999`） | `0.80` |
| `4.35*100`（`434.99999999999994`） | `435.00` |
| `-(0.1+0.2)` | `-0.30` |
| `1.005*3`（`3.0149999999999997`） | **`3.015`** |
| 字符串 `'12.345'` | `12.345` |
| number `12.3456` | `12.3456` |
| 字符串 `'100.00000000000001'` | 原样 |
| 字符串 `'123456789012.34'` | 原样 |

**倒数第五行是我一开始写错期望的地方**：我本来期望 `3.01`，实际是 `3.015`。代码是对的，我的期望是错的——噪声（`...49999999999997`）确实抹掉了，而第 3 位小数 `5` 是真实的，按「只补不截」就不该截。字符串路径原样保留这两条，证明这层收敛没有伤到后端给的精确值。

### 4.2 余数归属（10 组定点 + 960 组穷举）

| 金额 ÷ 月数 | 逐月份额 |
| ---- | ---- |
| 100.00 ÷ 3 | 33.33 / 33.33 / **33.34** |
| 100.00 ÷ 6 | 16.67 × 5 / **16.65** |
| 0.01 ÷ 3 | 0 / 0 / **0.01** |
| 0.05 ÷ 2 | 0.03 / **0.02** |
| −100.00 ÷ 3 | −33.33 / −33.33 / **−33.34** |
| −0.01 ÷ 3 | 0 / 0 / **−0.01** |
| 128.50 ÷ 1 | 128.5 |

每组都另外断言了四件事：各月之和恒等于原始金额、前 N−1 个月等额、每个份额小数位 ≤ 2、份额字符串不带长尾巴。

- 统计口径 30 条、整页渲染 30 条（新增「柱顶合计印出来没有浮点尾巴」）、契约与分页 12 条，全绿。
- 9 个模块 `node --check` 全过；import/export 0 处不匹配、0 处未使用。
- `go build ./...` 通过，`go test ./service/expense/... ./model/...` 全绿。

`grep float64 / NewFromFloat / ParseFloat` 在非测试的 Go 代码里**零命中**；金额算术全仓只有一处：

# 对话2 · 前端单测

## 一、先回答那个问题：能写，而且不用装任何东西

| 判据 | 实测 |

| 页面代码是 ESM，Node 认不认 | 认。Node 22.7 起默认开启语法自动识别，`.js` 里有 `import/export` 就按 ESM 跑，**不需要 `package.json`**——实测直接 `import '../static/js/util.js'` 通过 |
| 页面代码耦不耦合浏览器 | 一半不耦合：`util.js` / `config.js` / `mock.js` / `store.js` / 新拆出的 `expense_statistic.js` 全是纯逻辑，装上 `Decimal` 就能直接调；`component.js` 以下才需要 DOM |

## 三、方案取舍

### 3.1 测试目录放 `static_test/`，不放 `static/` 里

`static/static.go` 是 `//go:embed *`。我先做了实测：往 `static/_probe/` 放一个文件，它照样被嵌进二进制——**下划线前缀在这里挡不住**（那条「`.` 与 `_` 开头的会被排除」的规则只作用于模式里点名的目录，不作用于 `*` 的通配结果）。

放在 `static/` 下的后果是双份的：测试代码被打进发布二进制，而且 `static` 是对外托管的，`/static/test/...` 会变成任何人都能拉的路径。

所以测试落在仓库根的 `static_test/`：与 `static/` 镜像对称、名字自解释、Go 工具链因为目录里没有 `.go` 文件而整个跳过（`go build ./...` 与 `go test ./...` 都不受影响，已验证）。

**顺带验证了这条判据**：临时在 `static/` 放一个探针 `_test.go`，遍历 `StaticFile` 会把它自己列出来——反过来证明了 `static_test/` 确实在嵌入范围之外。嵌入文件数 25，与改动前一致。

### 3.2 不引 jsdom / vitest / jest

按 §八 的轮子顺序，这里该先问「有没有成熟三方库」。有，jsdom 就是。但这个仓库的前提不一样：

- 仓库里**没有 `package.json`、没有 `node_modules`、没有任何 npm 痕迹**，交付物是一个 Go 单二进制，前端三方库一律手动落到 `static/lib/` 且不走 CDN（`static/index.html:9-11`）。为了跑测试引入一整套包管理与上千个传递依赖，代价远大于收益。
- **真正需要 DOM 的只有整页渲染那一类用例。** 纯逻辑（金额、时间、CSV、摊销口径、mock 库、契约）一行 DOM 都不需要，它们走 `helper/lib.js`，只装 `Decimal`。
- 垫片收敛在 `helper/browser.js` **一个文件**里（391 行）。将来项目真要上 npm，把这一个文件换成 `import 'jsdom'` 即可，用例一行不用改——这也是把它单独拆出来的理由。

代价写在明处：**垫片不做布局、不做 CSS、不做默认行为**（表单提交、`data-bs-*` 的折叠与下拉都不会自己发生）。所以它能证明数据与结构，证明不了观感。这条也写在 `browser.js` 的文件头注释里。

### 3.3 为了可测性，把统计口径从页面里拆出来

规范 §3.2 讲的是「导出包装负责可靠与安全、非导出实现负责纯逻辑，测试直接构造任意环境调用非导出实现」。ESM 里没有「非导出但可测」这种东西——导出即全公开，不导出即完全够不着。**这一层在 JS 里的对应物就是拆模块。**

于是新增 `static/js/expense_statistic.js`：`monthShares` / `monthTotalOf` / `monthAxis` / `aggregate` / `cellAmount` / `monthTotal` / `percentText` 与三个口径常量，**原样搬过去，一个字没改**。`page_statistic.js` 从 361 行降到 262 行，只剩渲染与组装，行为零变化。

不拆的话，要测「100 ÷ 3 的余数落在最后一个月」只有两条路：改源码（上一轮在 scratchpad 里干的就是这个，不能作为长期资产），或者穿过整页渲染去反推（960 组穷举根本做不了）。

命名与 `expense_inquiry.js` 对齐：两者都是「明细领域的共用件」，一个管筛选条件，一个管统计口径，各自被 `page_*.js` 取用。

**没有跟着拆的**：`page_expense.js` 里的 `duplicateKey` / `groupDuplicate` / `pageRows`。它们都是十行上下的薄逻辑，单独拆出来就是过度拆分（§3.4）；而且 §七 本来就说「能从最外层入口发起的测试就从最外层发起」——这三个通过整页渲染验证，反而顺带验了表格装配。

### 3.4 断言手写，用栈帧裁剪顶替 `t.Helper()`

`helper/check.js` 只有 `equal` / `ok` / `not` / `same` / `includes` / `excludes` / `near` / `rejects` 八个，每个都干两件事：把实际值与期望值拼进文案，再 `Error.captureStackTrace(err, 这个函数)` 把自己这一帧从栈里砍掉。**这就是 Go 的 `t.Helper()` 在 JS 里的等价物**——不砍的话失败全都报在 `check.js` 里，看不出是哪条用例。

失败长这样，与 Go 那边的 `t.Errorf("...: got=%d want=%d")` 同一个形态：

```
Error: 摊销月数 -3: got=0 want=1
    at TestContext.<anonymous> (static_test/expense_statistic_test.js:100:5)
```

## 六、测试当场逮到的两处缺陷（已修）

### 6.1 摊销月数为负时，这一笔的钱从所有图里整个消失

`monthShares` 原本写的是 `Number(row.amortization_months) || 1`。`||` 只兜得住 `0 / NaN / null / ''`，**负数是真值，会原样漏过去**——`for (index = 0; index < -3; ...)` 一次都不跑，返回空数组，这一笔在柱状图、环形图、折线图、逐月表里同时消失，而且总额对不上还不报错。

改成与后端 `fillExpense`（`service/expense/expense.go:82-84`）同一个判据：

```js
const count = Math.floor(Number(row.amortization_months));
const months = count >= 1 ? count : 1;
```

**够得着吗**：后端落库前会把 `< 1` 收成 1，正常链路给不出负数。但统计口径是前端自己算的，判据不能靠上游的善意——何况 `Math.floor` 同时把非整数月数也收住了，那才是真正会让「各月之和 = 记账金额」这条不变式破掉的输入。

### 6.2 mock 收下了后端会拒的「2.5 个月」

`mock.js` 的判据是 `!(Number(months) >= 1)`，`"2.5"` 过得去；后端走 `util.Str2Int`（`strconv.ParseInt`），`"2.5"` 解析失败得 0，落进 `< 1` 被拒（`base_csv.go:111-117`）。

mock 是后端在前端这一侧的替身，替身比正主宽松就意味着：mock 模式下验收通过的 CSV，联调时会被后端打回。改成 `Number.isInteger(Number(months)) && Number(months) >= 1`。

## 一、依据来源

## 二、需求与范围

- **核心目标**：① 前端支持黑夜模式；② 前端支持中英双语，默认按浏览器判定（中文→中文，其余→英文）；③ 后端返回的文案也要按当前语言展示，但**不改后端一行代码**。
- **交付物**：纯前端（`static/`）+ 配套单测（`static_test/`）。仍是 mock，不联调。
- **范围边界**：后端零改动；`mock.js` 也零改动——它是后端在前端这一侧的替身，替身说中文才是对的，它一旦说英文，转译链路就永远测不到。
- **本轮后端确实零改动**：`git status` 里没有任何 `.go` 文件。

## 三、方案取舍

### 3.1 词条以中文原文为键，不另立一份中文词典

两种做法：symbol 键（`nav.expense` → 中/英两份词典），或原文键（`t('明细')` → 只有一份英文词典）。选后者，理由三条：

1. **中文词典必然与代码漂移**。symbol 键要维护两份表，改了代码忘了改中文表就是静默漏译，而且漏的是主语言。原文键让中文成为代码本身，漏不了。
2. **后端文案与界面文案能共用一张表**。后端给的 `成功`、`数据入库` 既是审计表里的展示值，也是筛选复选框的标签——同一个词条，一条记录同时供 `t()` 与 `serverText()` 用。symbol 键做不到这一点，得再建一张「后端原文 → symbol」的映射，等于凭空多一层。
3. gettext 的 msgid 就是源语言原文，这是成熟做法，不是权宜之计。

**代价写在明处**：改一句中文，英文词表里对应的键就失配了。所以补了一条契约用例——扫源码里所有 `t('…')` 字面量，逐条在英文词表里找（`static_test/i18n_test.js`「源码里每一处 t('…') 都能在英文词表里找到」）。改中文忘了改词表，这条用例当场红。

### 3.2 后端文案：整句表打头，模板表兜底，嵌套递归到底

`serverText(text)` 三步：整句命中 → 模板命中 → 原样返回。

- **整句表**就是 `TEXT`，覆盖 `解析明细，文件格式无法识别` 这类没有变量的。
- **模板表** `SERVER` 是 47 条 `{pattern, text}`，覆盖 `解析CSV，第%d行，%s` 这类。`text` 里的 `$1` 会**再走一次 `serverText`**——后端的报错正是嵌套拼出来的，只翻外层等于没翻：

  ```
  解析明细，第3笔，记账币种，不在枚举内: xx
  → Parse records: record #3, Accounting currency is not in the enumeration: xx
  ```

  递归收敛有保证：每条 pattern 都以中文字面量锚定，捕获组严格短于原串。
- **不命中就原样透出**，不吞不改。漏登记一句话的后果是「这一句还是中文」，不是「这一句没了」——这条分界很重要，后端将来新增报错，前端不会因此丢信息。

### 3.3 转译放在哪一层

| 文案来源 | 转译点 | 理由 |
| -------- | ------ | ---- |
| 前端自己写的文案 | 产生处 `t('…')` | 键就在代码里，没有中间态 |
| 后端报错 | `util.js` 的 `toastErr` | 错误全仓只有这一个显形出口，放这里就不必让每个 `catch` 各记一遍。mock 抛的和真接口抛的走的是同一个出口 |
| 审计的操作类型/结果/对象类型/摘要 | `page_operation_log.js` 的 `buildRow` 与 `component.js` 的 `resultBadge` | 它们是**数据字段**不是异常，只能在渲染那一格时转 |

`resultBadge` 是这条分界最直白的样子：**颜色认后端原文（`result === '成功'`），文案走转译（`badge(t(result))`）**。取值是契约，展示才是文案——和上一轮 `CSV_FIELDS` 把 `column` 与展示名拆开是同一条判据。

### 3.4 什么翻、什么不翻

**不翻的四类，一个都不能翻：**

| 不翻 | 为什么 |
| ---- | ---- |
| CSV 契约列名（`CSV_FIELDS[].column`） | 那是后端解析器逐字比对的表头，翻了导出的文件就再也传不回去 |
| 筛选条件里的枚举取值（`operation_type` 传给后端的仍是 `数据入库`） | 取值进请求体，翻了后端不认 |
| 用户数据（对手方、支出类型、备注、银行名、文件名） | 那是人自己录的内容，不是界面文案。英文态下种子里的「盒马鲜生」「餐饮」照旧原样——图例里出现中文不是漏译 |
| 语言下拉里的「中文 / English」 | 这个下拉恰恰是给看不懂当前语言的人用的，跟着当前语言变就白设了 |

**顺手翻了的一处**：CSV 导入模板里的示例值（`盒马鲜生 / 晚饭 / 餐饮`）。它是给人照着填的样例，不是契约；模板 blob 的缓存因此改成按语言存（`page_expense.js` `templateCache`），否则换了语言还下到上一门语言的模板。**表头那一行任何语言下都不动。**

### 3.5 顿号是文案的一部分

`全库记账币种：CNY、USD` 这种拼接，`、` 只有中文有。三处 `join('、')` 改成 `join(t('、'))`，词表里 `'、': ', '`。不改的话英文句子中间会突兀地冒出一个中文标点——这类「翻了句子没翻标点」是最容易漏的一种。

### 3.6 暗色：用 bootstrap 的 `data-bs-theme`，不自写暗色 CSS

bootstrap 5.3 的全套组件配色都挂在 `html` 的 `data-bs-theme` 上。所以暗色不是「再写一套样式」，而是「把这个属性设对」。`app.css` 里只补了两条：疑似重复那两档底色在深色下把透明度从 0.16/0.12 抬到 0.24/0.26，不抬就糊成一团分不出组。其余样式本来就走 `--bs-*` 变量，自动跟着走。

**导航条单独锁成暗色**（`<nav class="navbar bg-dark" data-bs-theme="dark">`）。`data-bs-theme` 可以挂在任意子树上，这样品牌色、导航链接色、里面那两个下拉在明暗两种主题下都不用另调。顺带把 5.3 已经弃用的 `navbar-dark` 换掉了。

**主题有三档不是两档**：跟随系统 / 浅色 / 深色，默认跟随系统。判据与语言一致——先问浏览器，人改了就以人为准。「跟随系统」下还挂了 `matchMedia` 的监听，系统半夜自己切深色，页面跟着切。

### 3.7 首屏不能闪白，所以那段脚本只能内联

模块脚本一律是 defer 的，等它跑起来样式表早就生效了，深色偏好的人会先被闪一屏白底。所以 `index.html` 的 `<head>` 里有一段同步内联脚本，在样式表之前把 `data-bs-theme` 落到 `html` 上。

它是 `theme.js` 的最小复刻，**这是刻意的重复**：唯一的替代是把逻辑塞进样式表，而 CSS 读不到 localStorage。为了让这份复制不悄悄漂移，补了两条用例——键名必须与 `store.js` 的 `THEME_KEY` 逐字相等，且这段脚本必须排在 `bootstrap.min.css` 之前、不能是 `type="module"`。

### 3.8 换语言换主题是整屏重绘，不是 `location.reload()`

刷新最省事，但 mock 模式下内存库会被连同这一轮新增/编辑过的数据一起清掉，等于「换个语言，刚录的几笔没了」。所以走 `app.js` 的 `renderRoute()` 整屏重来。代价是编辑器里填到一半的草稿会丢（`render()` 本来就会重置 `adding` / `editingId`），已写进局限。

主题切换要多做一步：`refreshChartTheme()` 必须**先于**重绘。Chart.js 只在建实例时读一次 `Chart.defaults.color`，不重读的话深色底上还印着深色字。

### 3.9 语言与主题的偏好落 localStorage，与列显隐同一档

`store.js` 是全仓唯一碰 storage 的地方，新增的 `getLang/setLang/getTheme/setTheme` 也放这里，不另起一处。读写都包了 try/catch：隐私模式下 storage 的读写会直接抛，偏好取不到该回落到自动判定，不该把整页带崩——原来的 `setColumns` 没包，这次新写的包了。

## 五、实施结果

### 5.1 语言判定

```
存过偏好 → 用偏好（值必须是 zh/en，别的一律不认）
没存过   → navigator.language 以 zh 开头即中文，其余英文
```

**只看首选语言，不去 `navigator.languages` 里翻中文**。翻的话，首选英文、备选中文的浏览器会落到中文，与「浏览器是中文才给中文」这条判据正相反。这一条单独有用例守着。

### 5.2 `UNFILLED` 从常量改成函数

统计里「支出类型/对手方留空」那一档叫「未填写」，是我们造的分类名，得跟着语言走。而常量在模块求值时就定死了——页面上换语言，图例里那一档不会跟着变。改成 `unfilled()`，在 `aggregate` 里取一次存进局部变量，不在循环里逐行调。

### 5.3 一处刻意的文案分叉

审计页「操作摘要」的小字，中文是「模糊匹配，输入片段即可（按后端原文匹配）」，英文是「Fuzzy match against the raw text the server stores, which is Chinese」。

这不是翻译不忠，是**英文态下必须多说的一句话**：摘要由后端生成并以中文落库，表格里展示的是转译后的英文，但模糊搜索打到的是库里那份中文。不写这句，英文用户会拿着屏幕上的 `Data ingest` 去搜，搜不到还找不出原因。明细页与文件页的模糊提示没有这个问题（对手方、备注、文件名都是用户自己录的），仍用原来那条共用词条。

### 5.4 `node --check` 靠不住，这次被它放过去一次

写完 `lang_en.js` 第一版时，词表里有一批键没加引号——中文汉字本身能当标识符，但全角逗号不能。`node --check static/js/lang_en.js` **报了 ok**，真正 `import` 才炸在第 264 行。

所以本轮没有再把 `node --check` 当静态检查，改为**让用例真的 import 每一个模块**：`lang_en.js` 被 `i18n.js` 引，`i18n.js` 被全部页面模块引，`theme.js` 与 `i18n.js` 各有自己的用例文件——语法错一定会红在测试里。

### 5.5 垫片补齐与确定性

`static_test/helper/lib.js` 现在钉死 `navigator`（`zh-CN`）与两个 storage。此前纯逻辑那三个用例文件（`contract` / `mock` / `expense_statistic`）没有装垫片，`navigator.language` 取的是**跑测试那台机器的系统区域**——在中文机器上碰巧全绿，换台英文机器结果就不一样了。钉死之后，「默认语言」这件事在用例里有了确定的前提。

`browser.js` 新增：`documentElement`（主题与 `lang` 都落在它上面）、`matchMedia`（带 `setSystemDark()` 抓手）、`#pref-host` 容器、`setNavigatorLanguage()` 抓手。

## 三、方案取舍

### 3.1 `newInquiry` 与 `defaultInquiry` 拆成两个

直接给 `newInquiry()` 加上默认日期是最省事的写法，也是错的：它同时是三条别的链路的底座。

| 复用它的地方 | 叠上日期窗口会怎样 |
| ---- | ---- |
| `deleteSelected`：`{...newInquiry(), id: ids}` | 勾中的行只要落在一年之外就**删不掉**，而页面还提示「已删除 N 笔」 |
| `loadVerify`：按审计ID 取本批次 | 老批次的核实视图变成空表 |
| 按 `operation_id` / `file_id` 从审计页、文件页跳过来 | 「本批明细」「本文件明细」点进去一行都没有 |

所以拆成一对：

- **`newInquiry()`**：空骨架，只描述「筛什么」，不带日期。上面三条链路继续用它——它们本来就被 ID 圈死了，那比任何日期窗口都紧。
- **`defaultInquiry()`**：页面初值与「重置」的落点，= 骨架 + 最近一年。

这条拆分同时回答了「按审计ID 进来的页面，日期框为什么是空的」：那一屏的边界是审计ID，不是日期。用例把这条钉住了。

### 3.2 必填在提交时校验，不用 `required`

`<input required>` 让浏览器拦，代价是提示气泡走**浏览器的语言**，跟页面语言对不上——刚做完多语言就自己戳个洞。所以判据自己写在 `expenseFilter` 的 submit 里，文案走词表；两个日期格各挂一行小字「必填，默认最近一年」。

### 3.3 mock 的种子跟着语言走：重写库里的值，而不是展示时翻译

「切换语言后 mock 数据也改英文」有两种做法：

| 做法 | 结果 |
| ---- | ---- |
| 只在展示时翻译 | 库里还是中文，**按「Dining」筛选一条都筛不出来**——筛选是拿库里存的值匹配的 |
| 换语言时把库里重写一遍 | 存的即展示的，筛选、去重、统计全都自洽 |

选后者。`mock.relocalize()` 走一遍三张表，`app.js` 在换语言时调它，`seed()` 最后也调一次（种子是按中文原文造的）。

**只重写我们自己造的那批词**。种子词表是封闭集（银行名、对手方、支出类型、备注、重复导入那几个标签），用户在页面上录入或上传的值不在表里，一个字都不会被改——这条由用例守着：造一笔「我录的对手方 / 我录的备注 / 我录的类型」，切两次语言后逐字比对。

认回来的办法是 `i18n.js` 新导出的 `textOf(lang, key)`：拿一个种子词在**各语言下的全部写法**去比对库里存的值，认出是哪个词条，再换成当前语言的写法。少了这个导出，英文→中文那一步就没法做（当前语言下 `t()` 只会把中文原样返回）。

文件名是唯一的例外：`2609-招商.csv` 里只有「招商」是词条，而这个文件名又嵌在入库摘要里。所以另立一张 `SEED_FILE_WORDS`，对文件名与摘要做**子串**替换；其余字段一律整值命中，不做子串，免得把用户备注里碰巧出现的词也换掉。

### 3.4 记账币种初值挂在语言上

`defaultCurrency()` 放在 `i18n.js`：币种初值本来就是语言的一部分，加第三种语言时会被这行逼着表态。解锁页按定义就是「没有会话」的状态，`store.getAccountingCurrency()` 此时返回的是常量缺省值，正是要被覆盖的那个，所以直接用 `defaultCurrency()`，顺手删掉了原来那句永远走不到的 `|| CURRENCY_DEFAULT`。

### 3.5 配套一：种子日期改成相对今天算

「默认最近一年」这条一上，写死 2026 年的种子就有两个问题：

1. **当下就少 10 行**。`1 + pseudo(index, 27)` 会把当月的日期铺到 27 号，其中 10 行落在今天之后——未来日期的支出既不真实，也正好被窗口筛掉。
2. **一年之后整批消失**。到 2027-09，59 行一条都不在窗口内，demo 打开就是空表。

所以批次改成「相对今天的第 0/1/2 个月」，当月的日期只取到今天为止；疑似重复那几组改成「N 天前」，其中一组就落在今天（原来那条「最新的一组要能在第一页看见高亮」的用意反而更准了）。文件名由批次月份推导，今天（2026-09）推出来的恰好还是 `2609-招商.csv` / `2608-中行.csv` / `2607-手工补录.csv`，与改动前逐字一致。

### 3.6 配套二：种子文件补上真实内容

原来 `db.fileBlob[batch.file_id] = ''`，三个种子文件都是空的。预览一打开就是「这个文件没有内容」，功能等于没法验收。

改成**用那一批明细导出的 CSV 当文件内容**，列名走落库契约。顺带修掉了一处对不上的账：疑似重复那 9 笔也挂在这些批次的 `file_id` 上，而入库摘要写的是 `batch.count`。现在文件内容与摘要条数都等明细全部落库之后再按真实行数生成，「文件里 22 行、库里挂着 24 行」这种情况不会再有（摘要条数因此由 22/18/12 变成 25/21/15）。

换语言时这份内容也要重新生成——`relocalize()` 最后会把种子文件重刷一遍，否则预览出来的还是上一门语言。

### 3.7 预览：认领看内容，不看扩展名

后端下载响应统一是 `application/octet-stream`，扩展名又只是文件名里的一截，两个都作不得准。所以 `file_preview.js` 抄的是后端 `Parser` 那个形态：一张 `{support, render}` 的注册表，逐个问「你认这份内容吗」，**宁可不认领也不能认错**——认错了要么铺一屏乱码，要么把二进制当文本渲染。

| 判据 | 认领条件 |
| ---- | ---- |
| PDF | 头部是 `%PDF-` |
| JSON | 去空白后以 `{` 或 `[` 开头，且 `JSON.parse` 过得去 |
| CSV | 不含控制字符；解出来至少两列，且每行列数一致 |

CSV 那条特意写严了：「能被 CSV 解析器解出来」太松，一段散文也能解成一列，判据松了就会把散文铺成一列表格。顺序上 JSON 排在 CSV 前面，`[[1,2],[3,4]]` 这种两边都认的内容有确定的归属，不看运气。

### 3.8 其余格式的交互：不藏按钮，进来之后说清原因

**不做的**：按扩展名把「预览」按钮灰掉。格式是按内容认的，没下载之前根本不知道认不认；按名字灰掉既会误伤（叫 `.dat` 的 CSV），又会漏放（叫 `.csv` 的二进制）。

**做的**：每一行都给预览入口，认不出来时弹窗里给一张兜底卡片，一句说清原因、一句指出下一步，页脚就是「下载」。三种兜底原因分开写，不混成一句「无法预览」：

| 情况 | 文案 |
| ---- | ---- |
| 空文件 | 这个文件没有内容 |
| 认不出格式 | 这种格式没有内置预览，目前只认 PDF、CSV 与 JSON |
| 文本超过 512 KB | 文件超过 512.00 KB，不在页面里铺开 |

尺寸这条只卡文本类：PDF 交给浏览器自带的阅读器，它自己按需加载，不必限。CSV 再加一层，只铺前 200 行并在表下写明「共 N 行，这里只铺了前 200 行」——几万行一次铺进 DOM 会把页面卡死，而截断了不说就是骗人。

### 3.9 弹窗骨架抽出来共用

预览要的是大对话框、可滚动、页脚只有「下载 / 关闭」，与 `confirmModal` 的「取消 / 确认」不是一回事。抽出非导出的 `modalNode(title, body, footer, dialogClass)`，`confirmModal` 与新的 `openModal` 共用同一层，差别只剩尺寸与页脚放什么。

预览页脚的「下载」直接复用行上那个 `downloadFile(row)`，不另起一条链路，也就不多造一个需要回收的 blob 地址。PDF 的 iframe 地址没法跟着弹窗一起消失，沿用图表那套「下一次预览时先撤上一次」。

## 六、待确认与局限

| # | 事项 | 说明 |
| - | - | - |
| 1 | **观感仍然证明不了** | 与前三轮同一条。预览弹窗在真浏览器里的表现（PDF 阅读器能不能起来、宽表会不会顶出横向滚动、深色下的 iframe 背景）只能你过一眼 |
| 2 | **PDF 预览这条路 mock 里跑不到** | 后端只从「明细入库」写 `file_meta`，而当前只有标准 CSV 一种解析器，所以库里根本不会出现 PDF。这条链路由单测覆盖（造一份 `%PDF-` 开头的内容），但真浏览器里的 PDF 阅读器要等后端多出一种解析器之后才验得到。**没有为了演示去伪造一条 PDF 文件记录**——那等于编业务 |
| 3 | 预览要先把整个文件下下来 | 接口没有「只取前若干字节」的能力，识别又必须看内容。小文件无所谓，几十兆的文件会先下完再告诉你「太大不铺开」。要根治得后端加一个范围读接口 |
| 4 | 种子词表的整值替换有个理论上的误伤 | 用户如果把对手方原样录成「星巴克」，换语言时会被一起翻成 `Starbucks`。判据是「整值等于某个种子词」，已经是最窄的口子；只在 mock 里发生，真实后端没有这一步 |
| 5 | 文件名与摘要走的是子串替换 | 用户上传的文件如果名字里带「招商」，换语言时那两个字会被换掉。同上，只在 mock 里 |
| 6 | 「最近一年」是模块求值时算的 | 页面从深夜开着到第二天，默认窗口还是昨天那个。重新进页面即刷新，不值得为它加一层 |
| 7 | 按审计ID/文件ID 进来的那一屏，日期框是空的 | 这是 §3.1 的取舍：那一屏的边界是 ID。但此时若再点「查询」，必填校验会要求补上日期——因为那一刻用户是在重新提交表单。**取舍写在这里，若你更想要「进来就填上默认日期」，改 `render()` 里那两行即可** |
| 8 | 摘要条数由 22/18/12 变成 25/21/15 | §3.6 的直接后果：疑似重复那 9 笔本来就挂在这些批次上，原先的数字是错的 |
| 9 | 预览只认三种格式 | 图片、Excel、纯文本都落兜底。加一种就是往 `VIEWERS` 里加一条 `{support, render}`，分发逻辑不用动 |
