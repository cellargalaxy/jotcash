## 二、需求与范围

- **核心目标**：① 把「摊分」这个不严谨的叫法在页面上订正为「摊销」；② 给两处模糊搜索补小字提示；③ 明细链路改成「一次拉全量 → 前端分页 / 前端统计 / 前端导出」；④ 新增金额统计图表。
- **交付物**：纯前端（`static/`），继续 mock，不联调、不动后端。
- **范围边界**：审计页与文件页的分页**不动**（本轮只要求明细表格改前端分页）；后端零改动。
- **关键约束**：统计全部在前端算，后端只提供原始数据；图表筛选模块与明细页一致。

## 三、方案取舍

### 3.1 图表放哪：新增独立页面「统计」

放明细页会有三个问题：明细页已经背着筛选卡片 + 工具条 + 行内编辑器 + 表格 + 分页条 + 两条提示，再叠四张图，一屏什么都看不全；图表要的「口径切换」会和表格工具条抢位置；统计与逐笔核对是两种心智，混在一起两边都不顺手。

所以新增路由 `#/statistic`、导航名「统计」，排在「明细」之后。筛选模块与全量拉取抽成共用件，两页共用同一套定义，满足「筛选模块与明细页面一样」。

**两页各自持有自己的筛选条件**：共享一份 state 会让「在统计页缩小范围」把明细页的筛选也改掉，这种跨页副作用不值当。

### 3.2 「摊分 → 摊销」只改页面，CSV 列契约保持后端原文

冲突点：`csvHeader()` 现在是拿展示名当 CSV 列名（`page_expense.js:277-279`），而 CSV 列名是后端契约常量 `model.CsvAmortizationMonths = "摊分月数"`。展示名一改，导出的文件就带上「摊销月数」表头，联调时后端没有解析器认领它——而且 mock 自校验是自洽的，这个断裂要等到联调才暴露，属于静默故障。

采用：**把「展示名」与「CSV 列名」拆成两条独立声明**。`CSV_FIELDS` 由字符串数组改为 `{key, column}`，`column` 是后端契约原文；页面展示名照改为「摊销月数 / 摊销起始月 / 摊销结束月」。上传弹窗里补一句说明，讲清「摊分月数」是契约列名、页面称「摊销月数」，同一列。

**待确认**：后端 `model.CsvAmortizationMonths` 以及 5 处测试里的「摊分」要不要一并改成「摊销」。本轮任务限定前端，未动；改动本身只有一个常量 + 测试常量串，随时可做。

### 3.3 明细：一次拉全量，分页/统计/导出共用同一份数据

`newInquiry()` 里**删掉 `page` / `page_size`** —— 筛选条件从此只描述「筛什么」，不描述「取第几页」，后端据此返回全集。前端分页另起 `state.paging`，只切片不重查。

顺带删掉的：`fetchAllFiltered()` 与 `EXPORT_PAGE_LIMIT`（导出逐页拉 500 页的那套兜底，全量拉取之后没有存在理由）、`config.PAGE_SIZE_DEFAULT` / `PAGE_SIZE_MAX`（门面不再兜底也不封顶，mock 的 `checkPageSize` 一并删掉，改成与后端 `pageLimit` 同语义：非正即不限）。

**顺带修好的一个缺陷**：疑似重复的分组 `groupDuplicate` 原先只在当前页的行里找，跨页的重复组标不出来；改成在全量行上分组、只渲染当前页切片，跨页重复现在也会高亮。

### 3.4 统计口径

| 口径 | 落月规则 | 取数 |
| ---- | -------- | ---- |
| 记账金额 | 整笔落在支出日期所属月 | `accounting_amount` |
| 摊销金额 | 按摊销月数均摊到 `摊销起始月 … 摊销结束月` | `accounting_amount ÷ 摊销月数` |

均摊的尾差落在最后一个月（`总额 − 每月份额 × (月数−1)`），保证各月之和恒等于原始记账金额——除不尽时逐月四舍五入会让合计对不上。

支出类型为空的行归入「未分类」，不丢数据。已删除的行是否计入，跟着筛选里的「已删除」走，页面上写明。

### 3.5 图表选型：Chart.js + datalabels，落本地 lib

按编码规范的轮子顺序，图表属于「有积极维护且使用面广的成熟三方库」那一档，不自造。`chart.js@4.4.1` UMD + `chartjs-plugin-datalabels@2.2.0`（后者正是「标记出每段的金额与占比」这个诉求的现成件），都下载到 `static/lib/chart/`，走相对路径，与 bootstrap / decimal 一致。插件不自动注册，逐图 `plugins: [ChartDataLabels]` 显式挂，不污染别的图。

### 3.6 四张图

| 图 | 形态 | 回答什么 | 受口径影响 |
| -- | ---- | -------- | ---------- |
| 每月支出 × 支出类型 | 堆叠柱 + 每段标金额与占该月比例 + 柱顶标该月合计 | 任务指定的第一张 | 是 |
| 支出类型占比 | 环形 | 钱主要花在哪类 | 否 |
| 记账口径 vs 摊销口径 | 双折线 | 摊销把大额支出摊平了多少 | 否（两条线同时画） |
| 交易对手方 Top 10 | 横向条 | 钱主要给了谁 | 否 |

后三张与口径无关：一笔明细的各月份额之和恒等于它的记账金额，所以按类型/对手方汇总两种口径结果相同。因此**口径开关只放在第一张图的卡片头上**，不做成全局开关，免得让人以为切了会影响所有图。

堆叠柱的段太薄时标签必然挤成一团，datalabels 的 `display:'auto'` 会自动藏掉放不下的；为了「每段的金额与占比」在任何情况下都读得到，图下面挂一张可折叠的逐月逐类型明细表兜底。

# 对话1 · 追加二：除法精度与余数归属

## 一、先确认：余数本来就落在最后一个月

`page_statistic.js` 的 `monthShares` 一开始就是这个算法，本轮**没有改动**，只是补齐了证据：

```
前 N-1 个月 = 记账金额 ÷ 摊销月数，按金额精度四舍五入
第 N 个月   = 记账金额 − 前 N-1 个月 × (N-1)
```

逐月单独四舍五入会让各月之和对不上原始记账金额（100 ÷ 3 会得到 33.33×3 = 99.99），所以尾差一次性落在最后一个月。全程走 `Decimal`，不碰浮点。

穷举验证：8 个金额（含 `0.01`、`-7.77`、`999999.99`）× 1~120 个月共 960 组，**每一组的各月之和都与原始记账金额分毫不差，且每个份额都是两位小数**。

## 二、真正有浮点尾巴的地方：图表的柱顶合计与坐标轴

排查下来，除法/求和一共 4 处，出问题的只有展示链路：

| 位置 | 判定 |
| ---- | ---- |
| `page_statistic.js` 全部聚合与摊销 | **安全**，全程 Decimal |
| `component.js:182` 分页总页数 | **安全**，整数除法 |
| `chart.js:21` 占比 | **安全**，除完立刻 `toFixed(1)` 截住 |
| **`chart.js:57` 堆叠柱的柱顶合计** | **有问题**，把各段 `number` 用浮点加了一遍 |
| **`chart.js:96` 环形图总额** | 同上（只喂给占比，实际没显形，但同一个毛病） |
| **`util.js` `formatAmount`** | **放大器**，见下 |

复现（都是真实形态的分段金额）：

```
0.01 + 0.14 + 0.15 → 0.30000000000000004
0.02 + 0.15 + 0.17 → 0.33999999999999997
4.35 × 100        → 434.99999999999994
```

`formatAmount` 的「只补不截」规则是为后端的精确十进制串写的：有几位小数就印几位。喂给它一个 `0.30000000000000004`，它数出 17 位小数，**照着补齐，把整条尾巴原样印到屏幕上**。这就是你说的那两种形态。

## 三、两层修法

### 3.1 不产生：图表不再自己求和（`chart.js` + `page_statistic.js`）

柱顶合计与环形总额改为**由调用方把算好的精确值传进来**。统计页在聚合时就有 `summary.monthTotal`（Decimal），图表再拿 `number` 加一遍既重复又出错。

```
stackedBar({ labels, datasets, totals, format })   //totals 由调用方给
doughnut({ labels, values, total, format })        //total 同理
```

顺带也把层次理顺了：`chart.js` 从此**不对金额做任何算术**，只负责画；算术全留在持有 Decimal 的那一层。

### 3.2 不显形：`formatAmount` 先收噪声再量小数位（`util.js`）

坐标轴刻度是 Chart.js 自己算的，我们管不到，所以展示口也得兜一层：

```js
const amount = typeof value === 'number' ? new Decimal(value).toSignificantDigits(15) : new Decimal(value);
```

**只对 `number` 收，字符串一个字不动。** 判据不是拍脑袋：JS 的 `number` 本来就只有约 15~17 位有效数字，噪声全长在这条线之外；而后端给的是精确十进制串，它有几位小数就是几位，不能替它做主。

## 四、验证（新增 76 条断言，全绿）

### 4.1 噪声抹掉，真实小数位一位不丢

| 输入 | 输出 |
| ---- | ---- |
| `0.01+0.14+0.15` | `0.30` |
| `0.02+0.15+0.17` | `0.34` |
| `0.1+0.2` | `0.30` |
| `0.7+0.1`（`0.7999999999999999`） | `0.80` |
| `4.35*100`（`434.99999999999994`） | `435.00` |
| `-(0.1+0.2)` | `-0.30` |
| `1.005*3`（`3.0149999999999997`） | **`3.015`** |
| 字符串 `'12.345'` | `12.345` |
| number `12.3456` | `12.3456` |
| 字符串 `'100.00000000000001'` | 原样 |
| 字符串 `'123456789012.34'` | 原样 |

**倒数第五行是我一开始写错期望的地方**：我本来期望 `3.01`，实际是 `3.015`。代码是对的，我的期望是错的——噪声（`...49999999999997`）确实抹掉了，而第 3 位小数 `5` 是真实的，按「只补不截」就不该截。字符串路径原样保留这两条，证明这层收敛没有伤到后端给的精确值。

### 4.2 余数归属（10 组定点 + 960 组穷举）

| 金额 ÷ 月数 | 逐月份额 |
| ---- | ---- |
| 100.00 ÷ 3 | 33.33 / 33.33 / **33.34** |
| 100.00 ÷ 6 | 16.67 × 5 / **16.65** |
| 0.01 ÷ 3 | 0 / 0 / **0.01** |
| 0.05 ÷ 2 | 0.03 / **0.02** |
| −100.00 ÷ 3 | −33.33 / −33.33 / **−33.34** |
| −0.01 ÷ 3 | 0 / 0 / **−0.01** |
| 128.50 ÷ 1 | 128.5 |

每组都另外断言了四件事：各月之和恒等于原始金额、前 N−1 个月等额、每个份额小数位 ≤ 2、份额字符串不带长尾巴。

### 4.3 回归

- 统计口径 30 条、整页渲染 30 条（新增「柱顶合计印出来没有浮点尾巴」）、契约与分页 12 条，全绿。
- 9 个模块 `node --check` 全过；import/export 0 处不匹配、0 处未使用。
- `go build ./...` 通过，`go test ./service/expense/... ./model/...` 全绿。

## 五、顺带查清的一件事：后端没有这个风险

`grep float64 / NewFromFloat / ParseFloat` 在非测试的 Go 代码里**零命中**；金额算术全仓只有一处：

# 对话2 · 前端单测

## 一、先回答那个问题：能写，而且不用装任何东西

| 判据 | 实测 |

| 有没有测试运行器 | Node 24.14 自带 `node --test`（`node:test`），等价于 Go 的 `testing`，不是三方库 |
| 页面代码是 ESM，Node 认不认 | 认。Node 22.7 起默认开启语法自动识别，`.js` 里有 `import/export` 就按 ESM 跑，**不需要 `package.json`**——实测直接 `import '../static/js/util.js'` 通过 |
| 页面代码耦不耦合浏览器 | 一半不耦合：`util.js` / `config.js` / `mock.js` / `store.js` / 新拆出的 `expense_statistic.js` 全是纯逻辑，装上 `Decimal` 就能直接调；`component.js` 以下才需要 DOM |

## 三、方案取舍

### 3.1 测试目录放 `static_test/`，不放 `static/` 里

`static/static.go` 是 `//go:embed *`。我先做了实测：往 `static/_probe/` 放一个文件，它照样被嵌进二进制——**下划线前缀在这里挡不住**（那条「`.` 与 `_` 开头的会被排除」的规则只作用于模式里点名的目录，不作用于 `*` 的通配结果）。

放在 `static/` 下的后果是双份的：测试代码被打进发布二进制，而且 `static` 是对外托管的，`/static/test/...` 会变成任何人都能拉的路径。

所以测试落在仓库根的 `static_test/`：与 `static/` 镜像对称、名字自解释、Go 工具链因为目录里没有 `.go` 文件而整个跳过（`go build ./...` 与 `go test ./...` 都不受影响，已验证）。

**顺带验证了这条判据**：临时在 `static/` 放一个探针 `_test.go`，遍历 `StaticFile` 会把它自己列出来——反过来证明了 `static_test/` 确实在嵌入范围之外。嵌入文件数 25，与改动前一致。

### 3.2 不引 jsdom / vitest / jest

按 §八 的轮子顺序，这里该先问「有没有成熟三方库」。有，jsdom 就是。但这个仓库的前提不一样：

- 仓库里**没有 `package.json`、没有 `node_modules`、没有任何 npm 痕迹**，交付物是一个 Go 单二进制，前端三方库一律手动落到 `static/lib/` 且不走 CDN（`static/index.html:9-11`）。为了跑测试引入一整套包管理与上千个传递依赖，代价远大于收益。
- **真正需要 DOM 的只有整页渲染那一类用例。** 纯逻辑（金额、时间、CSV、摊销口径、mock 库、契约）一行 DOM 都不需要，它们走 `helper/lib.js`，只装 `Decimal`。
- 垫片收敛在 `helper/browser.js` **一个文件**里（391 行）。将来项目真要上 npm，把这一个文件换成 `import 'jsdom'` 即可，用例一行不用改——这也是把它单独拆出来的理由。

代价写在明处：**垫片不做布局、不做 CSS、不做默认行为**（表单提交、`data-bs-*` 的折叠与下拉都不会自己发生）。所以它能证明数据与结构，证明不了观感。这条也写在 `browser.js` 的文件头注释里。

### 3.3 为了可测性，把统计口径从页面里拆出来

规范 §3.2 讲的是「导出包装负责可靠与安全、非导出实现负责纯逻辑，测试直接构造任意环境调用非导出实现」。ESM 里没有「非导出但可测」这种东西——导出即全公开，不导出即完全够不着。**这一层在 JS 里的对应物就是拆模块。**

于是新增 `static/js/expense_statistic.js`：`monthShares` / `monthTotalOf` / `monthAxis` / `aggregate` / `cellAmount` / `monthTotal` / `percentText` 与三个口径常量，**原样搬过去，一个字没改**。`page_statistic.js` 从 361 行降到 262 行，只剩渲染与组装，行为零变化。

不拆的话，要测「100 ÷ 3 的余数落在最后一个月」只有两条路：改源码（上一轮在 scratchpad 里干的就是这个，不能作为长期资产），或者穿过整页渲染去反推（960 组穷举根本做不了）。

命名与 `expense_inquiry.js` 对齐：两者都是「明细领域的共用件」，一个管筛选条件，一个管统计口径，各自被 `page_*.js` 取用。

**没有跟着拆的**：`page_expense.js` 里的 `duplicateKey` / `groupDuplicate` / `pageRows`。它们都是十行上下的薄逻辑，单独拆出来就是过度拆分（§3.4）；而且 §七 本来就说「能从最外层入口发起的测试就从最外层发起」——这三个通过整页渲染验证，反而顺带验了表格装配。

### 3.4 断言手写，用栈帧裁剪顶替 `t.Helper()`

`helper/check.js` 只有 `equal` / `ok` / `not` / `same` / `includes` / `excludes` / `near` / `rejects` 八个，每个都干两件事：把实际值与期望值拼进文案，再 `Error.captureStackTrace(err, 这个函数)` 把自己这一帧从栈里砍掉。**这就是 Go 的 `t.Helper()` 在 JS 里的等价物**——不砍的话失败全都报在 `check.js` 里，看不出是哪条用例。

失败长这样，与 Go 那边的 `t.Errorf("...: got=%d want=%d")` 同一个形态：

```
Error: 摊销月数 -3: got=0 want=1
    at TestContext.<anonymous> (static_test/expense_statistic_test.js:100:5)
```

### 3.5 Chart 用录像机，不装真 Chart.js

真 Chart.js 要量 canvas 与 2d 上下文，Node 里没有。垫片里的 `Chart` 只把每张图拿到的 `type / data / options / plugins` 录下来——**断言的是「喂给图表的数据对不对」**，这恰好是这一层唯一该由前端负责的事；像素怎么落是 Chart.js 的职责，不该由本仓库的用例去担保。

唯一的例外是柱顶合计：那段代码自己往 canvas 上写字（`chart.js:33-53`），所以用例造了个 `ctx` 录音机直接调 `afterDatasetsDraw`，验它写了几次、写在哪个坐标、写的是不是调用方传进来的精确值。

## 六、测试当场逮到的两处缺陷（已修）

### 6.1 摊销月数为负时，这一笔的钱从所有图里整个消失

`monthShares` 原本写的是 `Number(row.amortization_months) || 1`。`||` 只兜得住 `0 / NaN / null / ''`，**负数是真值，会原样漏过去**——`for (index = 0; index < -3; ...)` 一次都不跑，返回空数组，这一笔在柱状图、环形图、折线图、逐月表里同时消失，而且总额对不上还不报错。

改成与后端 `fillExpense`（`service/expense/expense.go:82-84`）同一个判据：

```js
const count = Math.floor(Number(row.amortization_months));
const months = count >= 1 ? count : 1;
```

**够得着吗**：后端落库前会把 `< 1` 收成 1，正常链路给不出负数。但统计口径是前端自己算的，判据不能靠上游的善意——何况 `Math.floor` 同时把非整数月数也收住了，那才是真正会让「各月之和 = 记账金额」这条不变式破掉的输入。

### 6.2 mock 收下了后端会拒的「2.5 个月」

`mock.js` 的判据是 `!(Number(months) >= 1)`，`"2.5"` 过得去；后端走 `util.Str2Int`（`strconv.ParseInt`），`"2.5"` 解析失败得 0，落进 `< 1` 被拒（`base_csv.go:111-117`）。

mock 是后端在前端这一侧的替身，替身比正主宽松就意味着：mock 模式下验收通过的 CSV，联调时会被后端打回。改成 `Number.isInteger(Number(months)) && Number(months) >= 1`。
