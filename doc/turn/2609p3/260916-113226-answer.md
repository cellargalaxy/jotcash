## 二、需求与范围

- **核心目标**：① 把「摊分」这个不严谨的叫法在页面上订正为「摊销」；② 给两处模糊搜索补小字提示；③ 明细链路改成「一次拉全量 → 前端分页 / 前端统计 / 前端导出」；④ 新增金额统计图表。
- **交付物**：纯前端（`static/`），继续 mock，不联调、不动后端。
- **范围边界**：审计页与文件页的分页**不动**（本轮只要求明细表格改前端分页）；后端零改动。
- **关键约束**：统计全部在前端算，后端只提供原始数据；图表筛选模块与明细页一致。

## 三、方案取舍

### 3.1 图表放哪：新增独立页面「统计」

放明细页会有三个问题：明细页已经背着筛选卡片 + 工具条 + 行内编辑器 + 表格 + 分页条 + 两条提示，再叠四张图，一屏什么都看不全；图表要的「口径切换」会和表格工具条抢位置；统计与逐笔核对是两种心智，混在一起两边都不顺手。

所以新增路由 `#/statistic`、导航名「统计」，排在「明细」之后。筛选模块与全量拉取抽成共用件，两页共用同一套定义，满足「筛选模块与明细页面一样」。

**两页各自持有自己的筛选条件**：共享一份 state 会让「在统计页缩小范围」把明细页的筛选也改掉，这种跨页副作用不值当。

### 3.2 「摊分 → 摊销」只改页面，CSV 列契约保持后端原文

冲突点：`csvHeader()` 现在是拿展示名当 CSV 列名（`page_expense.js:277-279`），而 CSV 列名是后端契约常量 `model.CsvAmortizationMonths = "摊分月数"`。展示名一改，导出的文件就带上「摊销月数」表头，联调时后端没有解析器认领它——而且 mock 自校验是自洽的，这个断裂要等到联调才暴露，属于静默故障。

采用：**把「展示名」与「CSV 列名」拆成两条独立声明**。`CSV_FIELDS` 由字符串数组改为 `{key, column}`，`column` 是后端契约原文；页面展示名照改为「摊销月数 / 摊销起始月 / 摊销结束月」。上传弹窗里补一句说明，讲清「摊分月数」是契约列名、页面称「摊销月数」，同一列。

**待确认**：后端 `model.CsvAmortizationMonths` 以及 5 处测试里的「摊分」要不要一并改成「摊销」。本轮任务限定前端，未动；改动本身只有一个常量 + 测试常量串，随时可做。

### 3.3 明细：一次拉全量，分页/统计/导出共用同一份数据

`newInquiry()` 里**删掉 `page` / `page_size`** —— 筛选条件从此只描述「筛什么」，不描述「取第几页」，后端据此返回全集。前端分页另起 `state.paging`，只切片不重查。

顺带删掉的：`fetchAllFiltered()` 与 `EXPORT_PAGE_LIMIT`（导出逐页拉 500 页的那套兜底，全量拉取之后没有存在理由）、`config.PAGE_SIZE_DEFAULT` / `PAGE_SIZE_MAX`（门面不再兜底也不封顶，mock 的 `checkPageSize` 一并删掉，改成与后端 `pageLimit` 同语义：非正即不限）。

**顺带修好的一个缺陷**：疑似重复的分组 `groupDuplicate` 原先只在当前页的行里找，跨页的重复组标不出来；改成在全量行上分组、只渲染当前页切片，跨页重复现在也会高亮。

### 3.4 统计口径

| 口径 | 落月规则 | 取数 |
| ---- | -------- | ---- |
| 记账金额 | 整笔落在支出日期所属月 | `accounting_amount` |
| 摊销金额 | 按摊销月数均摊到 `摊销起始月 … 摊销结束月` | `accounting_amount ÷ 摊销月数` |

均摊的尾差落在最后一个月（`总额 − 每月份额 × (月数−1)`），保证各月之和恒等于原始记账金额——除不尽时逐月四舍五入会让合计对不上。

支出类型为空的行归入「未分类」，不丢数据。已删除的行是否计入，跟着筛选里的「已删除」走，页面上写明。

### 3.5 图表选型：Chart.js + datalabels，落本地 lib

按编码规范的轮子顺序，图表属于「有积极维护且使用面广的成熟三方库」那一档，不自造。`chart.js@4.4.1` UMD + `chartjs-plugin-datalabels@2.2.0`（后者正是「标记出每段的金额与占比」这个诉求的现成件），都下载到 `static/lib/chart/`，走相对路径，与 bootstrap / decimal 一致。插件不自动注册，逐图 `plugins: [ChartDataLabels]` 显式挂，不污染别的图。

### 3.6 四张图

| 图 | 形态 | 回答什么 | 受口径影响 |
| -- | ---- | -------- | ---------- |
| 每月支出 × 支出类型 | 堆叠柱 + 每段标金额与占该月比例 + 柱顶标该月合计 | 任务指定的第一张 | 是 |
| 支出类型占比 | 环形 | 钱主要花在哪类 | 否 |
| 记账口径 vs 摊销口径 | 双折线 | 摊销把大额支出摊平了多少 | 否（两条线同时画） |
| 交易对手方 Top 10 | 横向条 | 钱主要给了谁 | 否 |

后三张与口径无关：一笔明细的各月份额之和恒等于它的记账金额，所以按类型/对手方汇总两种口径结果相同。因此**口径开关只放在第一张图的卡片头上**，不做成全局开关，免得让人以为切了会影响所有图。

堆叠柱的段太薄时标签必然挤成一团，datalabels 的 `display:'auto'` 会自动藏掉放不下的；为了「每段的金额与占比」在任何情况下都读得到，图下面挂一张可折叠的逐月逐类型明细表兜底。

### 2.3 柱高默认摊销口径

`page_statistic.js` 的 `state.measure` 初值改为 `MEASURE_AMORTIZATION`，并写明理由：大额分期的钱本来就不是当月花掉的，记账口径会让那一个月凭空拱起一根柱子。口径下拉的选项顺序不动（记账在前、摊销在后，原始在前、派生在后），只换默认选中项。

概览里的「覆盖月份（…口径）」、图1 标题、逐月逐类型表的标题都跟着 `measureName()` 走，无需另改。

## 四、需要你知道的一处不兼容

**改名前导出的 CSV 不能再导入了。** 表头第 11 列是「摊分月数」，解析器按内容认领、逐字比对表头，差一个字就不认领——上面 §3.2 那条用例正是这个行为的实证。

影响面：前端仍是 `USE_MOCK = true`，尚未联调、没有真实历史文件；真有旧文件，把表头那一列手工改成「摊销月数」即可，数据本身不用动。这是你明确要求的改名带来的必然结果，不是缺陷。
