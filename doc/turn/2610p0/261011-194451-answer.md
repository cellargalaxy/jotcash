### 2.2 云闪付账单截图离线识别器架构设计

由于系统要求**严禁调用在线 OCR 接口**，且云闪付截图为长达近万像素的高清移动端滚动截图，设计了「Go 宿主引擎 + 离线 ONNX 视觉推理 + 内存级哈希缓存」架构：

1. **离线 OCR 推理引擎**：
   - 使用工业级轻量离线 OCR 引擎 `RapidOCR`（基于 PP-OCRv3 模型与 ONNX Runtime），完全在本地 CPU 推理，模型权重内嵌于环境，零网络请求、零外泄风险；
   - 编写标准化离线 OCR 脚本 [`service/expense/unionpay_screenshot/ocr.py`](file:///home/ms/document/code/jotcash/service/expense/unionpay_screenshot/ocr.py)，通过标准输入流（stdin）接收图像原始字节，通过标准输出（stdout）返回结构化文本块（包含文字、多边形外接矩形坐标、置信度）；
   - 使用 Go 1.16+ `//go:embed ocr.py` 将脚本内嵌至 Go 二进制中，优先读取源码路径，若运行在独立编译二进制下则自释放至临时目录，实现跨平台与独立部署无缝兼容。
2. **内存级哈希缓存（`ocrCache`）**：
   - 针对长截图推理耗时的特点，在 `unionpay_screenshot` 包内实现基于 SHA-256 哈希的内容级结果缓存；
   - 当接入层依次执行 `Support(ctx, data)` 与 `Parse(ctx, data)` 时，OCR 仅在 `Support` 执行一次，`Parse` 直接毫秒级命中缓存，杜绝重复推理开销。

### 2.3 严格契约认领（`Support` 与 `checkContract`）

坚守《编码规范》§3.5「识别用内容不用外壳，宁可不认领也不能认错」：
1. **外壳层快速筛除**：
   - 检查文件前缀 Magic Bytes：仅放行 JPEG（`\xFF\xD8\xFF`）与 PNG（`\x89PNG\r\n\x1a\n`）；
   - CSV、PDF 等非图片格式在 0 微秒内安全拒绝，不产生任何子进程与推理消耗；
2. **页面顶层特征契约（`y <= 800` 区间）**：
   - 必须包含标题特征：`"交易记录"`；
   - 必须包含渠道特征：`"银联交易"` 或 `"云闪付"`；
   - 必须包含状态筛选标签：`"全部"` 且包含 `"支出"` 或 `"收入"`；
   - 若不满足上述特征组合，坚决不认领（返回 `false`），杜绝普通相册照片、微信截图或支付宝截图误认领。

### 2.4 流水数据抽取与时序解析

1. **时序与年份推断**：
   - 在页面顶层区域正则匹配账单年份（如 `(\d{4})年` 匹配 `2026年10月→`），获取基准年份；
   - 页面纵向扫描识别每日日期标头：正则匹配 `^(\d{1,2})\.(\d{1,2})\s*周[一二三四五六日天—\-]`，精准提取月份与日期；
   - 支持跨年推断：若账单标头为 1 月，而后续流水月份为 12 月，算法自动将年份折算为 `stmtYear - 1`。
2. **交易卡号、时间与银行名称归一化**：
   - 交易卡信息锚点行正则匹配：`([\p{Han}A-Za-z]+)\[(\d{4})\][］]?\s*·\s*(\d{1,2}:\d{2})`；
   - 提取银行名称、4 位卡号与时刻（`HH:MM`），与当前日期归并为精确的 `time.Time` 支出时间；
   - 银行名称通过映射表实现规范归一化（如繁体 `"滙豐"` 统一转换为标准 `"汇丰银行"`，`"招商"` 映射为 `"招商银行"` 等）。
3. **商户名聚合与长文本折行**：
   - 在卡信息锚点行上方（`y - 160 <= prev.Y < y - 20`）提取交易对手方文本；
   - 按横坐标 X 升序重组同一行的渠道前缀（如 `(特约)`、`美团` 等）与主商户名称，完整保留交易对手方明细。

### 2.5 交易类型识别与安全过滤规则

1. **预授权冻结/解冻与还款安全过滤**：
   - 严守保守过滤原则：在卡号锚点行附近识别状态标签，若为 `"冻结"` 或 `"解冻"`（为预授权验证，非实际结算支出），予以安全丢弃；
   - 针对商户名包含 `"还款"`、`"信用卡还款"`、`"转账"`、`"划转"` 的账户互转流水，予以安全丢弃；
2. **消费与退款判定**：
   - 带有 `"退款"` 标签或带有正号标头（`+￥...`）的流水，识别为退款抵扣，金额转为负数 `decimal.Decimal`，`Remark` 设为 `"退款"`；
   - 常规减号（`-￥...`）及支出列表明细，金额取正数，`Remark` 设为 `"消费"`。
