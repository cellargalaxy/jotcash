# internal/rule/passwd 实现记录

## 一、任务与承载边界

本轮实现 `internal/rule/passwd`，即分层文档 §六 L2 表 `rule/passwd` 行的两件承载：

| 承载 | 对应功能 | 落地 |
|---|---|---|
| A-8 策略校验（长度 ≥ 10、字母/数字/符号至少两类） | 终版 A-8 | `Check(password string) error` |
| 符合策略的随机初始密码生成 | 终版 A-2 | `Generate(ctx) (string, error)` |

依赖列只有 `base/pwdhash` 一项（外加普遍依赖的 `base/errs`）。承载末句是本包最硬的一条口径：**明文只在返回值中出现，本包不落盘、不打日志**。

产出四个文件：

| 文件 | 内容 |
|---|---|
| `passwd.go` | 包注释、两个阈值常量、四个文案键、`Check`、`countCategories` |
| `generate.go` | 字符集与生成规格常量、`KeyGenerateFailed`、`Generate`、`shuffle` |
| `passwd_test.go` | A-8 策略逐条覆盖（`TestCheckPolicy` 32 个子用例）+ 占位参数 + 红线回归 + 常量钉桩 |
| `generate_test.go` | 生成侧不变量 + 随机源失败注入 + 洗牌算法性质 |
| `consumer_check_test.go` | 依赖边界 AST 扫描 + 无日志约束 + 导出面 + 消费方走查 |

## 三、关键设计取舍

### 1. 长度按 rune 计，且非法 UTF-8 单独成一档错误

这是本轮唯一一处「比文档多做了一件事」的地方，理由是实测出来的一种**账户永久锁死**形态：

```
"aaaaaaaaa\xff"
  → RuneCountInString 得 10（每个非法字节各算一个 U+FFFD），长度判定「够 10 位」
  → 末字节 unicode.IsSymbol 为真，于是「两类」也满足 → A-8 判它合规
  → 经 base/pwdhash.Hash 落库
  → 下次登录时前端经 JSON 回传，json.Marshal 把非法字节换成真正的 U+FFFD
    （实测 10 字节变 12 字节、往返不相等）
  → Verify 拿到的已是另一个字符串，永远校验不通过
```

而 A-3 对 admin 明写「不设计恢复路径」。这与 `enum` 那一轮修掉的「写出侧不校验、读入侧校验」属同一类缺陷：**错误必须在造成它的那一次请求里失败**。故编码检查排在长度之前——非法编码下 rune 计数已无意义，先报长度会把真正的问题盖掉。

注意只拒**非法编码**，不拒合法多字节字符：用户真输入 U+FFFD 字面量是允许的，两者的区别在解码长度（实测 size 3 vs 1）。

### 2. 三类判据，且「不计类别」不等于「不许出现」

| 类别 | 判据 | 实测归类 |
|---|---|---|
| 字母 | `IsLetter` | `a` `Z` `汉` `五` `ｱ` 均为真 |
| 数字 | `IsDigit` | ASCII 数字、`٥`（阿拉伯-印度数字）为真 |
| 符号 | `IsPunct` \|\| `IsSymbol` | `!` `_` `-` 属 Punct；`$` `^` `+` `🙂` 属 Symbol |

两个判据都必须是「或」：`+` 只有 `IsSymbol` 为真、`_` 只有 `IsPunct` 为真，少判一个就漏一类字符。数字用 `IsDigit` 而非 `IsNumber`：`½`（No 类）、`Ⅷ`（Nl 类）实测 `IsNumber` 为真但 `IsDigit` 为假，把它们算作数字等于承认「9 个字母 + 一个 ½」是两类。

三类之外的字符（空白、控制字符、组合音标、`½`）**不计类别，但也不禁止**。这两句必须同时成立，各有反例兜着：

- 若把空白算作符号，`"aaaaaaaaa "` 就假装成了两类，而它实质是单类别弱口令；
- 若因为含空白就拒绝，`"hello world1"` 会被拒——它字母 10 个、数字 1 个，A-8 没有任何理由拒绝。

### 3. 生成用「定额 + 洗牌」，不用「生成后重试」

重试法（随机生成 → `Check` → 不合规重来）在字符集或定额配错时不会报错，只会变成跑很久甚至不终止的循环，故障形态是「A-1 系统初始化卡住」，比直接失败难查得多。定额法的合规性是结构性的。

洗牌是必需的：只把三段类别块拼起来会让数字与符号恒定落在固定区间，口令形态可预测。

洗牌上界必须是 `i+1` 而非 `i`——写成 `i` 就是 **Sattolo 算法**，只产生单个轮换，「任何字符都不可能留在原位」，排列空间从 n! 缩到 (n-1)! 且分布有偏。这个差别肉眼看不出（结果照样是乱的），是变异测试逼出来的一条用例，详见第五节。

生成完仍再过一遍 `Check`：定额已保证合规，这条断言是为了让「有人改了字符集常量或定额」在运行期第一次调用就暴露。

### 4. 字符集去易混字符，是 A-3 的直接要求

生成用字符集去掉 `0/O/o`、`1/l/I`，符号只取 `!@#$%^&*` 八个。理由不是美观：A-3 的 admin 初始密码要**由人从日志里抄读**，抄错一位与日志丢失后果相同。符号集也刻意避开 `\ " ' \` < > |`——它们会被 JSON 与 logrus 的 `%q` 转义，抄读时极易多抄漏抄一个反斜杠。作对照，`sethvargo/go-password` 的默认符号集实测恰好含 `\ " \` < > | $` 七个。

### 5. 本包一行日志都不打，连 logrus 都不 import

这是与 `base/pwdhash` 最明显的差别（后者打日志，只记长度与版本）。理由不是取向而是实情：本包每个错误分支的**唯一入参就是密码明文本身**，能写进日志的上下文只有「这个明文的哪一项不合规」。一旦允许打日志，「顺手把明文带上便于排查」在语法上就毫无阻力，而 §九 红线只给明文留了三个出口，日志那一个已被 A-3 的打印占满。

不 import logrus 把这件事变成编译期约束，`TestNoLoggingDependency` 把它变成 CI 约束。同理错误的 `errs.Params` 里**只放长度与类别的计数**——已实测确认 `errs.Error()` 会把 Params 逐项打出来，放明文进去就是日志与前端两处同时泄露。

### 6. 用分档错误而非哨兵错误

这与同层 `base/decimal`、`currency`、`enum` 相反，理由是**档位在本包是确定的**：A-8 校验失败恒为 `KindInvalidInput`，不像 `enum` 的「未知码值」会因调用方不同而分属 400 与 500 两档。既然档位唯一，就该在此定死，免得每个调用方各写一次映射。

四个键而非一个笼统的「密码不合规」：「请输入密码」与「至少 10 位」是两句不同的话，「编码非法」根本不该让用户去猜长度。

> **对 i18n 那一轮的硬性契约**：语言文件必须包含 `passwd.empty`、`passwd.invalid_encoding`、`passwd.too_short`、`passwd.too_few_categories`、`passwd.generate_failed` 五个键。前四个的占位参数分别为：无、无、`Min`+`Actual`、`Min`+`Actual`。

## 四、第三方库评估（结论：都不采用）

prompt 要求优先采用成熟库，故对两类候选做了**实测**而非只读文档。GitHub API 取到的数据：

| 库 | Star | 最近推送 | 许可 | 结论 |
|---|---|---|---|---|
| `sethvargo/go-password` | 688 | 2026-07 | MIT | 不采用 |
| `wagslane/go-password-validator` | 593 | 2022-09 | MIT | 不采用 |
| `trustelem/zxcvbn` | 71 | 2024-04 | MIT | 不采用 |
| `ccojocar/zxcvbn-go` | 7 | 2026-02 | MIT | 不采用 |
| `m1/go-generate-password` | 57 | 2022-04 | MIT | 不采用 |

**`sethvargo/go-password`（唯一认真评估的候选）**实测结论：

- 功能上只覆盖生成，**不解决 A-8 校验**——本包一半的承载它管不了；
- 随机源是 `io.Reader`，而 `base/pwdhash` 只出 `RandBytes`/`RandIndex`/`RandString`，接上去必须自建 Reader 适配器。实测该适配器下生成 5 个 12 位口令触发 **153 次 `Read`**，即 153 次 `RandBytes` 调用（每次都会走一遍 `pwdhash` 的日志分支）；
- 承载写死「采样自 `base/pwdhash` 的安全随机源」，为了用库反而要在本包写一层适配器 + 一套自定义字符集（默认集含 7 个转义敏感字符，见第三节 4）+ 一层错误档位映射，**比直接用 `RandString` 更长且多一个依赖**；
- 附带实测的两个行为：`Generate(10,5,5,...)` 会产出零字母口令（对 A-8 仍合法，但形态不可控）；`digits+symbols >= length` 时返回包级哨兵 `ErrExceedsTotalLength`（这点是好的）。

**`go-password-validator` / zxcvbn 系**：按**熵**或**猜测次数**判定强度，与 A-8 的「长度 + 类别数」是两套不兼容的判据。照用等于改业务规则，而 A-8 是终版定下的口径。

对照参考：`base/pwdhash` 用了官方 `golang.org/x/crypto/argon2`，`currency` 把 `bojanz/currency` 降为 test-only 依赖——**该用则用**。本包属确实无可用之处的一类：两个函数合计的算法内容只是「按 Unicode 属性数三类」与「定额采样 + 洗牌」，都是标准库直接支持的十几行。

## 五、依赖包排查：未发现影响本包的 bug

prompt 要求排查依赖包的 bug。逐项实测 `base/pwdhash` 与 `base/errs` 在本包用法下的行为，**未发现需要修复的缺陷**，以下是查过的点与实测结果：

| 排查点 | 实测结果 | 处置 |
|---|---|---|
| `RandString(n=0)` | 返回 `InvalidArgument` 档错误而非空串 | 符合其文档，本包不会传 0（定额均为正，有 `TestGenerateConstants` 钉住） |
| `RandIndex(1)` | 返回 0，不报错 | 正确，洗牌循环 `i > 0` 时上界最小为 2，不触及 |
| `RandString` 字符集含重复 rune | `"aab"` 采 2000 次得 a≈1333 / b≈667 | 按位置均匀采样，符合其文档；本包三个字符集均无重复字符 |
| `errs.Wrap(nil, ...)` | 返回 nil | 正确，本包不依赖此路径 |
| `errs` 的 typed-nil 陷阱 | 返回类型声明为 `error` 时不出现 | 本包 `Check` 已声明为 `error`（其 `From` 注释记录了该陷阱） |
| `errs.Error()` 是否打印 Params | **会**逐项打印 | 据此确立「Params 只放计数」的口径 + `TestNoPasswordInError` 兜底 |
| `Hash`/`Verify` 能否吃下生成的口令 | 可以，往返一致 | `TestGenerateHashable` 打通 A-2 全链路 |

排查过程中新建的临时探针包（`internal/tmpprobe2`）与临时模块（`/tmp/pwdprobe`）已全部删除，`git status` 中不留残余。

> 说明：`internal/tmpdedupprobe/` 属并发进行的 `rule/dedup` 会话的产物，不在本轮范围，未做改动。

### 变异测试（真正验证测试有效性的一步）

覆盖率只说明代码被执行过，不说明断言有效。故逐条把实现改错，确认测试**真的会失败**。共施加 32 条变异，其中 31 条为有效变异，**全部被杀**：

**Check 侧 13 条全杀**：长度下限 10→6、`<` 改 `<=`、长度按字节计、去掉非法 UTF-8 检查、跳过编码档、类别下限 2→1、空白算作符号、符号只判 `IsPunct`、只判 `IsSymbol`、数字改用 `IsNumber`、档位改成 `Internal`、占位参数带明文、空串档误判为长度档。

**Generate 侧 16 条全杀**：去掉洗牌、洗牌整体跳过、洗牌漏首位、洗牌上界 `i+1`→`i`（Sattolo）、洗牌单向赋值、`randIndex` 恒返 0、真实的按字节洗牌、生成长度 16→8、16→9、数字定额归零、符号定额归零、字符集放回 `0O1l`、字符集放回转义符、去掉末尾断言、失败时返回半成品口令、失败档位改成 `InvalidInput`。

**边界侧 2 条全杀**：偷偷 import logrus（`TestDependencyBoundary` 拦下）、导出 `countCategories`（`TestExportedSurface` 拦下）。

**变异测试发现了一个真实的测试缺口并已修复**：把洗牌上界 `randIndex(ctx, i+1)` 改成 `randIndex(ctx, i)`（退化为 Sattolo 算法）时，原有的形态、字符集、去重、位置分布四组用例**无一失败**——它们都只看「结果是不是乱的」。为此新增 `TestShuffleFixedPointsExist`，以 Sattolo 的定义性特征（不动点恒为 0，而 Fisher–Yates 下约 63% 的样本至少有一个不动点）判定，该变异随即被杀。同批补了 `TestShuffleIsPermutation`（拦覆盖字符的下标错误）、`TestShuffleMultibyte`（拦按字节洗牌产出非法 UTF-8）、`TestShuffleEdgeLengths`。

另有 1 条被判定为**等价变异**而非存活：`[]rune(string([]byte(s)))` 与 `[]rune(s)` 语义完全相同，属无效变异；改用真正的按字节洗牌（`[]byte` + `WriteByte`）后被 `TestShuffleMultibyte` 与 `TestShuffleEdgeLengths` 当场杀掉，报错信息即产出的乱码与变短的长度。

变异过程中源码均以 `diff` 核对已恢复原状；最终 `git status` 中本轮只新增 `internal/rule/passwd/` 一个目录。

### 测试自身的两处修正

两条红线用例第一版写错，都是被自己的「用例前提」断言当场拦下的，已修正并在注释里留了记录：

1. `TestNoPasswordInError` 的类别档哨兵用了 `strings.ToLower("Zq7Wv3Xb9K")`，它含数字因而构成两类、实际通过了校验，红线断言成了空转 → 改为纯字母哨兵，并加了一条「命中的必须是预期档位」的前提断言；
2. `TestNoPasswordInGenerateError` 的哨兵用了 `"short"`，而它正是文案键 `passwd.too_short` 的子串，被误报成泄露 → 换成不与任何文案键重叠的哨兵。

## 七、待确认项

**A-8 未规定长度上限，本包因此不设上限。**加上限等于新增一条业务规则、会拒掉一个按 A-8 合法的口令，故未自行决定。已知代价：超长口令会让 Argon2id 的单次开销随长度线性上升（`base/pwdhash` 参数为 64 MiB / 3 轮），登录接口存在被超长口令放大 CPU 的面。缓解落在别处而非本包——A-8 的「连续失败 5 次锁定 10 分钟」（`service/auth`）与接入层的请求体大小限制。是否需要在本包显式设上限，需产品口径确认后再动；此项已同步写入包注释的「已登记的残留」。
