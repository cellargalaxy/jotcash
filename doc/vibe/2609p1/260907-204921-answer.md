# internal/i18n 实现记录

## 一、任务与承载边界

本轮实现 `internal/i18n`，即分层文档 §六 L3 表 `i18n` 行（**边界包**，实现内联、无 L4 子包）的四件承载：

| 承载 | 对应功能 | 落地 |
|---|---|---|
| 按「语言 + 文案键」取词并填充占位参数 | K-4 + `base/errs` 错误文案 | `Render(lang, key, params)` |
| 可用语言列表与语言键合法性校验 | K-1 下拉 + `service/preference` 校验 | `Languages()` / `ParseLang()` |
| 整包语言文件下发 | T34④ 前端取词 | `Messages(lang)` |
| 语言文件随包 embed（T37） | K-4「加语种不改代码」 | `internal/i18n/locales/`（本轮仅 `zh-CN`） |

外加一件由 `middleware` 承载反向要求、必须落在本包的能力：

| 承载 | 来源 | 落地 |
|---|---|---|
| `Accept-Language` 回落 | 分层 §六 L6 `middleware` 行「语言解析（`ctxs.界面语言` → 请求头 `Accept-Language` → `i18n` 默认语言）」 | `Match(acceptLanguage)` |

依赖列是 `—`（**零仓库内依赖**）。这一条同时决定了两件事，见 §三 1：本包**不 import `base/errs`**（故错误用哨兵而非分档），**不 import `base/log`**（故本包一行日志都不打）。

## 三、关键设计取舍

### 1. 依赖列 `—` 的两个直接后果：哨兵错误 + 零日志

`i18n` 的依赖列是 `—`，而 `base/errs` 的包注释写明它**不依赖 i18n**（「i18n 在 L3，反向依赖会成环」）。方向上 `i18n → errs` 并不成环（L3 → L0 是下行），但本包仍不 import 它，理由与 `enum` 相同且更强：

- **档位在本包不唯一**：同一个「语言键非法」，经 `dto` 进来是用户输入错误（前端提交了非法值），经 `store` 出来是系统错误（库里存了不存在的语言键，属数据损坏）。本包无从判断被谁调用，一旦在此选定档位必有一方是错的；
- 故沿用 `currency` / `enum` / `decimal` / `calendar` 的一致取向：**返回哨兵错误，由调用方 `errors.Is` 判定后自行套档位与文案键**。

哨兵一律用**标准库** `errors.New` 构造，不用 `pkg/errors`——后者在包级变量初始化时抓栈，会让哨兵永久携带一份指向 `i18n.init` 的栈，`base/errs.Wrap` 的 `hasStack`（`errs.go:107`）随即跳过补栈，`middleware` 打 `%+v` 得到的栈顶变成 `i18n.init` 而非真实出错点。这条已由 `currency` 那一轮写成可执行断言，本包同步照做。

不 import `base/log` 的后果是**本包一行日志都不打**。这带来一个必须正面解决的问题：取词失败时无处可记，见下面第 3 条。

### 2. 采用 `nicksnyder/go-i18n`，但必须包一层——四个陷阱有三个是静默的

prompt 要求优先采用成熟库。候选实测数据（GitHub API，2026-09-08）：

| 库 | Star | 最近推送 | 许可 | 结论 |
|---|---|---|---|---|
| `nicksnyder/go-i18n` | **3544** | 2026-09-01 | MIT | **采用** |
| `leonelquinteros/gotext` | 509 | 2026-09-02 | NOASSERTION | 不采用 |
| `invopop/ctxi18n` | 96 | 2024-12-04 | Apache-2.0 | 不采用 |
| `vorlif/spreak` | 94 | 2025-09-28 | NOASSERTION | 不采用 |
| `knadh/go-i18n` | 24 | 2025-10-26 | MIT | 不采用 |
| `teacat/i18n` | 1 | 2023-05-21 | MIT | 不采用 |

**采用 `go-i18n` 的决定性理由是 K-4 本身，不是 star 数**：K-4 要求「新增语种只需增加配置、**无需改动代码**」。中文无复数形态，本轮若手写取词完全够用；但**英文有复数**——一旦加入英文，「1 item / 2 items」这类文案在手写实现下必须回头改 Go 代码，K-4 当场失效。`go-i18n` 内置 CLDR 200+ 语言的复数规则，这正是 K-4 那句话唯一真正需要第三方库的地方。gotext / spreak 走 GNU gettext 的 `.po/.mo` 路线，与「语言配置文件 + 文案键」的既有口径（`errs` 的 `msgKey`、`currency.NameKey()`）不兼容；其余几个 star 过低或已停更。

依赖足迹实测（`go list -deps`）：只增加 `go-i18n/v2/i18n` 及其 `internal/plural`、`i18n/template`，外加 `golang.org/x/text/language`——**而 `x/text v0.41.0` 本就已在 `go.mod` 中**（indirect）。`BurntSushi/toml` 与 `go.yaml.in/yaml/v3` **不进构建**（仅 `goi18n` CLI 需要，本仓库只用 JSON）。

但实测查出**五个陷阱，其中四个静默出错**，全部由本包包一层挡住：

| # | 陷阱 | 实测现象 | 本包的挡法 |
|---|---|---|---|
| **A** | 默认 `missingkey=default`，**占位参数缺失不报错** | 语言文件写 `{{.Min}}/{{.Actual}}` 而只传 `Min`，渲染出 `"密码至少需要 10 位，当前 <no value> 位"`，`err` 为 `nil`。完全不传数据则两处都是 `<no value>` | 一律以 `template.TextParser{Option: "missingkey=error"}` 覆盖。实测覆盖后同一输入返回 `map has no entry for key "Actual"` |
| **B** | `NewBundle` 的默认 tag 与语言文件 tag **不一致时，回落全盘失效** | `NewBundle(language.SimplifiedChinese)` + `zh-CN.json` → bundle 得到**两个** tag `[zh-Hans, zh-CN]`，而 `zh-Hans` 一条文案都没有。于是 `Accept-Language` 为 `en-US`、`zh-TW`、空串、垃圾串**全部取词失败**（实测 4/4 条）——登录页与 A-8 失败提示恰好都在这条路上 | 默认 tag 用 `language.Make("zh-CN")`，与文件名解析出的 tag **严格一致**；并在 `load` 里断言「bundle 内不得有无文案的空壳语言」，不一致即启动失败 |
| **C** | **`LanguageTags()` 返回内部切片本身，不是副本**（库缺陷） | `sort` 一下返回值（为让 K-1 下拉稳定有序，这是再自然不过的动作）→ **bundle 内部 matcher 的顺序被改写** → 双语言下取词**完全错配**：用户选中文得到英文、选英文得到中文，`err` 恒为 `nil`。实测 2/2 条错配 | 本包**从不对外暴露**该切片：`load` 时一次性拷出，自持 `matchTags`/`matchLangs` 并行数组；`Languages()` 返回副本 |
| **D** | `MessageFile.Messages` **顺序不稳定**（源自 map 遍历） | 同一文件解析 3 次，第 3 次顺序即变化 | 整包下发的键一律排序（`MessageKeys`）；`Messages()` 返回 `map`（无序天然无歧义） |
| **E** | **模板缓存把首次调用的 `missingkey` 语义永久固定**（最隐蔽） | `internal.Template.Execute` 用 `sync.Once` 缓存**第一次**解析的模板，而解析选项来自当次传入的 parser。故只要有一次调用漏传 `TemplateParser`，该文案即被焙成静默模式，**此后处处传 `missingkey=error` 也不再生效**——陷阱 A 的防线被一次疏忽永久拆除 | `load` 末尾 `warmTemplateCache` 在 init 期抢先把 `missingkey=error` 焙进每条文案的缓存槽。实测预热后即便**显式**用默认 parser 取词也仍然报错 |

陷阱 C 是货真价实的库缺陷（对外返回内部状态的可变引用）；陷阱 E 源自「缓存键不含解析选项」这一设计疏漏。两者的回归用例都留了 `t.Skip` 分支，若上游修复会自动降级为跳过而非误报失败。A/B/D 属「文档未强调、按直觉写必踩」。五条各有回归用例，且均经变异测试确认能捕获（见 §五）。

**陷阱 E 是被测试逼出来的**：最初实现只在每次 `Render` 传 `missingkey=error`，`TestTrapMissingKeyDefaultIsSilent` 因此失败——那次失败直接导致了 `warmTemplateCache` 的诞生。若当时把该用例改成「顺序无关」的宽松写法，缺陷会一路带到线上。

### 3. 取词是总函数，但同时返回失败原因

`middleware` 拿到 `errs` 三件套后必须产出一个字符串塞进 HTTP 响应体——它对「取词失败」无法做任何有意义的处置（难道给一个 400 错误回 500？）。故 `Render` 设计为**总函数**：任何输入都返回非空字符串，缺键或渲染失败时**回落到文案键本身**。

但纯总函数会把问题咽掉，而本包又不能打日志（第 1 条）。故签名为：

```go
func Render(lang Lang, key string, params Params) (string, error)
```

**第一个返回值恒非空**（调用方可直接用），第二个返回值在发生回落时非 nil（调用方可选择记录，测试据此断言）。两个消费方各取所需：`middleware` 用第一个值渲染、把第二个值打进日志；单测断言第二个值。这样「静默」与「无处可记」两个问题同时解决，且不需要本包 import `base/log`。

配套的 `MustRender` 只返回字符串，供文案键与参数都由本包测试锁死的场景使用。

### 4. 缺键在**启动时**就炸，不留到运行期

`Render` 的回落是最后一道保险，不是常态。真正的防线在 `load`：语言文件的**语法错误**（非法 JSON、坏模板）在 `load` 阶段一律返回错误并 panic 于 `init`——与 `currency.init` 对枚举表自检失败的处置一致（「表本身写错了」属编码错误，让它在进程启动时当场炸掉，远好过带着一张坏表跑到某笔请求才出错）。

实测确认 `go-i18n` **不在解析期校验模板语法**：`{{.Unclosed` 这种坏模板 `ParseMessageFileBytes` 返回 `nil`，要到取词时才报 `unclosed action`。故本包在 `load` 里**主动预编译每一条文案**，把坏模板从「某个用户某次请求时才暴露」提前到启动失败。

至于「37 个业务键是否齐备」——本包不能 import `errs`/`passwd`/`currency`（键的声明方分散在 L0/L1.0/L2，全 import 会让本包耦合到每个声明键的业务包）。故该校验落在**测试文件**里：`consumer_check_test.go` import 三个包、拿它们导出的键常量逐一断言语言文件覆盖。这正是 `currency` 已用过的手法（生产代码零仓库内依赖，测试文件 import `base/decimal` 做消费方走查）。

### 5. `Lang` 用私有指针的结构体，不用裸 string

与 `currency.Code` 同构：字段私有、包外无法构造非法值，`Lang("bogus")` 这类强转在编译期就不成立。这与 `enum` 的取向相反（那 7 个类型底层是 string，故必须在四条出入口逐一校验码值），原因是本包的取值域**在编译期就由 `locales/` 目录固定**，没有「库里存着一个代码里不存在的语言」之外的来源，而后者恰好就该被 `ParseLang` 拒掉。

`entity.User.Language` 是 `string`（`user.go:114`），故本包提供 `ParseLang(string) (Lang, error)` 与 `Lang.String()` 两侧转换；零值 `Lang{}` 表示「未指定」，`Render` 遇零值一律按默认语言处理——A-6 之前 `ctxs` 尚未写入，登录页与登录失败提示正是走这条路。

### 6. `Params` 用类型别名，让 `errs.Params` 直接传得进来

`base/errs.Params` 是 `map[string]any`，本包不能 import 它，于是必须自己声明一个。若声明为**定义类型**（`type Params map[string]any`），`middleware` 每次调用都要写 `i18n.Params(errs.ParamsOf(err))` 显式转换；声明为**类型别名**（`type Params = map[string]any`）则可直接传。取别名，并在注释里写明它与 `errs.Params` 的对应关系。

同时继承 `errs.Params` 的红线：**不得放入任何密码值**——文案会同时流向日志与前端两条路径。

补一条与本轮无关的观察：`go vet ./...` 在 `internal/fxrate` 与 `internal/parser` 两个**未纳入 git 跟踪**的目录上报错（`decimal.RoundRate` 未定义、`currency.Code("")` 无法转换）。两者都不在 `i18n` 的依赖链上（`go list -deps ./internal/i18n/` 只返回自身，零仓库内依赖），且文件时间戳晚于本轮产出，属并发进行的其他轮次的中间状态。其中 `decimal.RoundRate` 实为 `Decimal` 的**方法**（`round.go:78`）而非包级函数，`fxrate` 按包级函数调用故编译不过——已核实与本轮改动无因果关系，未擅自修改他人正在进行的工作。本轮范围内（`i18n` 及其 import 的 `base/*`、`currency`、`enum`、`entity`、`rule/*`）`go vet` 全部通过。

未覆盖的 4.2% 是三条「理论不可达」的防御分支（`Render` 中 `localizers` 查不到语言、`Match` 下标越界、`init` 的 panic 路径）——它们的存在是为了让将来的改动不至于 panic，无法在不破坏类型约束的前提下构造输入。

### 4. 变异测试：11 处注入，11 处被捕获

覆盖率只说明代码被执行过，不说明断言有效。故逐一把关键逻辑改坏，确认测试会失败：

| # | 注入的缺陷 | 结果 |
|---|---|---|
| 1 | `missingkey=error` → `missingkey=default` | 4 个用例组失败 |
| 2 | 去掉 `warmTemplateCache` 调用 | `TestTrapTemplateCacheFreezesFirstParser` 失败 |
| 3 | `Languages()` 返回内部切片 | `TestTrapLanguageTagsAliasesInternalState` 失败 |
| 4 | 去掉空壳语言断言 | `TestLoadRejectsBadLocales` 失败 |
| 5 | `Render` 丢弃回落值 | `TestRenderPrefersFallbackTextOverError` 失败 |
| 6 | `Messages` 不按默认语言补全 | `TestMessagesBackfillsFromDefault` 失败 |
| 7 | `ParseLang` 放宽为模糊匹配 | 4 个用例失败 |
| 8 | `MessageKeys` 不排序 | `TestTrapMessageOrderUnstable` 失败 |
| 9 | `Match` 去掉 `Confidence` 兜底 | `TestMatchFallsBackToDefaultWhenNoConfidence` 失败 |
| 10 | `loadFile` 不预编译模板 | `TestLoadRejectsBadLocales` 失败 |
| 11 | `ParseLang` 回落到默认语言 | 4 个用例失败 |

**其中 5、6、9 三处最初「存活」**（改坏了测试却全绿），暴露出两个真实的测试缺陷，均已修正：

- **根因**：本轮只有 `zh-CN` 一种语言，而这三条恰好都是**多语言才走得到**的分支（某语言缺某键的逐键回落、整包下发按默认语言补全、偏好完全不匹配时的兜底）。最初的用例为了绕开这一点，或直接调库、或在测试里重算一遍合并逻辑——**测的都不是生产代码**。
- **修法**：把包级零散变量收成单个 `active catalog`，让全部对外函数以 `catalog` 为接收者实现。测试遂能用 `load` 造出一份双语 catalog（`zh-CN` 默认 + `en` 故意缺键），调**完全相同**的代码路径。这一重构本身没有改变任何对外行为，但让三条分支从「无法测试」变为「已钉死」。

这三处存活是本轮最有价值的发现：它们说明「覆盖率 95%」与「断言有效」是两件事——那三条分支在重构前也被执行过（计入了覆盖率），只是没有任何断言能感知它们被改坏。

### 5. 端到端集成验证

除单元断言外，用 `rule/passwd` **真实产生**的错误对象走完整链路（`passwd.Check` → `errs.MsgKeyOf`/`ParamsOf` → `i18n.Render`），实测输出：

| `"aA1"` | `passwd.too_short` | `map[Actual:3 Min:10]` | 密码至少需要 10 位，当前 3 位 |

### 7. 对下游的硬性契约

本轮向后续几轮立下三条，均已写成可执行断言：

1. **`middleware`（L6）**：语言解析链为 `ctxs.界面语言` → `Match(Accept-Language)` → `Default()`；取词一律用 `Render`（**不是** `MustRender`），第一个返回值进响应体、第二个进日志——那是取词失败唯一的观测点，因为本包不打日志。
